Plugin: the agent link's `set-override` command changes Theme color overrides (#3394, owner decisions Q3394.1–.7 all A). It takes 1 to 32 changes, each `{ mode, role, palette, step }` or `{ mode, role, clear: true }`, applied all or nothing and judged on the final state. `confirm: false` previews and writes nothing. Its result carries a `previewHash`, each change's before and after (the stored override's real palette, the step the engine emitted, the hex and the ratio), every other pair whose ratio moved, and the contrast totals. `confirm: true` with that hash runs the Theme write itself, through the same `applyTheme` handler the panel's Apply reaches: the variables, the stored brand and a saved version. The panel is then sent the stored brand. The command refuses a change that puts a contracted pair below its minimum that was at or above it, in any mode, naming the pair and its ratio. It also refuses a link step the engine would clamp, a role the mode lacks, an unknown palette or step, a ground, a role that follows its source, a locked icon or focus ring, and a clear with nothing to clear. A write is refused when the file's brand changed after the preview, or when the panel holds Theme edits the file does not. Each write is one Activity row, "Color override", with one line per change, before → after. A preview is not recorded. The real-Figma canary previews one no-op change. The executor is unchanged, and no emitted token or projected component surface moves.
