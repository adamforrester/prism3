A brand icon map (#3076, owner decision 2026-11-18: A, both; the proposal's Q1–Q8 at their recommendations). A brand input's new optional `icons` block says which of the brand's own icons stands in for each Prism3 icon (`map`), and carries that art (`glyphs`: one filled path on the 24×24 artboard). The map applies everywhere a generated component uses a mapped icon, the Counter included: a vector glyph, a slot's default and a nested part's swap override. A mapped Prism3 icon is no longer built into the brand's icon set, and each brand glyph is built from the brand's art; a glyph named like a Prism3 icon redraws it. `brandTheme` refuses a key that isn't a Prism3 icon, a self-map, a chain, a target with no art, art for a mapped name and art that isn't one path, each naming the entry. The block is in `theme-schema.json` and survives the design.md round trip. The plugin and the component-defs export apply it before projection (`applyIconMap`, `icon-map.ts`). The export carries it as `brand.settings.icons` (format `prism3-component-defs/1.7`, after #2778 took 1.6), and `<brand>.ai.json` records `icons: { note, map, names }` (schema `prism3-ai-metadata/0.7`, after #2857 took 0.6, which moves every `.ai.json`'s `$schema`). A brand without the block is unchanged: every def comes back as the same object. Brand art that draws the same shape as another icon in the brand's set is reported in Update file's dry run, never refused (owner decision 2026-11-20 A; `iconArtDuplicates`).
