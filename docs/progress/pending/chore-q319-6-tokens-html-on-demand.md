## (2026-10-15) — `out/tokens.html` is built on demand, not committed (Q319.6)

Owner decision Q319.6 on #2583: the 1.8 MB preview page leaves the committed set. `npm run tokens-html` (root `package.json`, documented in `packages/engine/README.md` and `visualize.ts`'s header) writes it to `packages/engine/out/tokens.html`, which is gitignored. Nothing user-facing served it — the site build (`build-site.mjs`) publishes only the studio bundle, and no app or doc linked it — so no owner question was needed.

- **Why a skip list and not just a removed step.** Taking `visualize` out of `regen.ts`'s `STEPS` is enough for CI, but a developer who runs `npm run tokens-html` then has a gitignored file in `out/`, and two walkers read `out/` wholesale: regen's comparison universe (whose count `verify.ts` and `ci.yml` pin) and `lint-payload-manifest.ts` (which would call it UNCLASSIFIED once its `preview` rule is gone, or STALE in CI if the rule stayed). So `ON_DEMAND_OUT` in `regen.ts` names it, and both walks skip it.
- **The trap a skip list sets, and the check that closes it.** A name both walks skip is invisible to the comparison, so re-adding `visualize` to `STEPS` would have been silent. `check()` now stamps each on-demand file's mtime before regenerating and fails `on-demand packages/engine/out/tokens.html (regen wrote it …)` if any step touched it. The mtime, not the bytes: a step that rewrites identical bytes is still a step writing it. A copy that gets **committed** (`git add -f`, a lost `.gitignore` line, a conflict resolved toward an older branch) is skipped by both walks too, so `check()` also reads `git ls-files` for each on-demand name and fails `on-demand packages/engine/out/tokens.html (git tracks it …)` (review on #2685). It reads the index, not the disk, so a local ignored copy still passes; a git that cannot answer fails closed.
- **`test.ts` read the committed page** for the #2586 check (no type specimen for a non-typography leaf under `type.*`). It now renders its own copy with `visualize.ts --out <tmpdir>`; a failed render leaves zero specimens and the check fails by its own name.
- `EXPECTED_ARTIFACTS` in `verify.ts` and the count in `ci.yml` both drop by one: 194 → 193 at the base this was written on, 195 → 194 after merging the Link PR's new artifact, 198 → 197 after merging the flush icon button and the CHANGELOG move, 199 → 198 after merging the agent reference (#2644), 200 → 199 after merging the password field (#2648). `docs/inventory/surfaces.*` still list the page as written by `visualize.ts:599`; it is a snapshot of `b020716` by its own header, so it was left alone.
- **The prose gates kept the page (review on #2685).** `lint-us-english.ts` and `lint-voice.ts` walked `out/` wholesale, so they used to scan the committed page. With the file gone they stopped seeing it in CI but still saw a local copy — so the same commit was green in CI and red on a laptop that had built the page (the reviewer's demonstration: `colour` in the page heading passes with no copy, fails with one). Under docs/34 that is a scope that shrank with no diff in either gate. Fixed by keeping the coverage rather than dropping it: both gates skip `ON_DEMAND_OUT` in their `out/` walk and scan a copy `regen.ts`'s `renderOnDemand()` renders into a temp dir, so CI and a laptop scan the same fresh bytes. A failed render is `blind`, and the render is its own `REQUIRED_SURFACES` line, so dropping it fails the scope check by name. Each run of either gate pays one `visualize.ts` render (a few seconds).
- **Merging #2644.** The agent reference (`emit-agent-reference.ts --check`) requires every file that reads `process.argv` to be listed as a CLI or excluded with a reason. `visualize.ts` now reads `--out` and is run by hand, so it joins `CLI`, and `docs/public/reference/commands.json` lists it. That file ships under `/docs`, so its header line now says "visualizer" and its bare usage line says what it writes rather than "the same".
