## (2026-10-14) — Ecosystem diagram: three interface lanes and a compare table, one data file checked against the code (#2637, Q300.4, Q304 A)

Lane 3 of #2637. `docs/public/ecosystem/` holds `ecosystem.json` and `index.html`, one self-contained page with two views, and a new CI gate, `lint-ecosystem.ts`. The first draft was a node graph; the owner's review (Q304) found it mixed interfaces, inputs, connections and checks into one layer. This entry describes the restructure.

**The shape (Q304 A).** Left to right: inputs (levers by hand, design.md, tool arguments) sit at the start of each lane; three interface lanes (Web studio, Figma plugin, Agent) each list their features, shared ones first and in the same order, then "Only here"; the engine hub; outputs, with the Figma file and the code library as groups. Connections (MCP, the command line, the agent link, the desktop bridge, the Figma MCP scripts) are labels on the agent lane's arrows, not boxes. Checks (contrast contracts, code scoring, CI gates, the token contract) are badges on the boxes they act on, behind "Show checks". "Compare interfaces" is a feature-by-lane table generated from the same `features` list. Traces follow the lanes. Below 900 px the diagram is a stacked lane list.

**The page draws arrows by measuring the layout,** not from hand-placed coordinates: boxes sit in a CSS grid by `column`, and the arrows are recomputed from their rects on every resize. That removed the old `at` and `via` fields and the trap that went with them (an edge passing behind a node it does not touch). An edge out of the agent lane to the Figma file takes `route: "under"`, below the engine column.

**Feature facts, from the code and the inventory branch (`docs/surface-inventory`).** One correction to the Q304 wording: "only Figma … updates" is not what the code does. Update, capture baseline and adopt are agent-only: they are agent link commands with no `UiToMain` message, so no panel button reaches them. The diagram shows them in the agent lane only, and the gate holds that. Everything else Q304 named matches: only the plugin (and the agent, through it) applies, builds, prunes, sets up the file and draws style guides; only the agent scores code. Web and Figma share every studio feature except two: loading a brand from a Figma file (planned, #677) and the agent link switch. "Keep the brand" is shared with different mechanisms (browser storage on the web, the file in Figma).

**The gate's new LANES arm, and why it is independent.** It reads three facts from code, never from the data: `toolDefs` (MCP tools), `AGENT_COMMANDS`, and the `UiToMain` union parsed from `apps/plugin/src/messages.ts`. MCP tools may sit only in an agent lane, and every tool is claimed. Plugin messages may sit only in a figma lane, and a feature that sends one cannot claim the web. An agent command that is also a `UiToMain` type needs the figma lane; one that is not must not have it. The gate also checks that the plugin still imports the studio's whole entry, so the premise of the host rule below cannot rot silently. The first run caught two real drifts: the two segmented-control defs that landed on main the same day, and `ui-ready` on a feature that both hosts have (`ui-ready` is boot plumbing; it is now in the gate's authored `PLUMBING` list).

**The REACH arm (added after review).** The review found that a feature could claim a UI lane the code cannot reach: `score-code` given web and figma lanes, both citing `preview.ts`, passed with exit 0, because the host rules fired only when one UI lane was present without the other, and any file with any `PRISM3_HOST` branch satisfied them. The fix reads the import graph. The gate walks each lane's bundle from its build entry points (`apps/studio/src/entry.ts`; `apps/plugin/src/ui/entry.ts` plus `main.ts`), following value imports and `@prism3/engine/*` through the engine's `exports` map. An authored `TOOL_MODULE` names the engine export each MCP tool runs, held against `mcp.ts`. A feature whose agent tools run an export can claim web or figma only if that bundle imports the export, and must claim it if the bundle does. Host-only features now name an `anchor` string that must sit within 8 lines after the matching branch. Two things were tried and dropped. Module-level reach was too coarse: the plugin reaches `eval.ts` for `normalizeRef` (through `component-schema.ts`) without scoring anything, so the check is by imported name. And a naive `/* … */` strip swallowed real imports, because a string held `/*`, so only comments that open a line are stripped. With that fixed, the walk's file sets equal esbuild's metafile inputs for both lanes (119 web, 212 figma), checked once by hand while writing it. The check is not wired in, since esbuild is not an engine dependency.

**Trap.** The `PRISM3_HOST` anchor rule only decides features that cite a source. A shared panel that quietly behaves differently per host passes. Read the code before claiming a UI feature is the same on both hosts.
