## (2026-11-13) — Changes that reach files using the library are named by their effect; "breaks" only where they break (#3711, Q-UF1 A)

**The defect.** The owner's Update file run on 2026-11-12 ended "2 changes break library consumers". Both were Wallet button members retired: kept and marked deprecated, so their instances in other files still resolve. The update's four lines for these changes (`breakingSummary`, `breakingSection`, `breakingClause` and `breakingLine` in `apps/plugin/src/update-plan.ts`, read by the dry run and by the apply) called every change consumer files get "breaking". That included a member retired and a set renamed out of the library.

**The fix.** A new predicate, `breaksConsumers`, reserves "breaks" for the changes that do break those files: a property removed or retyped, or a layer replaced or removed. Every other change is named by its real effect. Draft wording, for example: "2 changes affect files that use this library: 2 Wallet button members retired. Their instances keep working and show as deprecated." The headline clause reads " · 2 changes affect files that use this library", and adds ", 1 breaks them" or " and break them" only when some do. The section heads "Files that use this library: n changes in k published sets[, b of them breaking], passed on at the next library publish." `checkedSetOf` passes the set's name, so the checklist line names whose members retire. The publish description's "n breaking changes for library consumers" (#2914) counts only the changes that break, through the same predicate, so a run of deprecations no longer reads as breaking there either.

**What this does not do.** The callout before the run is Q-UF2, its own PR. The `Breaking` type and its field name `breaking` stay as they are: they are internal names, and renaming them would touch every reader for no change a person sees.

**Tests and mutations, each failing by name.** `uf1/retired only` (the owner's case, two Wallet button members, three surfaces as literals), `uf1/retired one`, `uf1/clause breaks`, `uf1/publish`, and the updated `published/*` arms (`apps/plugin/test-update-apply.ts`, which split the list by kind themselves, never through `breaksConsumers`). Mutation: `breaksConsumers` counting a retired member → `uf1/retired only`, `uf1/publish`, `published/section`, `published/headline`.

**Review follow-up.** The published fixture holds only retired members, replacements and properties, so `breaksConsumers` was not pinned for a removed layer or a private rename. New literal arms send each through the clause, the section head and the apply's publish count: `uf1/layer counted`, `uf1/private not counted`, `uf1/publish layer`, `uf1/publish private`. Mutations: `breaksConsumers` without `layer` → `uf1/layer counted`, `uf1/publish layer`; with `private` → `uf1/private not counted`, `uf1/publish private`.
