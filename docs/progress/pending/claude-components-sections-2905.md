## (2026-10-22) — Components page: Buttons, Fields and Tag sections, with their options (#2905, phase 1)

The owner asked for Field style on the Components page, then for the page to be grouped (Q538): one section per group of components, each with its settings once. Q548 took every recommendation on wireframe v2. Phase 1 ships Buttons and Fields together (Q12 A), in the studio and the plugin, which share the page.

- **The sections.** `groupsOf` (`state/component-groups.ts`) returns Buttons, Fields, Other components and Subcomponents. A section with settings is a `SETTING_SECTIONS` entry, matched by page (Buttons) or by def ids (Fields). Its rows are `flat`: the section title stands in for the family row (Q8 A), so each set is a row at the section's edge. Every other component row is drawn as before, in Other components (Q6 A). Fields' ids are typed in the studio, because no definition may reach the web bundle (`check:ignore`). `test-component-groups.ts` holds them to the engine's `FIELD_FRAME_PARTS`, the defs `applyFieldStyle` draws.
- **Focus in a flat section.** Buttons' sets have no family row to focus, so a set there focuses as itself (`setFocusKey`, `set=<id>`). `rowOfFocus` resolves that key to the family's row, so the preview still shows Buttons. Opening a section's settings focuses its first set, unless one of its sets already has focus (wireframe v2).
- **Settings per section.** `settingsOf` is keyed by section, not by row: one block per section, mounted once, kept across redraws, after the sets (Q9 A), behind #2868's disclosure line, closed on arrival (Q7 A). `optsOpen` now holds section kinds. Line, block and rows share one edge (Q1 A), so #2868's 32px indent on the line is gone.
- **Field options** (`domains/field-options.ts`, Q3 B): the way to Shape › Control shape, reading "No corners on an underline field." under Underline, then Field style's chips. There is no way to Density. **Field style lives only here (owner Q578 B, on the PR's Q1):** Shape no longer draws its chips, and there is no line on Shape pointing to it. Its page-data home moved from Shape › Radius to a Components › Field section in `shell/pages.ts`, so `test-pages.ts`'s one-home rule holds by a real home. It writes through `state/shape-input.ts`. Control shape and Density stay on Shape.
- **Copy (Q10 A).** The section titles, the block titles and both descriptions are wireframe v2's. Button options' description now says icon buttons are not affected, so its closing scope line is dropped. Its levers are unchanged. The label readout is #2919's, not repeated here.
- **Built on #2868, unmerged.** Its head is merged into this branch with a normal merge commit.
- **Gate.** `test:chrome`'s #2905 arm runs on both hosts at 1280 and 380. It checks the section order, the sets in each section with no family row, one edge for the head, rows, line and block (within 0.5px), Field options' copy and its Underline write, and the focus rule.
