## (2026-10-25) — CI runs the Chromium install script's test, and its stall cases hold where PID 1 does not reap (#2981)

`install-chromium.sh` runs in all four browser jobs, and its test, `test-install-chromium.sh`, ran nowhere: a change to the script was gated by whoever remembered to run the test. The `engine` job now runs it as "The Chromium install script retries cleanly after a stall (#2981)". It needs no browser and no network, only a stand-in install and lock in `$TMPDIR`.

**The stall cases.** Under a subreaper that never reaps (`prctl(PR_SET_CHILD_SUBREAPER)` and no `wait`), five cases failed on `main`: the four the issue names plus `stall/ok`. The stopped lock holder stayed a zombie, and the stand-in's `kill -0` still answered for it, so attempt 2 failed on the lock. A zombie holds no lock, because the kernel releases a process's locks when it exits, so apt would not wait on it either. The stand-in now reads a zombie (`ps` state `Z`) as not holding the lock. All cases pass under the non-reaping subreaper and without it. The container this was written in reaps orphans, so the plain run passed before the fix too. The subreaper is what reproduces the issue's containers.

**`lint-doc-gates`.** Its prose arm saw only `npm run` and `npx tsx` steps, so a step that runs a script was a gate no checklist had to list. The freshness battery was already listed, but nothing required it. A step whose line starts `sh` or `bash` and names a `.sh` script now counts, keyed by the script's path. The named install and aggregator steps are skipped, as they are in the runner arm. Arm 5 now accepts `bash` as an invocation. Dropping the new line from each of the three gate regions fails the gate, naming that region.

**Mutation.** With the clear before a retry dropped from `install-chromium.sh`, the test fails `stall/ok`, `stall/no lock error`, `stall/two attempts`, `stall/cleared` and `stall/repaired`. The PR's CI shows the same mutant failing the new step by name, and the revert after it passing.
