### What changed

- **#3462.** Components' status order is now the key order of a `Record<SetStatus, true>` (`apps/studio/src/domains/components.ts`).
  A status added to `SetStatus` and not placed in the order fails the studio typecheck, naming the missing status
  (`Property 'stale' is missing … Record<SetStatus, true>`), instead of silently losing its tag as `kept` did in #3446.
  The order and the rendered tags are unchanged. A compile-time check over a unit arm: the type is the list, so the two
  cannot drift and there is no exemption list to keep.
- **#3463.** `test-update-kept-run.ts` gains `held joined`: a second Keep run that holds B over an entry holding A
  records A and B, members the larger count, from literals. Dropping the join (`now ?? before`) fails it by name, and
  only it.
- **#3464.** In `tools/agent-adherence/`:
  - c: both self-tests gain `independence/static-aliases` (`-oracle` for `oracle.ts`). Every mention of a read or exec
    name that is not a call must be a plain `import { … }` specifier, so `readFileSync as rd`, a destructured rename or
    a bare reference fails by name. The call-name scan could not see these.
  - a: `run`'s reset and baseline move into an exported `baseline` in `run-figma.ts`, with no change in behavior.
    `before/run-control` and `before/run-strict` drive it through the stand-in client, so a `keepFailed: true` at that
    call site fails by name. Before, only `send`'s default was pinned.
  - b: `probe/no-result-glob` pins "a call with no result still counts" for a Glob, as it was already pinned for Read.
