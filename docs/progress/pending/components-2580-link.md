**Status:** a new def, `link`, an engine extension the def needs, the gate lists it joins, and the Button `href` documentation. ENGINE minor (change note). CONTRACT unchanged: no new token. No executor change, so `EXECUTOR_REVISION` stays where main has it.

**What it builds (Q289):** 96 members — `style` standalone | inline × `weight` emphasis | default × `size` small | medium | large × `surface` default | inverse × rest, hover, pressed, focus-visible. A row that hugs its label, one text line tall, no padding, optional leading and trailing icons (node-visibility booleans with the swap canon), and the shared focus ring following `surface`. Label "Link text". Ink is `color.text.link.*` / `color.icon.link.*`, `focus-visible` on the `focused` rung; the inverse twins come from the projector's one inverse rewrite, as Button's do. Visited, current, the router `asChild`, the external link and the 24px hit-area expansion are code only (`codeOnly`). Its own `Link` page under Components, canvas furniture, and Q238 A reactions derived from the state axis (48 sources, 72 reactions). Button's `href` prop now documents the anchor rendering (Q289.6 A, no LinkButton), and `link` leaves the five `planned` lists that named it.

**The diagnosis that made it small:** the proposal flagged that standalone swaps its text style by state (underline on hover), and asked whether the engine can key a type binding by state. It could not: the projector already fills a binding key from a coordinate that carries `state` (#1248), but the validator refused any placeholder that is not a variant axis. So the extension is two lines of rule plus one of resolution: `component-schema.ts` admits `{state}` in a part's `type` key only, expanded over the def's declared states, and `anatomy-figma.ts` resolves a structure-only plan (no state) at the first declared state. Type only, on purpose: a state-keyed height or padding would move one instance's box between before and after, which the footprint rule exists to refuse. The two styles a state picks between differ only in `textDecoration`, so the box does not move.

**A trap for whoever re-verifies:** a `{state}` type key resolves at the first declared state when a plan has no state. Every def's first state is `rest` today; a def that declared another state first would get that look in its structure-only plans.

**Review fix: the `{state}` rule had no test.** The schema allows `{state}` only in a type key (`keyAxes` in `component-schema.ts`), and its comment leans on the footprint rule to refuse a state-keyed box. That rule runs only against a live Figma file, and the shim has no equivalent, so widening `keyAxes` to every binding key failed nothing. `#2580 link/state-type-only` validates a Link clone whose row gap is `size.{size}.gap.{state}`, with every slot that expansion would ask for supplied, and asserts the refusal names the placeholder. With every slot present, a validator that lets `{state}` through finds nothing missing, so the arm can't pass for the wrong reason. Mutation: `keyAxes` widened to every key fails that arm by name (`clone: no errors`), and nothing else in the suite fails. The icon props now say "Not for inline links", matching the docs, because the toggles exist on both styles.

**Owner decisions Q297, applied (review findings 2–4).** Items 2, 4 and 5 above are settled, and superseded where they differ.
1. **Body tier for both styles**, 14 / 16 / 18px, so a Link matches the body text and the text-range link in the same paragraph. No 12px link. `default` binds `type.body.<rung>.default[-link]`. `emphasis` has no `emphasis` role to bind in a default brand's body tier: there it is `strong`. In nb-redesign's brief (body weights `[default, emphasis]`) `strong` is never emitted, so a fixed `strong` binding fails test.ts #1601 at nb-redesign. That is the miss the 2026-10-11 accordion decision stepped around by staying on the label tier. **The diagnosis that made it small:** field-label already solved this shape with `weightIntent` (#1602, `bold` → the heaviest body weight the brand ships). It needed two things to fit Link. First, an optional `intents` map, because Link keeps its value names (Q297.3) where the validator wanted `regular | bold`. Second, the repoint keeps a `-link` suffix, which field-label never had. So `emphasis` resolves to `strong[-link]` in the four default brands and to `emphasis[-link]` in nb-redesign. **The tradeoff, deliberate:** in prism3 the emphasis link is now 600 (`strong`) where the label tier gave 500. That is the body text's own heavier weight, which is what "matching body text" asks for. Like field-label, a brand that ships one body weight drops the `weight` axis (`link@body-single`, 48 members).
2. **Icons: trailing only, standalone only.** The leading slot, its prop, boolean and swap are gone. The trailing slot carries `presentWhen: { style: ['standalone'] }`, so it is absent from every inline member, not just hidden by a toggle: the axis model expresses "standalone only" directly, as Accordion gates its indicators. Rungs are `icon.size.xs` / `xs` / `sm` (16 / 16 / 20px). They fit inside the body line (21 / 24 / 27px at 1.5) in all five brands. The `size` prop now states the height with an icon. The medium default on `xs` is two rungs below `md`, so `lint-rung-names` gains `ICON_OFFSET_TWO_DEFS` (`link`), sanctioned by Q297.2 and checked both ways, as `ICON_OFFSET_DEFS` is. Paint census 288 → 144 assignments (96 labels plus 48 standalone trailing icons).
3. **Weight wording** per Q297.3. The "matches body text" claims are gone.
