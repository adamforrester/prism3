## (2026-10-15) — Skills audit fixes: theme, consume, rebind, and the wrong claims in build-component (#2677, Q320.1)

**What changed.** The claims the Q320.1 audit found false or superseded on `main`, in four shipped skills, plus four `lint-skills.ts` checks for the classes a mechanical check can see. The full audit, including what is missing and the `prism3-build-component` rewrite plan, is the comment on #2677.

- **`prism3-theme`:** `radiusHairline` is retired (#2053), not an opt-in; a pinned neutral still needs `hue` and `chroma` beside `anchor` (the schema requires both); `controlShape` takes four values, not two, and reaches fields and checkboxes; the default-action note is quoted as the engine prints it; the `x-prism3:` block reads ten keys and drops any other without a warning; `theme_brand` returns contracts and notes by default, not the tree, and `theme_from_brief` and `export_theme` are named; the dead `inverse` entry left `omits:`.
- **`prism3-consume`:** primitives are `core.palette.*`, `core.dimension.*`, `core.font.*`; disabled inks carry a 3:1 contract (4.5:1 in the high-contrast modes, `modes.ts`'s `disabledTarget`), so the skill no longer tells an agent to drop them from the self-check; `text.secondary` and `border.tertiary` name the surfaces they are actually measured on; code builds from the base + overlay projection, not the single tree's `mode_overrides`; `export_theme` and `score_consumption` replace "call `theme_brand` for the tree".
- **`prism3-rebind`:** tabs now exist (and accordion, list, divider, segmented control), so they leave the "no component" list; `radiusHairline` gives way to `controlShape`; the layout mode is the one for the frame's width, named by the brand's breakpoints (`xs` in one brand); a legacy grid style maps to Prism3's grid style first; legacy effects map to `shadow/*`, `shadow-dark/*` and the gradient styles before being left on purpose.
- **`prism3-build-component`, WRONG items only** (the rewrite waits for #2660, #2645 and #2648): `KB_BRIEF_CATEGORY` is derived from `schema/kb-briefs.json` (#2488), not an authored table; image-placeholder's `ratio` has seven values; `lint-hit-target`'s exceptions are `SMALL_SIZE` and `FLUSH_MEMBERS`, not "the small Button"; axis order is #2501's fixed order with the three fields as the named exception, and Figma's default is the top-left member, not the first child; three baselines move with a projection, not two (`schema/component-axes.json`).

**The four new checks in `lint-skills.ts`**, each driven both ways by the self-check:
- *primitive without core* — a dotted name that resolves only as the tail of a `core.*` path fails. The suffix rule that lets a skill say `border.primary` for `color.border.primary` also passed `palette.primary.600` for `core.palette.primary.600`, which names nothing at the tree root. `color.` is a namespace a reader drops (the `.ai.json` drops it too); `core.` is what marks a private primitive. The counter-example exemption still applies, so "not `palette.*`" style teaching is unaffected.
- *retired lever* — a backticked lever that `levers.ts` marks `deprecated` must be called retired or deprecated on the same line. Read from the manifest, so the next retirement is covered without an edit here.
- *dead omission* — every `omits:` entry is a BrandInput property.
- *incomplete enum* — in a `documents: brandInput` skill, a table row whose first cell is an enum property lists every value the schema accepts. A wiring floor fails by name if no row is read at all. A dotted first cell (`typography.captionFloor`) resolves through nested `properties`: the first pattern took plain words only, so the two nested enum rows were never read (review on #2681). The values are read from the row's second cell only: the check first read the whole row, so `captionFloor` stayed complete with `10` gone from its values cell, because its description quotes "`10` adds caption.sm" (the reviewer's mutation, which passed for that reason too). Narrowed, it found `disabledStrategy`'s values cell listing two of four accepted values; the two legacy aliases were named only in the description, and now sit in the values cell as aliases.

**Mutations, each failing by name:** the three skills restored from `origin/main` (consume → four `primitive without core`; theme → `retired lever`, `incomplete enum` ×2, `dead omission`; rebind → `retired lever`); each new `findings.push` neutered → the self-check names the check; the theme table's rows reshaped → "the enum-row check read no table row in prism3-theme".

**Review round on #2681.** The disabled-ink line now gives the high-contrast 4.5:1. `prism3-build-component`'s hit-target exceptions name #2607's `CODE_SIDE_TARGETS` (44×44 at every size, stated in `codeOnly` and the shipped docs), `EXCLUDED` and `INNER_TARGETS`; the state ladder is an example pointing at `STATE_LADDER`; `component-axes.json` moves only on an axis, value or member-count change. `prism3-consume` says `export_theme` writes `tokens.json`, `ai-metadata.json` and `figma/` but no base + overlay set, and points a multi-mode build at the CLI's `--out` or the studio export; modes may also be more than four. `prism3-rebind` names Link and Flush icon button among the atoms.

**What stays out of reach, stated so nobody trusts the gate past it.** Prose claims about where a role sits (`text.secondary`'s surfaces), what a tool returns by default, quoted note text, the `x-prism3:` key set, and "Prism3 has no X component" are not mechanical names; review catches those. The audit lists cheap next extensions (a `documents: mcpTools` coverage mode, an opt-in `absent_components:` list).

**Filed, not fixed (one concern per PR):** the standard dialect drops unknown `x-prism3:` keys silently: #2678.
