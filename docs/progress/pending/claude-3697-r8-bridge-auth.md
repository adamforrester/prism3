## (2026-11-13) — The desktop bridge proves itself to the plugin (#3697 R8)

The review's M4: the plugin never checked the bridge. Pairing (#3204) proved the plugin to the server, but the relay heard any `welcome`, and kept any `paired` token, from whatever answered on port 17331. A process holding the port while the real bridge was down could send write commands into the open file once the person switched the link on. The owner chose A: the server proves its token over a nonce the plugin sends, and an unasked `paired` is ignored.

**The bridge.** Each connection now draws its own 32-byte `clientNonce` (`randomNonce`, `crypto.getRandomValues` in the iframe and in Node), sent with the pair and the hello. The server answers `welcome` with `HMAC(token, "prism3-bridge-welcome-v1:" + clientNonce)` and `paired` with `HMAC(code, "prism3-bridge-paired-v1:" + clientNonce + ":" + token)`. The relay drops a socket whose welcome does not verify, before any command is heard, and retries on the usual schedule, so the real bridge is found once it is back. A `paired` is heard only while a code went out on that socket; one whose proof fails is an impostor and is dropped, with the code kept for the real server. The `paired` proof goes one step past the decision's wording: without it, an impostor that answered while a code was pending could still hand the plugin a token it chose, and then prove that token in its own welcome. The person sees nothing new, since the prompt and its words are unchanged.

**No session code on the file mailbox (owner, Q-R8.1 A).** An earlier round of this PR also made the mailbox's theme write and confirms carry a per-session code the person relayed to their agent. The owner removed it: anything that can write the mailbox already has edit access to the file, and the one exposure the code covered, the dev-only `run-code`, is kept out of the release build by `lint-release-bundle`. The code, its status line, the `no-session` refusal, the CLI's `--session`, and their guide lines, docs and tests are gone; the mailbox behaves as on `main`.

**The residual risk (owner, D3728.5 a).** The `paired` proof is only as strong as the 8-character pairing code (about 2³⁹). An impostor holding the port while a code is pending can search that space offline from the plugin's `pair`, and the relay keeps the code across dropped sockets. The owner accepted it, and the agent-link guide says so in one line. Forgetting the waiting code after a failed connection is #3764.

**A plugin and a bridge from before this change don't connect to each other.** An old plugin sends no `clientNonce`, so the new server refuses its hello. A new plugin gets no proof from an old server, so it refuses the welcome. Update both together. `AGENT_PROTOCOL_VERSION` stays 1: the command and result envelopes are unchanged.
