## (2026-11-12) — Line height and letter spacing as a Figma `text-spacing` collection (#2423)

Owner decision Q175 A (2026-11-11), with the collection name chosen on 2026-11-12 (option A). The DTCG half (#2434) made letter spacing a number multiplier and carried the one contract bump; this is the Figma half. No DTCG name moves, so `CONTRACT_VERSION` is unchanged and the change note is `engine: minor`.

**What moved.** Every brand's Figma emission gains `out/figma/<brand>/text-spacing.json`: one `text-spacing` collection, one `Default` mode, 32 FLOAT variables per brand. Each is named by its DTCG path, the motion precedent (#2394): `<root>/core/font/line-height/<step>`, `…/line-height-role/<role>`, `…/letter-spacing/<step>`, `…/letter-spacing-role/<role>`. Values are the DTCG's multipliers (`1.05`, `-0.04`). Steps are hidden from publishing; roles are published and alias their steps. The collection is built in `emit-figma-dims.ts` beside `blur`, so Apply Theme writes it through `buildFloatWritePlan` and the CLI paste path through `dims-create`, with no new executor. `EXPECTED_ARTIFACTS` 229 → 233 (`verify.ts`, `ci.yml`).

**Why no scopes.** Figma's `VariableScope` does have `LINE_HEIGHT` and `LETTER_SPACING`, but Figma reads a FLOAT bound to either text field as pixels (#1356's measurement). A multiplier offered in those pickers would bind as `1.05px`. So every variable carries `scopes: []`, the issue's stated default, and text styles keep their baked PERCENT. `lint-lineheight-bake.ts` assertion E used to say no line-height variable existed at all; the owner's decision minted them, so E now holds every line-height and letter-spacing variable to an empty scope list, with a per-brand floor so it cannot pass over an emission that lost them.

**The export.** TokenPress typed an unscoped `font/line-height/105` as a bare-number breakpoint and `font/letter-spacing/neg-40` as a negative dimension, both in px. It now types an unscoped `font/line-height/…` or `font/letter-spacing/…` variable, and its `-role` alias, as `number` by its path (#2616's shape). Only a variable with no scopes at all: on Figma's default ALL_SCOPES, or any other scope, the same path often holds pixels in a third-party file, so it keeps its old type (review finding on #3720). Unscoped is not enough on its own either, since a file may clear every scope to hide its px primitives, so the value, read through any alias, must also be in a multiplier's range: a line height above 0 and at most 4, a letter spacing at most 0.25 either way (second review finding on #3720). `test:readback-parity` gains a text-spacing arm: Apply Theme's file holds the plan's count, all FLOAT and unscoped, and every leaf of both exports matches `out/<brand>.tokens.json` by path, type and value. The exporter comparison's two `NOT_IN_EMISSION` prefixes for these groups are gone: the paths now pair, and the gate stays green without them.

**A trap for the next axis.** `test-rename-parity.ts` read only the first `migrate` payload's report. The migrate pass is packed into chunks by bytes, and the new axis moved the chunk boundary, so one rename was reported by the second chunk. The test now merges every migrate chunk's report.

**Not built here.** The style guide reading these variables from the file (the reason option A was chosen) is a later change to the plugin's style guide.
