## (2026-10-21) — Skills: a consistency audit for rebuilt spec pages (#2886, Q506 A)

**What changed.** `skills/prism3-rebind/consistency-audit.js` is a read-only Figma plugin-API script an agent sends through the dev agent link's `run-code` over a set of rebuilt pages. It returns the frames it read (each classified desktop or mobile, and why), a findings list, a markdown findings table and a row for the Runs table on #2886. Four checks: (1) plain text outside any instance that repeats a control instance's label, with a heading/title allowlist; (2) the desktop → mobile text-style pair per element role is the same on every page; (3) at one breakpoint, each role has one text style, one component and variant, and one spacing to its parent; (4) every variable and style is the library's, inside instances too, and no visible raw solid fill or stroke outside an instance (on a text with mixed fills, per run; gradients and images are not read). The library match is configuration (`local`, collection/style keys, or name patterns), never a brand name. The rebind skill gains section 10 (when to run it, the definitions it relies on, how to read and log findings), and the consume skill points to it.

**The definitions, made concrete because the issue left them open.** An element role is the layer name, lowercased, separators as spaces, a trailing `copy`/`copy N` removed; a number stays (`Heading 1` and `Heading 2` are two roles). A layer Figma named (`Frame 12`, `Rectangle 4`, a text layer still named after its own characters) has no role, so checks 2 and 3 skip it and `coverage` counts the text ones. The heading allowlist matches the role or the text style name, so an unnamed heading layer is still skipped by its style. A frame is desktop/mobile by a breakpoint word in its name (`desktop`/`lg`/`xl`, `mobile`/`sm`/`xs`), else by width (≤ 767 by default). Frames whose names match once those words are removed are one page. "Expected" is what most frames use, so a two-page tie reports whichever came first; three or more pages make it meaningful.

**The test.** `apps/plugin/test-consistency-audit.ts`, in the plugin's `test` script, sends the file through the real `runCode` (`src/dev-commands.ts`) over a hand-built mock tree: three pages at two breakpoints, one pair inside a section, one mobile frame classified by width. The consistent set is quiet on every check; a drifted copy with one seeded drift per check reports exactly the findings written in the test (14). The mock `getStyledTextSegments` refuses a field outside the plugin typings, and the mock page records `loadAsync`. Nodes are Proxies that record writes, and the suite fails on any. Mutations, each failing by name: each check's function returns early (`drift/1 control label`, `drift/2 pairing`, `drift/3 component|spacing|text style`, `drift/4 raw fill|legacy variable|legacy style inside an instance`); the heading allowlist by style dropped (`consistent/1`); any trailing number stripped (`consistent/3`); Figma's default names kept as roles (`default-named layers … have no role`, `consistent/3`); the mixed-run paints dropped (`drift/4 raw run`); either page load dropped (`the page is loaded before it is read`, `frameIds: each frame's page is loaded`); a frame renamed by the audit (`the audit wrote nothing to the file`).

**Review.** An independent read-only review found the default-name, numbered-role, mixed-fill, unnamed-heading and page-load gaps above; each is fixed and has an arm. Kept as is: a `SPACE_BETWEEN` parent reports `gap auto (space between)` rather than a number.

**Ceiling.** Not run against a live file in this PR: the fixture models the plugin API calls the audit makes (`getNodeByIdAsync`, `getStyleByIdAsync`, `getVariableByIdAsync`, `getVariableCollectionByIdAsync`, `getMainComponentAsync`, `getStyledTextSegments`), and the first real run is the Runs table's row 1. Check 3's spacing in a frame without auto layout is the distance from the previous sibling, which moves with content height; the Runs table will say whether it is noise.
