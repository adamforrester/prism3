## (2026-10-01) — UI redesign S11: the Activity drawer gives every Figma operation its own row, and shows an agent's run (#1788)

**STATUS: PR open from `ui/s11-figma-activity`, held for the owner's review (DO NOT MERGE).** UI and plugin bridge only. No engine change and no emitted artifact moves, so ENGINE stays at {{ENGINE_VERSION}} and `CONTRACT_VERSION` is unchanged. Writes are behavior-neutral: every write message the panel posts is byte-identical to main's, and `test:chrome` asserts each one whole against the committed `example-brands.json`.

**What moved.** The S1.4 drawer held the old bar's pills plus one shared detail row. S11 replaces both with concept v6's model (plan §3.9). Each operation has its own row: Apply Theme, Build set, Set up file, Style guide, Prune stale and Read-back. A row appears once that operation has run. It carries a verdict pill, its time, a phase line and progress bar while it runs, its summary, and "Earlier results (N)", the last five. The drawer's bar row names the newest operation and counts how many are running or need attention. It opens by itself when a write starts. A success collapses it 4 s later (`COLLAPSE_MS`), held while the pointer or focus is inside. A failure or warning keeps it open. A page row's verdict no longer discloses anything in place: clicking it opens the drawer on that operation's row, through the store's `openDetail`. `renderSeedPill`, `syncApplyDetail`, the `apply-detail` row and the drawer's `bar` slot are gone. "Apply to Figma" is now "Apply Theme" everywhere, and pending copy reads "…" with no lead "⋯". That empties the chrome's `FACE_GAPS`: Inter has no U+22EF, and no glyph in the chrome comes from a device face any more.

**The agent's run.** The plugin's dispatcher now brackets every agent command that has an operation with `agent-started {id, cmd}` and `agent-finished {id}`, around the verdict. `test-agent-link.ts`'s `brackets/<cmd>` arms check the order. `host-session.ts` keeps it in a new `agentRun` slot: a verdict for the same operation settles it (`settleAgent`, first thing in `reduce`), `agent-progress` feeds its build reading, and `agent-finished` clears it. The panel's own action slots are never set to pending by an agent's run, so Apply Theme keeps its label and stays enabled while an agent writes. An agent's write is not the designer's click. The drawer tags the row "Agent". A run that finishes with no verdict (its handler threw) restores the row's previous result from history rather than leaving it spinning.

**Two technical calls, both forced by existing gates.** The progress fill is a native `<progress value max>`, not v6's `<i style="width:…">`. The chrome sets no inline value, and `chrome.css` may read only `var(--p3-*)` variables defined in the token map. The element also brings the progressbar role. And `OP_TITLE`'s `'apply'` key is quoted: `test-shell-imports.ts` reads a bare `apply` identifier in shell code as a reference to the legacy repaint tier.

**Suites.** `test-build-verdict.mjs` reads each build from its `components` row rather than `[data-p3="bar"]`. Its #1890 arm retires its bar-before-detail write-order checks, because there is one surface now, painted in one pass. The arm's header explains why; the arm keeps every check a designer would see. New arms cover an agent's run end to end, and the page pill's reveal. One trap: the clean-collapse arm moves the pointer off the drawer first. The click that started the build leaves the pointer where the drawer then opens, and v6 holds the collapse while hovered. `test-chrome.mjs` reads rows by `data-op`, classifies the two new control kinds (`p3-drawer-bar`, `p3-op-head`), and counts top-bar pills by class, because this suite never renders a `status-pill`. Nine mutations, each failing by name, are listed in the headers of `test-build-verdict.mjs`, `test-chrome.mjs`, `test-host-session.ts` and `test-agent-link.ts`.

**Held for the owner** (concept v6 is silent or conflicts; each took the option closest to v6):
- A clean result leaves its row expanded and collapses the whole drawer after 4 s. #483's rule was "a clean verdict stays collapsed".
- The count reads "N need(s) attention". `ok: false` cannot tell a failure from a warning, so v6's "failed" isn't available.
- Read-back and Prune rows use the host's summary as their verdict words, which are the old seed-pill text and long.
- A panel verdict that lands while an agent runs the same operation is marked as the agent's.
- The page-row pill lost its caret, since it no longer discloses in place.
- At 380 the strip does not auto-collapse.
- No queued state, no Export row, and no agent note: v6 draws them, and none has a source today.
