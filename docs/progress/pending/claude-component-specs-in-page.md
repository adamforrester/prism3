## (2026-10-24) — Spec panels below the usage panel, on request (#2830 phase 2, draft on recommendations)

**What.** `apps/plugin/src/spec-panel.ts` draws one spec panel per family, `SPEC_GAP` (40) below the family's live usage panel and at its 560 width, from the phase 1 spec model (`componentSpec`) with each def materialized for the file's brand. Per set of the family: Anatomy (the usage panel's numbers, `anatomyMarks`), Spacing and size (a live specimen per size, without and with a leading visual, redlined in a fixed magenta and labeled `variable · px`, the px read off the specimen), Color (a table per value of the color key's non-state axes, rest in full, other states only what changes, each swatch bound to its variable), Nesting and properties. The agent command `draw-specs` runs it; Build and Update never do (Q2830.3 A). Wireframe: https://claude.ai/artifact/5HwWQduNSyWnp9Vv27g6mL, questions on #2830.

**Hand edits and Update (#2956's posture).** The panel takes the usage panel's rule whole: a print (`panelPrint`, now exported) and a plan hash on the panel; an unedited earlier panel is replaced, an edited one renamed "(edited)", retagged `kept`, moved below its column and named in the result. Its tag is its own key (`prism3`/`specPanel`, `spec-tag.ts`), so the usage panel's draw never treats it as an earlier usage panel. Update reads a live spec panel as its set's furniture (`pageViews`) and moves it with the set (`respaceLive`); the usage panel's blocker test skips it, and a taller redrawn usage panel pushes it down.

**Deliberately not built.** The separate-file run (Q2830.6 A, follow-up: a specs file has no `_Doc-block` source), the panel button (waits on IA v2's Documentation area, #2909), and a due signal in Update's dry run.
