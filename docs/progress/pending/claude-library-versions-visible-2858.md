## (2026-10-21) — Versions visible in the library file: the About frame, the publish description, "Last changed in" data (#2858)

Built from the approved wireframe and the owner's Q479 decisions: the About frame beside the thumbnail (1 A), the latest release only (2 A), "Last changed in" from the release notes only (3 A), item sentences shown as generated (4 B, follow-up filed), no executor revision (5 A), and the publish description offered with a Copy button.

- **The plugin bundles what it needs.** `release-summary.ts` already bundled `docs/public/releases/index.json`, but only its breaking and new Figma highlights, and "Last changed in" for Button is a fix (`set-rebuilt`). Each index entry now carries `items`: every Figma and token item, every class, in the release's order. Code items stay in `<version>.json`. `release-notes.ts --index` rewrote the four existing entries from their release files, and `lint-release-notes.ts` checks the new field against each release (`INDEX … items for <v>`).
- **The words** (`apps/plugin/src/library-about.ts`, pure): `aboutContent`, `lastChangedIn`, `publishDescription`. New sets are one line with building blocks left out, new tokens one line under their shared prefix, and sets that build differently one line. The publish description's first sentence is the title the Update saved its named version under, whichever builder made it, so #2851's wording reaches it with no change here. Its "from" is the engine the old About frame recorded.
- **The frame** (`apps/plugin/src/about-frame.ts`): canvas furniture under shared plugin data `prism3`/`about`, recording the engine, contract, date and fingerprint. The fingerprint is the style guide's `fingerprintOf`, exported and reused (#2862 exports the same function the same way). An unedited frame is replaced in place; an edited one is renamed "(edited)", moved below and untagged.
- **It is part of the Update, not after it.** The dry run reads the frame (`aboutDue`) and lists it when it is missing or stale, and it is in the preview hash only while it is work, so every existing hash is unchanged. A run whose only work is the frame saves one named version naming it. A run that wrote draws it last, so the date is the run's; a run that stopped leaves it.
- **No API sets the publish description.** `@figma/plugin-typings` 1.141.0 has `saveVersionHistoryAsync(title, description?)` (version history), a per-node `description`, and `getPublishStatusAsync` (read only). Nothing publishes a library or writes its description, so the Activity drawer shows the text with a Copy button. A plugin iframe may refuse the async clipboard, so Copy falls back to a selected textarea and `execCommand('copy')`, then to selecting the text and saying so.
- **"Last changed in" is data only for now.** The panel it belongs in is #2862, not merged when this was built. `lastChangedIn` and `lastChangedLines` are tested against the wireframe's two blocks; wiring them into the panel is a follow-up.
- **Trap:** the plugin build refuses any `node:` in `dist/main.js`, and an object key `{ node: n }` minifies to exactly that. The frame lookup returns `{ frame, record }` for that reason.
