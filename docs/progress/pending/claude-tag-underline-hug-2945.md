## (2026-10-22) — Tag underline hugs its content (#2945, Q585 A)

Owner QA on a real library file found 18px of empty frame above a medium underline tag. #2937 had turned the pill's fixed height into a `minHeight` at the same rung. The owner chose Q585 A: under Tag style Underline the tag hugs its content, and the 24px target moves to code, as Link's does. A wireframe on #2945 measured the three sizes beside the pill and raised two follow-ups. Both were answered with A, which keeps what ships today, and built: the × slot keeps the rung height as its width (Q585.1), and the minimum width stays 1.5 × the rung height (Q585.2).

- **Heights:** 20 / 26 / 32px at small / medium / large (they were 36 / 44 / 56). That is the glyph-height label row (16 / 20 / 24, taller than every example brand's label line box) plus the inset (4 / 6 / 8). The label row keeps its glyph floor, so the label doesn't move when the check appears. The line stays inside the inset, so the 1px to 2px step never changes the height.
- **The trap behind the small diff:** `applyMinWidthRatio` multiplied the frame's `height ?? minHeight`. Dropping the floor alone would have thrown at materialization, because the ratio had nothing to multiply. A new `PartDef.minWidthBase` gives the ratio a base on a box that binds no height. The schema refuses it without `minWidthRatio` and refuses it beside a height. The × slot's height now hugs, so the schema's `innerTarget` rule (both sides bound) refuses the mark. The underline def drops it, and the target is code's.
- **Pill unchanged, proved independently:** `test.ts` pins the sha256 of the 45 pill members as `specMaterialize` builds them. It was computed on main before this change, and `lint-component-surface.ts`'s baseline didn't move.
- **Filed:** #2947. `lint-hit-target.ts` measures only the pill, so the underline's box and its code-side 24px target are not gated.
