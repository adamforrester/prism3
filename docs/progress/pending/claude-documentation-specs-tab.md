## (2026-10-26) — Documentation › Specs draws spec panels for the current page (#2830, Q2830.3 A)

**What.** Phase 1 of IA v2 shipped a Specs tab whose description said "Coming later". #2994 shipped the `draw-specs` agent command. Q2830.3 A says specs are drawn only on request, by their own "Draw specs", and that this action becomes Documentation's Specs tab once that area exists. This PR makes the Specs tab a real control:
- **Draw specs** (`apps/studio/src/shell/documentation.ts`) posts a new panel message, `draw-specs`. The host runs it through the agent's action, `ACTIONS.drawSpecs`, under the build's guard. The button reads "Drawing specs…" until the host's verdict lands. The verdict then shows as the result line under the button (`specsState` in `host-session.ts`). A refusal shows the host's words.
- **For the current page.** `drawSpecs` takes a scope. The agent's command stays `'file'` (every family in the file, unchanged). The panel's is `'page'`, and `specTargets` then keeps only the families whose lead set is on `figma.currentPage`, matched by the page's id. Two sets of one name are counted over the whole file first, so the panel and the agent's command skip the same families (the independent review's Nit 1 and gap).
- **Never beside another components write.** While a build, an update, an agent's run or an Update file run is out, the button is unavailable. While the specs draw, `componentBusy()` holds Build and Update file's update step too, so no other `component-update-result` can be read as the specs' verdict.
- **Never by Build or Update.** `specs/never on build` and `specs/never on update` still pass.
- **The ecosystem map** (`docs/public/ecosystem/ecosystem.json`): the `draw-specs` feature gains its figma lane, because the command is now a panel message too (`lint-ecosystem.ts` requires it).
- **Activity.** While Draw specs is out, Activity's components row runs, reading "Drawing specs…", and then shows the verdict. That is Q2830.12 A as written; the first push left it out (the independent review's Should-fix 2, held for the owner as Q3034.1).
- **Visible calls** (where the button sits, which sets it draws, its progress) are posted on #2830 as Q2830.10–.12, and each "A (rec)" is built, awaiting the owner's answers: the button in the Specs card under its description, the current page only, and the button's own busy label with one result line and the run's row in Activity.
- **Copy stays DRAFT** (Q685 A). The description drops "Coming later", which is no longer true, and the two new strings are placeholders.
