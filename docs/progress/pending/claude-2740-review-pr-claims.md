## (2026-10-16) — /review-pr: the fold checklist names the gate that catches a missed fragment, and authorship reads both session links (#2740)

**What changed.** Three corrections to `.claude/commands/review-pr.md`, found in the independent review of #2682:

- **A false claim, removed.** The fold checklist said a fragment merged after the fold's base is missed "and no gate
  catches that". `lint-progress-order.ts`'s LEAVES NOTHING PENDING arm (#2663, merged in #2667) fails exactly that case,
  on the merged tree, the branch and the push run. The step stays, as a cross-check of that gate.
- **The authorship signal.** "A session link that is your own means it is yours" read only the commit trailers. Lane
  commits carry the orchestrating session's `Claude-Session:` trailer, so a lane never sees its own link there and the
  signal cleared it to review its own PR. The command now names both places: the trailer may be the orchestrator's, and
  the PR body's `Generated by` footer, when it carries a link, names the session that wrote it. Ready comments usually
  carry only the bare footer, with no link, so the command does not point there (review of #2767).
- **A check the checklist lacked.** Re-run `fold.ts` in your own worktree at the fold's base and diff against the PR
  head. The base is `git merge-base <head> origin/main`, the newest `main` commit the fold carries, so a fold branch
  that merged `main` is re-run against what it merged. The approving review of fold #2582 ran it, and it is the one
  fold check independent of the fold PR's own claims. The one expected difference is the date: `fold.ts` stamps the
  day it runs into `CHANGELOG.md`'s "folded <date>" line and the release notes, so a re-run on a later day differs
  there and nowhere else (review of #2767, re-running #2582 a day later).
- **The fold's write list, kept current.** #2650 (merged while this PR was open) made a fold also write release notes
  under `docs/public/releases/`, and `lint-progress-order.ts`'s PURE arm admits them. The checklist's "it edits only"
  list now names them, so a reviewer does not flag a correct fold for touching them.

**Trap.** The commit trailer and the PR footer can legitimately name different sessions on the same PR. Neither alone
proves a PR is not yours. Only your own link in either place proves it is. A missing footer, or one with no link,
proves nothing either way: some lane PRs carry only the orchestrator's link, and Ready comments carry the bare footer.
