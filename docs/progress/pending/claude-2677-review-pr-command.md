## (2026-10-15) — /review-pr matches how reviews are run now, and its file names are gated (#2677, Q320.1)

**What changed.** `.claude/commands/review-pr.md`, which review lanes now follow (owner decision Q320), had drifted from both the repo and the reviews actually being run. Fixed:
- **Wrong:** two doc names that were never files (`01-architecture`, `06-surface-model`); "all four" `@prism3/*` links (five); a hand-listed gate section whose baselines were off by about two orders of magnitude, that named `emit-dtcg.ts` and `cli.ts` as CI gates (neither runs in CI), and that built only the studio bundle before `lint-us-english` (it scans the plugin bundle too) without naming `lint-voice` at all; four brands' `tokens.json` as the whole byte-identity surface; `engine: major` as a declarable class (refused below 1.0).
- **Superseded:** the gate section is now "prepare, run `npm run verify` on the PR merged with current `main`, report N/N against the head SHA"; "commit before the first mutation" is now "before every mutation" (the 2026-08-24 incident), and a mutation counts only if it fails by name; the hand-edited-log paragraph is now the fold-review checklist, since only a fold writes the log (#1807); "post a `COMMENT` review, then squash-merge" is now "one verdict comment on the head SHA, delta checks after, merge only when your instructions say you may"; the empty-commit and `--force-with-lease` advice gives way to the CLAUDE.md rules (no empty commits; corrections as a follow-up PR; compare trees).
- **Added, from what tonight's independent reviews actually checked:** the `EXPECTED_ARTIFACTS` and `EXECUTOR_REVISION` pairs and their collisions across open PRs; the owner-decision boundary (design calls go to the owner as questions, new strings listed verbatim); filing out-of-scope defects; draft markers in shipped prose; per-hunk conflict recipes; reading check-runs on the head SHA; the authorship signals agents actually leave (trailers and session links, and branch prefixes beyond `claude/*`).

**The gate.** `lint-skills.ts` check 7 reads the command and fails by name on any backticked file name that does not resolve: a path from the repo root, a bare name (`verify.ts`, `lint-skills.ts`) in one of the places its reader would look. A self-check drives it with two dead names and one live one, and a floor fails if fewer than five names are read. It runs inside the skills gate because it is the same check as scan 3 applied to the one other agent-instruction file review lanes follow; a separate gate would have meant another `ci.yml` step and gate-list entry for a dozen lines.

**Mutations, each failing by name:** `docs/01-token-architecture.md` → `docs/01-architecture.md` ("[missing file] `docs/01-architecture.md` does not exist"); `lint-progress-order.ts` → `lint-progress-ordering.ts` (missing file, with the places searched); the check's `findings.push` neutered, and its pattern pointed at nothing ("the review-command file check is broken").

**Ceiling.** It would not have caught the original defect as written: "01-architecture" was a shorthand in prose, not a backticked path, which is why this PR writes the doc names as paths. The command's advice, like a skill's, is out of reach of any name check.

Also: a comment in `test.ts` cited `review-pr.md:133` for the fail-soft trap, a line number the rewrite moved; it now names the section.
