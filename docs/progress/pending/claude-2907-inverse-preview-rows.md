## (2026-11-03) — The interactive preview draws the inverse outline and text buttons (#2907)

**What it is.** Owner decisions Q2907.1–.3, all A. Each button set on the interactive preview (Color › Interactive, and Brand's Style guide, which draws the same section) gains two rows after Inverse, each on its own inverse band, like the Inverse row. "Inverse outline" shows rest, hover and pressed with the edge `inverse.interactive.‹c›.border.‹state›`. "Inverse text" is the text button on the band, with no edge. Each state's ink chip carries its ratio badge on the band. The chips and row feet match the Outline and Text rows: `text.‹state›` chips, with `border` and `text` feet. Before this change, the color editor offered "Text · inverse" and "Border · inverse" (six roles per set) that the preview drew only when its ground picker was set to an inverse band. So a designer could change those roles and never see the result.

**The diagnosis that made it small.** The roles were already resolved, and the preview already read them: `outlineStateRoles(method, c, state, true)` is what the Outline and Text rows read on an inverse ground. The new rows call it with the ground fixed to the band, so their fill, ink and edge come from the same helper and cannot disagree with those rows. On an inverse preview ground, the new rows take the page's ground, as the Inverse row does.

**The guard.** Each specimen button now records the roles it paints, in `data-sg-binds` (`fill=…`, `ink=…`, `edge=…`). The new case in `test:chrome` section 19 runs on both hosts, previewing Light and Dark. It takes two lists of what must be drawn, each independent of the preview: the editor's rows as rendered (each column's `.p3-fillrow[data-role]`, `interactiveRowsFor` drawn) and the literal `COLUMN_ROWS`. Every role on either list must be bound by a shown specimen in its column's block, and at least one specimen binding it must paint it: its computed ink, edge or fill must be the emission's hex for the role in that mode. A role nothing binds, or that no specimen paints, fails. That arm passes as long as one specimen paints a role right, so a second arm holds each new row on its own. For each state of the Inverse outline and Inverse text rows, the roles bound are literal keys typed into the test, not read from `outlineStateRoles`: the band's text twin, the band's border twin on the outline row (no edge on the text row), and the band's overlay twin at hover and pressed (no wash at rest, under the default overlay wash). Each one's computed ink, edge and fill must be the emission's hex for that key. It also holds each new row's band to the emission's `inverse.background.primary`.

**Mutations,** each failing the new case by name. Dropping both new rows (the bug as filed) fails `… inverse.interactive.primary.text.hover is drawn … — is not drawn` for each of the 18 inverse text and border roles across the three sets. Dropping the Inverse text row alone fails `… "Inverse text" row draws rest, hover and pressed on its own band … read []`. The role arm stays green there, because those roles are still painted as the Inverse outline row's ink, which is the arm's job: representation by role, not by row. Reading the Inverse outline row's edge off the page twin fails `… inverse.interactive.primary.border.rest is drawn … — bound by 1, painted by 0`. Painting the Inverse text row in the page ink, with its bind unchanged, fails `… "Inverse text" rest binds and paints its own roles …`. Reading both new rows' wash off the page (the #1629 bug) fails `… "Inverse outline" hover binds and paints its own roles …`. The role arm alone passed both of these, which is why the per-row arm exists.
