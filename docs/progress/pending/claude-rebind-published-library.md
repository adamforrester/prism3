## (2026-10-20) — prism3-rebind covers a file that consumes Prism3 as a published library (#2854, Q446)

**What changed.** `skills/prism3-rebind/SKILL.md` assumed Prism3's variables, styles and components were local to the file. The common case is a file that consumes Prism3 as a published team library. New section 8 covers that path; the old section 8 (hand-back) is now 9 and gains one library line. Three existing lines gained a pointer to it: the detach guard in section 1, the mapping-table step in section 2, and the "legacy names look like Prism3's" trap in section 5.

**What was reused, not restated.** The never-detach rule, the font check, the breakpoint-mode rule (read the modes), the rogue-binding audit and the hand-back are unchanged. Section 8 says only what the library path alters: the library is enabled by a person, the mapping table's Prism3 side is a key, everything in it is imported before any screen, import comes before bind, fonts are checked after the import, and only published work is importable.

**The one real correction.** Both the detach guard ("confirm the main component is remote") and the section 5 trap ("tell them apart by `remote: true`") are wrong on this path: Prism3's library instances are remote too, so a guard on `remote` alone detaches the very components the skill says never to detach. The test becomes the key against a set built from the mapping table.

**Verified against the repo's plugin typings** (`@figma/plugin-typings`, the version in the lockfile): the four import signatures and their reject-if-unpublished wording, both `teamLibrary` methods and the `LibraryVariableCollection` / `LibraryVariable` shapes, "libraries can't be enabled through the plugin API", `key` and `remote` on components, component sets, styles and variables, `setBoundVariable` / `setBoundVariableForPaint` taking a `Variable`, `getVariableCollectionByIdAsync`, `setExplicitVariableModeForCollection(collection, modeId)`, `defaultVariant`, and `PublishStatus`.

**Not checkable from the typings, so stated as the owner's account, not as API fact:** that a consuming file takes a library update in the UI, and that a variant's `key` equals its instance's main component `key`. A first run on a real library file should confirm both.
