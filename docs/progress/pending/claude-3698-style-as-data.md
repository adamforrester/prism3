## (2026-11-15) — per-component style reach is data on the def, not tables in the projector (#3698 F4, R5 refactor 4)

**STATUS: PR open, not merged.** ENGINE {{ENGINE_VERSION}} (minor, `packages/engine/changes/claude-3698-style-as-data.md`: a new def field and its validator refusals; `fieldStyleFor` takes the def), CONTRACT stands. Refactor 4 of the four R5 refactors, on top of the facade (#3776), the theme split (#3777), the part union (#3780) and the field tightening (#3782). **The data shape is an OWNER DECISION** (proposal on #3698). This PR builds option A under the name `levers`, and each key is a rename away.

**What moved.** `anatomy-figma.ts` held eight tables keyed by def id: the five F4 named (`FIELD_FRAME_PARTS`, `TAG_STYLE_PARTS`, `DIALOG_TITLE_TYPE_KEYS`, `BANNER_STYLE_FILL_KEYS`, `CURRENT_INDICATOR_PARTS`) and three more the inventory found (`FIELD_CORNER_REFS`, `SEARCH_FIELD_STYLE_DEFS`, `OPAQUE_FILL_DEFS`). Each fed a brand-setting materializer (`apply*`), which runs before `figmaAnatomyPlan`. Each table is now an entry under `ComponentDef.levers` on the defs it named, keyed by the `BrandInput` setting it serves. The materializers read `def.levers` and have no def id left to key on. The tables are deleted. The four the components facade re-exported are gone from it, and their two readers (`test.ts`, the studio's `test-component-groups.ts`) derive the same maps from `componentDefs`. `fieldStyleFor(defId, input)` became `fieldStyleFor(def, input)`. `applyFieldStyle`'s guard gains `!frameName`, which is redundant at run time (no name, no frame) but keeps the name narrowed for the surfaces' stricter `tsc`, which the engine's own typecheck does not catch. The plugin's `brand-def.ts` and `field-style-note.ts` follow it.

**Why def-level and not part-level.** The precedent is `densitySpacing`, `typeWeight` and `weightIntent`: lever data on the def, validated in `validateComponentDef`. Four of the eight settings name token keys or refs, not parts. One object per setting keeps each setting's reach in one place. `PartDef` is unchanged, so `lint-part-union` and `KIND_ONLY` are untouched.

**Not emitted.** `project-def.ts` projects named fields, and the specs and component-defs exports read the plan, so `.ai.json`, the def export and its schema do not carry `levers`. `regen --check` is in sync (230 artifacts), and the three `UNCOMMITTED_OUT` exports are byte-identical on main and the head.

**Validation.** `leverErrors` refuses an unknown setting or field, a named part that does not exist or is not a box (and, for `currentIndicator`, not a foot bar), and a named key that is not bound. `controlShape.squares` is checked as ref syntax only: a materialized def keeps its `levers`, and Underline has already rebound the corner it names. `test.ts`'s first run caught that.

**Proof.** A scratch harness materialized every def (62) under 23 lever scenarios on main and on the head: each non-default value of every setting alone, plus two "all off" combinations. It compared the materialized def (minus `levers`) and every plan of its `figmaAnatomySet`: 1,426 defs, 101,936 plans and 4,432 raw def × variant plans, 0 differences. Dropping two defs' `levers` made it report 8 differences by name, so it can see one. The bundles were built on both and split at esbuild's `// <path>` markers. Web `main.js` is identical. In the plugin's dev, release and offline builds, only `anatomy-figma.ts`, the 15 def modules that gained `levers`, `component-defs-export.ts`, `brand-def.ts`, `field-style-note.ts` and the build stamps differ. `lint-executor-revision` asks for no bump, because no executor file changed.

**The gate.** `lint-projector-def-ids.ts` scans `anatomy-figma.ts` with its comments blanked. LOOKUP catches an index by def id, a membership test on it, any `.id` compared to a string literal, or `def.id` compared to an upper-case constant. TABLE catches a top-level declaration with a def id as a key, or two or more as list elements. The ids come from `componentDefs`. The allowlist is typed in the gate: `ICON_DEF_ID` and `PROVIDER_LOGO_DEF_ID`, the glyph libraries, and `CANVAS_FURNITURE`, a layout rollout list held by id on purpose. Neither is style. Every rule failed by name under a mutation, and main's own projector fails it with 16 named hits.

**Found on the way, filed, not fixed.** The Password field takes Field style but not Control shape's Boxed or Hairline corner (`FIELD_CORNER_REFS` never listed it), so under Boxed it keeps `radius.sm`. Filed as #3784 and kept as found.

**Trap.** A materialized def keeps `levers`. A validator rule that asks a named ref or key to still be bound after materializing fails on it. Keys survive every materializer today; refs do not.
