## (2026-11-02) — Update file builds _Doc-block's sets first on a first run, so every queued set gets its usage panel (#3308, Q3308.3 A)

**The defect.** The owner's first run built five sets "with problems", each for one reason: "No usage panels drawn: this file has no _Doc-block component". Set up file, the run's first step, cannot build `_Doc-block` until Badge, Tag, List item and Divider exist, and nothing later in the run builds it. The owner chose Q3308.3 A: with Documentation's usage panels on and no `_Doc-block`, Update file's run also builds those four first, listed as "Also builds", then `_Doc-block`, before the queued sets.

**The fix.** Update file's sets step asks each build for it (`build-components`' new `docBlock`, sent by `postCurrent` in the panel's `main.ts`). The plugin's `buildComponents` acts on the ask only while the panels are on, the file has no `_Doc-block`, and the file holds the theme the template binds (`docBlockThemed`). It then builds the four sets the file lacks first, each with the sets it nests, as a nested set is built, then `_Doc-block` on the File Components page (`ensureDocBlock`, found by `fileComponentsPageOf`), then this set. A set built before the template exists waits for its panel and is seated again once the panel's room can be measured (`docPanelReach` is 0 without the template). When the set asked for is one of the four, it is built before the template, which follows it. The verdict names what was built first ("Also built: …") and "Built _Doc-block". The file's read (`file-sets`) now says which of the four the file lacks when it has no `_Doc-block` (`docBlockLacks`). Update file's To add lists the ones the queue does not hold as "Also builds, when the file lacks them: …" (the existing words of `RUN_COPY.also`), and the run puts the queued ones first (`runOrderOf`), so a queued Badge builds the template itself and is not built twice. With the panels off, or without the ask (the Components page's build, an agent's), nothing changes (#3311).

**What a later reader should know.** A queue holding two or more of the four still builds the second one twice: the first post builds every one the file lacks, and the later post finds its set present ("✓ already built", clean). The ask cannot name the queue's later sets without the plugin waiting on sets that are not built yet. The owner's selection holds one (Badge).

**Tests.** `apps/plugin/test-update-doc-block.ts` drives the real `main.ts` under the strict host on a fresh file with the owner's ticks (nine sets), using #3323's host: `panels/on` (the read names the four, "Also builds" names Tag, Divider and List Item, Badge runs first, every queued set completes clean with no "No usage panels drawn" line, `_Doc-block` and the four are in the file, and each queued set's family has a live panel), `panels/off` (none of the extra sets, no template, no panel, the queue's order), and `no ask` (a build without the ask is as it was). The chrome arm `#3308: panels on/off, a file with no _Doc-block` (section 10) holds the To add line and the posts, at every width and theme. The shim gains one thing, scoped to a several-page file (`pages`): Figma takes a live component's own id as an instance-swap value, as the usage panel's Specimen sets it.

**Shim gaps met, not fixed.** The shim's search returns no frames, so a set built twice (Checkbox.Row after Checkbox group, the double build #3320 removes) cannot find the panel it replaces and reads it as in the way; and the shim's instances carry no children, so a drawn panel reports "_Doc-block has no text layer". Neither is this decision's, and the suite asserts around them by name.

**Mutations, each failing by name.** The build ignoring the ask (`blockFirst` false) → `panels/on: sets/…`, `_Doc-block`, and the panels. The ask ignoring the panels switch → `panels/off: nothing extra`. A waiting panel drawn at once → `panels/on: sets/badge` and the panels. `runOrderOf` keeping the queue's order → `panels/on: run order`. `docBlockAlsoOf` ignoring the switch → `panels/off: also builds`. `postCurrent` not asking → the chrome arm.
