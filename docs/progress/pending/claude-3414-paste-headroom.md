## (2026-11-04) — MCP paste: a set's page is placed by its own script, so a new component page no longer eats chunk headroom (#3414)

**STATUS: PR open, not merged.** Plugin and paste tooling only. **No engine change, no `out/**` change, no ENGINE or CONTRACT bump, no `EXECUTOR_REVISION` change** (`lint-executor-revision`: the executor's code is unchanged; `mcp-steps.ts` is not in its reach). Files: `apps/plugin/src/mcp-steps.ts` (a new step, `runComponentPlace`; `runComponentChunk` finds its page by name), `apps/plugin/mcp-paste.ts` (one `component-place` script before each set's first chunk; the chunk data carries `page`), `apps/plugin/test-mcp-paste.ts` (the `size/pages` arm), `apps/plugin/test-paste-reactions.ts` (runs the place step, and a chunk with no page), `tools/figma-mcp/plan.ts` and `README.md`, `docs/inventory/surfaces.md`.

**The cause.** Every component-chunk script carried the whole file taxonomy, because `runComponentChunk` called `placeOnPage`, which calls `resolveComponentPage`, which reads every section and leaf to anchor a created page. So each new component page took its taxonomy entry's characters out of every chunk of every set. Dialog's one-member chunks were left 46 characters under `SCRIPT_CEILING` (44,954 of 45,000, as numbered), and #3380's one new page (75 characters) put them over.

**The option built: placement as a step of its own (the issue's A).** One `component-place` script per set-built def, before its first chunk, runs `placeOnPage` and checks it landed on the page the generator planned. Each chunk is handed that page name in `__D` and switches to it by name. A chunk never creates a page: if the page is absent, it throws an error naming the place script. A def the taxonomy doesn't map still builds on the current page, with no place script, as before. This follows `runComponentReactions`' precedent, a step of its own to keep code out of every chunk's budget. Emit (icon) and reactions scripts still place themselves; neither is near the ceiling.

**Options turned down.** *Only the needed taxonomy entry in each chunk:* `resolveComponentPage` and `ensureSectionHeader` need the whole taxonomy to anchor a created page or section header after the earlier ones. Narrowing it changes where pages land, and the defaulted `TAXONOMY` parameter keeps the full object in the bundle anyway. *`pack` splitting a single member:* a member is one variant, built by one payload, and can't be divided. This option also leaves the cause in place: chunks would keep shrinking, just in more pieces. *Raising `SCRIPT_CEILING`:* ruled out by the issue.

**Measured.** The chunk step bundle went from about 7,700 to 2,630 characters. For one example brand, a full build went from 1,418 chunk scripts (160 of them one-member) to 698 (12 one-member) plus 57 place scripts: 1,590 component scripts down to 927. The largest one-member chunk is now 40,108 characters, 4,892 under the ceiling. Peak chunk headroom is the same for all 8 example brands: before, 46 (dialog 18/24); after, 84 (link 10/19). Multi-member chunks still pack to within about 100 characters of the ceiling, by design: `planSetChunks` fills the budget it's given. That number is packing slack, not shrinking headroom. **Adding #3380's page entry to the taxonomy, simulated:** on main, the peak went 44,954 → 45,003 (over), and the chunk count went from 1,418 to 1,463. On this branch, every chunk script was byte-identical (same hash).

**The gate.** `size/<brand>` is unchanged. A new arm, `size/pages`, has a literal expectation. A minified taxonomy leaf ships as `page:"<name>"`, and a script's JSON `__D` can't match that pattern, because its keys are quoted. The arm expects **0** such entries across all 698 chunk scripts. To show the pattern can find them, the place bundle must carry them (Dialog's and Buttons' among its 42). The arm also checks that every set is placed exactly once, before its first chunk, on the page its chunks switch to, and checks Dialog's page literally. Mutation, from a `wip:` commit: `runComponentChunk` calling `placeOnPage` again (the full taxonomy back in every chunk) → `✗ size/pages: no chunk script carries a taxonomy entry (1625 of 1625 do — focus-ring 1/1: 42 entries)`, plus all 8 `size/<brand>` arms over the ceiling. `test-paste-reactions.ts` now runs the generator's place step before the chunks. It adds two arms: `#3414 code-input-cell is placed … once, and every chunk builds there`, and `#3414 a chunk whose page is not in the file throws, naming the place step`.

**Filed, not built: #3418.** The issue also notes that `pack`'s at-least-one-variant rule silently ships an over-budget chunk, though `mcp-paste.ts`'s header says an indivisible unit that won't fit is a thrown error. The size gate still catches it, at the finished-script level. That is a separate concern from this PR.
