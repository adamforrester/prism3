## (2026-10-22) — Usage panels, phase 1: one panel per family, markers on their parts, no stacked panels (#2927, #2916)

The first phase the owner asked for after deciding Q551 A on 1–10 (the wireframe on #2927): the P0 bug, the anatomy markers, and one panel per taxonomy page. Examples instead of chips, related links, the file-wide switch and drawn Do/Don't pairs are later PRs (checklist on #2927).

- **The stacked panels (P0).** A panel's "unedited" test was the style guide's whole-subtree fingerprint, which reads the specimen: the documented set's member, its layers, its main component, and every size it pushes up to the panel. A rebuilt or updated set changed all of that with no one touching the panel, so the next draw read the panel as hand-edited, kept it aside renamed "(edited)" and drew a fresh one: two panels stacked. The print is now taken through a view that leaves out a specimen's content, every width and height and every instance's main component (a rebuilt Badge or Tag did the same to the markers and chips). Text, fills, visibility and structure still count. A print in the old form is still compared the old way, so panels drawn before this are not all kept aside on the next update. **Not confirmed on the review copy**: the mechanism reproduces in the shim; that it is what Progress hit is inferred (Progress was the draft rebuilt most often).
- **Markers (#2916).** Three causes, all fixed: parts were found by layer name anywhere (now by the def's part path, step by step, so a slot child or a part inside a nested instance is reached and a same-named layer inside another part's nested component is not taken); positions summed relative x/y and centered the marker on the part's corner (now read from `absoluteBoundingBox`, the host's laid-out box); the root and any part not in the default member had no layer to mark (now a bracket for the root, a boolean turned on for a hidden part, and one more specimen per member for the rest, numbered across them).
- **Geometry.** Leaders go to the nearer of the top and bottom gutters at the part's middle; brackets go on the left, innermost nearest. A marker that would touch another moves one tier out, and the stage's padding grows to hold every tier. "Crosses no other layer" from the wireframe is not implemented: a leader may cross layers between the gutter and its part.
- **Families.** `lead` is data on the taxonomy leaf; `assertCoverage` fails by name on a multi-def page with none. The panel is drawn only from the lead; the dry run counts it due while a member still carries its own panel; only the lead's set reaches past a panel when Update spaces sets (`PageSet.lead`).
- **Gates (`test-doc-panel.ts`).** The host now lays nodes out itself (`absoluteBoundingBox` from its own auto-layout model) and builds every fake set's members from the engine's plans, so the marker oracle (each marker frame and its leader overlap the part's box, the Badge sits in its stage's gutter, off the specimen) is independent of the placement code. Ten mutations, each failing by name: summed offsets, the whole-subtree print, family panels not replaced, no merge, no reveal, no extra specimens, no gutter growth, a non-lead drawing, no bracket, every set reaching.
