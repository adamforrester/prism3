## (2026-11-14) — `PartDef` is a union discriminated by `kind` (#3698 F4, R5 item 3)

**STATUS: PR open, not merged.** ENGINE stands (no engine output moves, so no change note), CONTRACT stands. Refactor 3 of the four R5 refactors, on top of the facade (#3776) and the theme split (#3777). Files: `packages/engine/component-schema.ts` (the union, and the validator reading the wide bag), `packages/engine/anatomy-figma.ts` (four transform sites), `packages/engine/index-components.ts` (one type re-export), `packages/engine/lint-part-union.ts` (**NEW** gate, registered in `ci.yml`, `verify.ts`, `CONTRIBUTING.md` §3, the PR template and `CLAUDE.md`), and two plugin test fixtures (`test-native-slots.ts`, `test-slot-constraints.ts`). The 53 def files are unchanged.

**What changed.** `PartDef` was one bag of 77 optional fields under a `PartKind` string. The bag stays, renamed `PartFields`, because it is where every field's doc comment lives, unmoved. `PartDef` is now the union of seven types, `BoxPart` … `VectorPart`. Each is its `kind`, the eight base fields, the fields that kind admits, and every other field typed `never`. Because every member names every field, a read of any field on any part still compiles (it is `undefined` on kinds that do not admit it). So the consumers needed no narrowing to read; only code that writes a kind's field onto a part of unknown kind did. Two compile-time checks sit under the union: every `PartKind` is a member, and every field is admitted by at least one kind (`PartFieldsPlaced`; a mutation removing `gap` from the box list trips it).

**The rule the lists follow.** A field is admitted on a kind unless `anatomyErrors` refuses it there, directly (`is kind 'X' but declares 'f'`) or through a field it requires (`footShare` needs `foot`, `slotSettings` needs `contentSlot`, both box-only). That is "legal today" by the validator's own definition, so the union adds no rule the run time does not already enforce. Every field every shipped def writes on a kind is in that kind's list (tabulated from `componentDefs`, all seven kinds). Eight fields the validator never refuses by kind are base fields, admitted everywhere: `role`, `optional`, `note`, `radius`, `type`, `replaces`, `overlaysWhenAbsent`, `when`. Several of those have docs naming one kind (`type` "for text parts", `replaces` "for overlay"). Tightening them, or `children` (refused only on vector, nest and absolute), is a schema decision, flagged on the PR, not taken here.

**Why the validator reads the wide bag.** Read through the union, every `p.kind !== 'box' && p.layout` refusal narrows to `never`, and tsc reports the refusal as dead code (TS2367, 40-odd sites). The refusals are not dead: a def reaching the engine as JSON or from plain JS is never typechecked. So `anatomyErrors` types its `parts` as `Record<string, PartFields>`, one type-only line, and every per-kind refusal stays. `replacesCandidates` takes `Pick<PartFields, 'replaces'>` so both readers can call it.

**The four transforms.** `applyFieldStyle`, `applyTagStyle` (twice) and `builtSizeAt` spread a part and add box fields (`strokeEdges`, `minHeight`, `grow`). Three now narrow: `frame.kind !== 'box'` returns the def unchanged, and the label row is rewritten only when it is a box. Every current target is a box (checked: seven field frames, Tag's frame and label row), so no output moves. `builtSize.grow` names a column child without typing its kind, so that spread takes a type-only `as PartDef` and its JS is unchanged.

**Proof.** `regen --check` is in sync: 230 artifacts, none changed. The three uncommitted component exports (`UNCOMMITTED_OUT`) were rendered on `main` (9725b18c) and on this head and are byte-identical. Bundles were built on both and split at esbuild's `// <path>` markers: web `main.js` is byte-identical. Plugin `main.js` and `ui.html` in the dev, release and offline builds differ only in `anatomy-figma.ts` (the three guards, 6 lines) and the build-stamp lines. No executor file changed, so `lint-executor-revision` asks for no bump. A whole-tree `tsc` (engine, both apps, `tools/`, with `@types/node`) adds errors only in test files no tsconfig covers: `packages/engine/test.ts` (+11, mostly negative fixtures that build an illegal part on purpose to exercise the validator) and three plugin test files already carrying errors. The two plugin test files that were clean are kept clean.

**The gate.** `lint-part-union.ts` writes one probe file per case to `$TMPDIR` and runs the real tsc over them. Per kind, one legal part must compile, and each illegal probe (24, at least two per kind) must fail with tsc naming that field (`Types of property '<field>' are incompatible`). The probes are authored in the gate and never read the per-kind lists. Every kind a shipped def uses, read from `componentDefs`, must be probed both ways. Each arm failed by name under a mutation from a committed tree:
- text admitting `layout` → `the union ADMITS 'layout' on a 'text' part`.
- every kind admitting every field (the bag back) → all 24 illegal probes named.
- box refusing `gap` → `LEGAL box part refused`, plus `PartFieldsPlaced` failing.
- the legal vector probe deleted → `kind 'vector' is used by a shipped def but has no LEGAL probe`.

**Lints made redundant: none.** `lint-nesting`, `lint-paint-placement`, `lint-absolute-inset` and `lint-fill-under-hug` measure what a projection builds (the nest graph, paint on built nodes, ring geometry, fill under a hugging parent), which no field type expresses. What the union duplicates is a slice of `anatomyErrors`' per-kind refusals, which stay for untyped defs. #3778 asks whether any of them should go. Found on the way and filed, not fixed: `builtSize.grow` can name a column child of any kind, though `grow` is a box/nest field (#3779).
