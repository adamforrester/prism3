## (2026-10-20) — One canonical colour-variable order, default and inverse alike (#2860, #2836)

The owner hand-reordered the default colour groups in the master file but not the inverse ones, so the two read differently, and `foreground` listed `danger` after the subtle tints. The order is what Figma's variable panels show, and it is the emission's write order, so the fix is in the emission (owner decisions Q453 A on #2836, and the reference order on #2860).

- **One module, `packages/engine/color-order.ts`**, replaces `COLOR_FAMILY_ORDER` and `orderedRoleKeys` in `tree.ts`. Families: background, foreground, text, interactive, border, icon, disabled, scrim, veil, field, inverse. Below the family, one sibling list per depth. The statuses are `SEMANTICS` from `modes.ts` (now exported), not a second copy. `inverse.<family>` is ranked as `<family>` with `inverse.` stripped, so the two cannot drift. A segment the module does not name throws, except the tone slot of `interactive`, which a brand can extend (`interactivePalettes`); an extra tone sorts after the named ones in build order.
- **Key order only.** Every moved file was read back and compared with `main` after sorting keys: 41 files, 0 differ in content. Token names, values, aliases and the contract baseline are untouched, so `token-contract.ts --check`, `nb-regression.ts` and `regen.ts --check` agree with the new emission.
- **Which files move:** `packages/engine/out/<brand>.tokens.json`, `<brand>.base.tokens.json` and the three `<brand>.*.overlay.tokens.json` for nb, prism3, aurora, harbor and wendys (the key order of `color`), and `out/figma/<brand>/color.{light,dark,hc-light,hc-dark}.json` for nb, prism3, aurora and wendys (the order of `variables[]`). No other committed artifact moves.
- **No code path sorted keys alphabetically before emission.** `emit-figma-color.ts` `byNumericKey` is a stable no-op for non-numeric keys, and the remaining `.sort()` calls in the write path are prune reports. The gate asserts hover precedes focused and success precedes danger, so a sort that comes back fails by name.
- **Gate:** the `#1150` block in `test.ts` gains a `#2860` block. Everything is a literal typed in the test, none read from `color-order.ts`. Per brand it asserts, on the DTCG tree and on each Figma mode file: every group is one run; statuses are brand, success, warning, danger, info in every group (bare, subtle and on-); each inverse group is the default group's order restricted to what the inverse has; scrim and veil are the only families with no inverse; plus design-UX spot checks. Mutations (each committed first, each run through `regen.ts` and `test.ts`): `foreground.danger` ranked last fails `statuses in canonical order` and `foreground lists danger with the statuses`; one inverse interactive part moved fails `inverse mirrors default`; alphabetical segment order fails the `design-UX order` lines; `border.primary` split off fails `inverse mirrors default`. `apps/studio/test-status-order.ts` (#2843) drops its `foreground` exception and now holds all eight groups to the canon.
- **Contiguity is guaranteed by the tree's shape.** The emission is nested, so a group cannot be split by building it; the master file's splits came from variables appended later by releases. The contiguity assertions are a regression guard for a flattening change, not something a ranking mutation can break.
- **Existing files (the plugin limit).** The Plugin API moves styles but not variables, so an existing file cannot be reordered by the plugin. The Update check now reads the file's `<root>/color/*` variables in the order the host returns them and lists the fewest to drag (`colorVariablesOutOfOrder`, a longest-run calculation), as one line: "Color variables: N out of order (…)". It is a report: nothing moves, and it is not in the apply's hash. A file built fresh from the emission reads clean. Documented in `apps/plugin/README.md`.
- **Downstream, and what it showed.** The style-guide page (Figma) draws its colour tables in the emission's family order ("in file order"), so its typed-out expectations in `apps/plugin/test-style-guide.ts` (tests 3, 9, 10 and 26: table order and the column each table sits in) failed by name and were updated to the new order, inverse tables included. The inverse table list there had been the old inverse order from the master file (background, foreground, interactive, disabled, field, text, icon, border); it now mirrors the default.
- **Traps for whoever re-verifies.** The throw messages in `color-order.ts` ship in the built bundles, so they are held to US spelling by `lint-us-english`. `studio test:smoke` fails one assertion in this sandbox (the "Not installed" font status is not drawn for harbor) and fails identically on `main`; it is a fonts-in-the-sandbox condition, not this change. `lint-release-notes` cannot run in a shallow clone (`git fetch --unshallow`).
