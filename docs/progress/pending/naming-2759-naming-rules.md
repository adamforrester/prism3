## (2026-10-16) — Naming sweep PR 1: the naming table in the build-component skill, and `lint-naming.ts` (#2759, owner decisions Q345, Q349, Q350, Q355, Q394)

**What moved.** `skills/prism3-build-component/SKILL.md` §6 has a naming table: a root is named for its role from a closed list and never the def's id, main text is `label`, a glyph layer is `<shape>Glyph`, and a Row's control cell is `controlCell`. It also states the `_` prefix rule (a part that should not be used outside its parent takes it; a slot's preferred item and the checkbox and radio controls are exempt) and the casing rule (Figma property names are lowercase). §2's stale list of root names is replaced by a pointer to the table (audit item S1). `packages/engine/lint-naming.ts` is a new CI gate that checks every rule except main text.

**No def changed.** The renames come in PRs 2–4 of #2759, one kind each. The gate finds 22 breaches on `main` today: 4 property names (PR 2) and 18 layer names (PR 4). PR 3's one rename (`tab` → `tab-item`) breaches no rule this gate reads. Each is listed in the gate's `PENDING` ledger with the PR that clears it. A breach not listed fails by its arm's name. A listed entry that no longer breaches fails as `stale`, so the ledger cannot keep an entry the defs have outgrown.

**Why the rules are literals.** Each arm's expected value comes from the owner's rule, typed in the gate: `name.toLowerCase()`, the role list, the `Glyph` suffix, the `controlCell` name, and the two private-part wordings. Nothing is read off the defs, which are the subject (`docs/34` shape 1). The ledger is a waiver, never the oracle. The root list, the owner's prefixed set and the exempt controls are written twice, in the gate and in the skill's §6, so a sixth arm (`skill`) parses §6 and fails if either copy moves without the other.

**How the prefix rule is read.** "Should not be used outside its parent" is read off `ai.whenToUse`, which says it as "Never directly …" for the accordion indicator, the owner's one prefixed def. Both directions are checked: the wording without the prefix, and the prefix without the wording. The owner's set is a floor: each id must be registered (or be the target of a pending rename) and must be detected by the wording, so rewording a whenToUse to slip the rule fails. Radio row's "Always as a child of a Radio.Group" matches neither wording, and Q355 leaves it out of the set. That call is raised on #2759 as Q-N1.

**Slot items stay unprefixed (Q394 A, #2783).** The tab, the list item and the segmented-control segment are each a native slot's preferred item. Figma does not publish a `_` set, so a `_` slot item would offer nothing to insert in a file that uses the library (#2831). A seventh arm, `slot item`, reads every content slot's `preferred` and `preferredWhenBuilt` and fails by name if any of them names a `_` id. The prefix arm does not ask a slot item for the prefix, even though their `whenToUse` says "Only as a child of …". `SLOT_ITEMS` is the owner's list and a floor: each must be registered, unprefixed and offered by a slot. It is also parsed from §6.

**Main text is not checked.** Which text part is the main one is a judgment (a dialog has a title and a description), not a field. FieldLabel's root is already `label`, so its main text cannot also be `label` without a root rename. That is raised as Q-N3 with a recommendation.

**Liveness.** A self-check feeds each rule a known breach and a known pass. A floor asserts that the walk saw property names (226, the state axes included), every root, glyph layers (17), control cells (3), private defs by wording (4) and slot items (8). Mutations are recorded in the PR.
