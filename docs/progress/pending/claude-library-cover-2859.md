## (2026-10-21) — Library file cover: brand and version, kept current by Update (#2859)

Built from the approved wireframe and the owner's Q509 A, which accepted every recommendation: a new optional `BrandInput.name`, falling back to the `id` as written (Q?1); no logo, the wordmark in the brand's display face, the logo slot a follow-up (Q?2); the brand color as the ground with `text/on-brand` (Q?3); a hand-edited cover kept, with only its tagged version text refreshed (Q?4 B); drawn by Set up file and kept current by every Update (Q?5); "Prism3 {{ENGINE_VERSION}}" (Q?6).

- **The cover** (`apps/plugin/src/cover-frame.ts`): a 1920 × 1080 frame named `Cover` with two texts and nothing else, tagged `prism3`/`cover` (the engine and name it was drawn for, and its fingerprint) and `prism3`/`cover-part` = `brand` | `version`. Every color and font is bound, so Apply Theme moves the cover live; a file with no theme yet gets placeholders that the first Update finding the variables binds, only while they are still the placeholder (the `bindBackdrop` rule).
- **The contrast is the engine's, asserted against it.** `test-cover-frame.ts` maps the cover's two variable tails to the engine's role paths and checks, for every example brand and mode, that `text.on-brand` is contracted against exactly `foreground.brand` at 4.5:1 or more, and measures the pair itself from the emitted hex with its own WCAG function, so the engine's `ratio` is the claim and not the measure.
- **An Update never replaces the frame.** The About frame (#2858) replaces an unedited frame in place, but the cover is the thumbnail, so replacing it would drop the thumbnail pointer. An unedited cover is refreshed in place (version, name, placeholder bindings); an edited one has only its tagged version text set. A cover-page-only run saves no named version, as Q498 B says for the About frame, and the lines name the cover. A cover-only run leaves a current About frame alone: no set changed, so its date has nothing new to say.
- **Its own fingerprint.** The style guide's `fingerprintOf` reads each text's font and size; a bound display face moves both when Apply Theme changes the family, so every theme change would read as a hand edit. `coverPrint` reads a bound font by its variable id and leaves text geometry and the version's characters out.
- **The thumbnail rule.** `setFileThumbnailNodeAsync` runs only while `getFileThumbnailNodeAsync()` is `null`. A designer's frame is named in the result and left.
- **The brand comes from the file.** Set up file and the Update read the saved brand (`persist-figma.ts`); a file with none gets no cover, it is not work, and the line says to Apply Theme first.
- **Trap:** the shim's text measures `characters.length * 6` at any size, so the long-name fit rule (240 px on one line, else 180 px wrapping inside the 120 px inset) is tested on a host written in `test-cover-frame.ts` that measures by size.
