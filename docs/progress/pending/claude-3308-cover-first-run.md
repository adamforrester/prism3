**The defect.** The owner's first run never drew the cover or About this library. Set up file, the run's first step, has no brand yet ("the file has no brand yet. Run Update file with Theme ticked, then it draws the cover"), and nothing after Theme in the same run drew either. Only a later Update file whose in-place update ran (its finish, `finishAbout` in `update-apply.ts`) drew them. The owner chose Q3308.4 A: a run that includes Set up file and Theme ends by drawing both.

**The fix.** Update file's run gains a last step, `cover` (`state/update-file.ts`), in the run only when Set up file and Theme both run (`stepsOf`). It is the in-place update over no sets: the panel's `main.ts` asks for the check (`update-check-request`, no defs) for the hash, then applies it (`update-sets`, no defs), through the same path as the `update` step (`inPlaceOf`). The plugin is unchanged: an update whose only work is the Cover page's draws the cover and About this library and saves no named version (Q498 B), and says so in its verdict. A Stop or a refusal ends it as it ends the update. The step's names are new words, DRAFT: "Cover and About this library" (the checklist's running line), "Drawing the cover and About this library" (the strip), "the cover" (Stop after, Stopped at) and "Cover page drawn" (the verdict line; the owner's copy decision, 2026-11-02).

**What a later reader should know.** The update over no sets reads, and does, any other work it finds beyond the sets (page order, block headers, sets on a former page), as every Update does. On a file Set up file has just laid out there is none. With Documentation's cover off, the step draws About this library alone.
