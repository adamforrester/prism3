## (2026-11-07) — `@prism3/tokens` ships the house brand's token CSS as an installable tarball (#3408 S1)

**What changed.** `packages/tokens` was only a gate; since Q99 A it also builds what a client installs. `npm pack -w @prism3/tokens` now produces a tarball holding the house brand's CSS custom properties and the README, nothing else, and that tarball installs into a client project with no registry (Q84 A). Engine output doesn't move, so there is no change note.

- **`sd.ship.mjs`** builds `prism3` from the conforming projection the engine already emits: one stock Style Dictionary v5 run per mode, the base (the light defaults) under `:root`, each overlay under `[data-theme="<mode>"]`. It is the consumer build's shape, in its own file so the gate's config never bends to suit a deliverable. The four per-mode files are then joined into `dist/prism3.css`; joining finished files is plumbing after Style Dictionary ran, not a format, and no client runs it. No Style Dictionary bump was needed: the installed 5.5.0 does all of it.
- **Names stay `--pds3-…`** (Q98 A, now `docs/35` §9.4 with its index rows). No `prefix` option, no rename.
- **`package.json`:** `exports` (`.` and `./prism3.css` → the joined file, `./prism3/*.css` → one block each), `style`, `files: ["dist/"]`, `prepack` running the build. Still `private` at `0.0.0`: `npm pack` works on a private package, and publish refuses it. No JS is emitted, so there is no ESM entry to declare; `"type": "module"` stays.
- **The no-custom-code rule now covers both files.** `check-consumability.mjs` reads `sd.ship.mjs` as source with the same banned list as `sd.consumer.mjs`.
- **New gate, `check:package`** (CI step, `verify.ts`, CONTRIBUTING §3, CLAUDE.md §4, PR template). It packs, installs the tarball with `--offline` into a temp folder outside the repo, resolves the CSS through the installed `exports`, and checks every guaranteed name from `token-contract.json` with a DTCG type (618 of 621) under `--pds3-` in each of the four promised blocks, plus that each `[data-theme]` block changes at least one value from `:root`. The contract, the prefix and the promised blocks are the oracle; none is read off the build.
- **Mutations, each failing by name:** dropping `dark` from the build's mode list fails `[BLOCK] [data-theme="dark"] is in the installed CSS`; adding Style Dictionary's `prefix` option fails `[NAMES] … under --pds3-` and `[PREFIX]` for every block.

**A trap for whoever re-verifies this.** The three `motion.spring.*` contract names aren't in the CSS, by design: `spring` isn't a DTCG type, so it isn't in the projection the build reads (#642). The gate excludes them by its own copy of the DTCG type list and prints them on every run. If a spring ever reaches the projection, the gate's count rises rather than failing silently.
