## (2026-10-09) — Studio: the preview header's mode select shows its whole label at 640 and 800 (#2383)

**What changed.** Where the mode radios do not fit, the preview header shows the select of the same modes. At 640 that select drew only its caret: the chosen mode's name was cut to nothing on Interactive and to "Lig" on Palettes. It was cut at 800 as well, which the issue did not name (an 82px content box for 177px of "HC light (derived) · all pass"). The select is now never narrower than its longest option. Where the title, the select and Inspect do not fit one row, the select takes its own row under the title, Inspect stays on the title's row, and the title never truncates. In the default theme that is every select case at 640, 800 and 380; at 1280 the radios still fit and nothing moves. This layout is a DRAFT for the owner's screenshots.

**The diagnosis.** The select was `width: 100%` inside a wrap that was `flex: 0 1 auto; min-width: 0`. A select is a compressible element: with a percentage width, its min-content contribution is zero, so the flex row could squeeze it to its padding. Setting `min-width` on the wrap alone does not fix that. The select needs `width: auto`, so it takes its widest option's width, and its wrap needs `flex: none`.

**Why the wrap is decided in script, not CSS.** With `flex-wrap`, the browser breaks a row in source order, so the item that drops is Inspect and the select stays beside the title. The draft keeps Inspect beside the title and moves the select under it. CSS cannot reorder only when the row breaks, so the mode control's existing `fit` (which already chooses radios or the select) now also sets `data-row="own"` when title + select + Inspect + gaps exceed the header's content width. The header wraps through `:has()`. Every width it measures is the same on either row, so the answer cannot flip.

**Two traps the fix ran into.** (1) Moving the select changes the header's height inside the header's own ResizeObserver callback. Chromium reports that as "ResizeObserver loop completed with undelivered notifications", a window `error` event that neither Playwright's `pageerror` nor the console catches. The first build raised it 7 times per case at 640 and 800. The observer now runs `fit` in the next animation frame, and section 40 counts that error explicitly. (2) A title change ("Palettes" to "Surfaces & fills") changes what is left for the control without resizing the header, and a new verdict count changes the select's width, so the header's observer alone missed both. The title and Inspect are observed too (never the control itself), and a redraw of the select's options re-runs `fit`.

**Tests.** `test:chrome` section 40 (36 and 37 are on `main`; open #2393 holds 38 and #1855 claims 39): both hosts, both chrome themes, 640, 800, 380 and 1280, on Palettes (Light, held), Interactive and Surfaces & fills, those two in each of Light, Dark, HC light and HC dark. Where the select shows, its chosen option's text, measured in a probe span in the select's computed font, fits the select's content box, and it reads the mode's label, which is typed as a literal in the test. Where the radios show, the checked radio's name is not cut. In every case the header has no horizontal overflow, the title, the control and Inspect sit inside it, and the title is not cut. At 640 the select must be the control shown in every case, so the label check cannot pass because only radios were drawn. Before the fix: 68 failures at 640 and 800 on both hosts. The mutation (the wrap back to `flex: 0 1 auto; min-width: 0` and the select back to `width: 100%`) fails by name at 640.

**Trap for whoever re-verifies this.** At 640 and 800 on `main`, a pointer cannot reach the Interactive sub-page, because the preview covers it (#1975, open as #2393). Section 38 reaches Interactive by keyboard at those widths, as section 19b does. Once #2393 lands, that branch can go.
