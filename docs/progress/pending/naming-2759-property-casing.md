## (2026-10-16) — Naming sweep PR 2: Figma property names are lowercase, renamed in place by Update (#2759, owner decision Q345 A)

**What moved.** Four property names: Switch.Control's `State icon` → `state icon`, Image placeholder's `Marker` → `marker`, Tag's `Check icon` → `check icon`, and Segmented control's `Label` → `label`. The code props are unchanged. Shipped prose that names them (Image placeholder's whenToUse, do and don't, and the switch and tag notes) follows. `lint-naming.ts` drops their four `PENDING` entries.

**The mechanism.** `COMPONENT_RENAMES` covered variant axes and values only, so a property name change was a delete and an add on Update: every placed instance lost the value a designer had given it. The ledger gains a `property-rename` kind (`renameProperty` follows chains and refuses a cycle). It is not `property`: #2649 took that kind on `main` for a property gone with no successor. The dry run (`dryRunSet`) reads the set's property under its old name as the new one when the ledger renames it, the plan wants the new name and the set has none. It lists it in `properties.rename`, which already existed in `SetPreview` and was always empty. The apply renames those first with `editComponentProperty(key, { name })`, before any delete or default edit. Figma keeps the property's `#id` through a rename, and references and instance values follow the id.

**The forcing function.** `schema/component-axes.json` records each set's properties by panel name and type (#2649 added the record on `main`). `unaccounted` fails a property that leaves a set unclaimed, and a `property-rename` entry now claims one; `danglingTargets` fails a rename whose target the set does not declare. `main`'s baseline already holds the old names, so the lint checks this PR's own four renames. `test.ts` checks the accounting on hand-built baselines, and the shim test below checks the apply.

**The shim, made to tell a rename from a delete.** `component-shim.ts` already renamed a property's key on `editComponentProperty({ name })`, but it left every `componentPropertyReferences` entry pointing at the old key, and an instance held its value by the full key. A renamed property would have read as wired to nothing, and every instance would have been reset. It now moves references to the new key and holds an instance's value by the property's id, as Figma does. `test-update-apply.ts` runs the same check for each of the four renames, typed in the test from Q345 A rather than read off the ledger, so deleting any shipped entry fails by its def's name (the lint cannot, once the baseline records the lowercase names). For each def it builds the set from plans that say the old name (the file as it was) and places an instance with the switch off. It first shows that with no ledger entry the dry run removes the old name and adds the new one. With the entry, the dry run lists one rename and nothing else. After the apply, the set has one property under the new name and the same id, the instance's switch is still off, the set and every member keep their keys and ids, and a second dry run reads every member current.

**The per-item booleans are gone.** #2649 replaced `Option N`, `Tab N`, `Item N` and `Segment N` with native `items` slots on `main`, so there is nothing of theirs to rename, and PR 1 deleted their `PENDING` entries.
