## (2026-10-16) — Style guides: grouped into titled sections, inverse under its default (#2801, owner decisions Q378)

**What moved.** Every style-guide run now draws its guides into titled groups. On Primitive tokens: Palettes, Dimensions, Fonts. On Semantic tokens: Semantic colors, Space & size, Borders, Fonts. Each group is a top-level frame (`Style guides — <title>`): a vertical auto layout, transparent, padded 88 / 160 / 160 / 160, a `_Section-header` Size=Large holding the title only, then a HUG grid of guides 160 apart. Groups stack down the page in the table's order, 320 apart. Effect and gradient styles have no group, and sit below the last one in decision 16's rows. The inverse table splits per family ("Inverse text", keyed `…/inverse/text`), and Semantic colors draws each inverse guide in a second row, under its default-surface counterpart.

**Where the table lives.** `packages/engine/style-guide-groups.ts`, a pure table and one function, `styleGuideGroupOf({ type, tier, allRadius })`. The plugin's planner sets each table's `group` from it. The rule reads type and tier, plus "every row is a radius" for Borders, never a family name. So an icon COLOR family lands in Semantic colors and an icon SIZE family in Space & size from the same rule, with no special case for "icon".

**Membership is read from the canvas, every run.** That is the design choice the rest follows from (decision 3: a guide a designer moved stays moved). A guide found inside any page-level frame stays there and is redrawn in place. The table is consulted only for a guide in no group. Two plugin-data records make the cases tell apart without stored defaults. A group Prism3 drew carries `prism3-style-guide-group` (its id) and a `<page>|<frame>` mark, so a designer's duplicate is never taken for it. A guide carries `prism3-style-guide-in-group`, the id of the group it was last found in. A loose guide with that record was dragged out by a designer and stays loose (Q5 A). A loose guide without it was drawn by an earlier build, before groups existed, and joins its group on the next run, at the place the old rows started. That migration is what the owner's main file will see.

**Adoption.** A group's home is the group Prism3 drew for it. Failing that, it is the hand-made frame holding the most of its guides, adopted with its title, place and layout untouched; new guides are appended as that frame's layout allows. Only then is a group drawn. Adoption is recomputed every run from the guides, so nothing marks a hand-made frame.

**Full and partial runs.** A full run removes a group Prism3 drew once it holds nothing but its own title and an empty grid. A designer's note counts as content. A hand-made group is never removed. The full run closes each grid over removed guides (empty columns dropped, order kept) and re-stacks Prism3's groups that are still where it left them. A filtered or stopped run does none of that. It only moves what sits below a group whose height changed, by exactly that change. The trap the test caught: a group drawn in the same partial run was already placed against the page as it stood, and the first build pushed it up into the group above it. Groups drawn this run are now left out of the push-down.

**The superseded check.** A guide in a group no longer has a meaningful x and y (the group's layout sets them). So a superseded guide in a group counts as the generator's while it sits in the group it was last found in, on its page, and is deleted when unedited. Dragged out or moved to another group, it is "moved" and kept, as before.

**Tests.** `test-style-guide.ts` §37 asserts each rule with typed literals: the table by type and tier (another brand's accent ramp, a semantic link family, icon sizes, border widths, radii); adoption, including a hand frame holding two groups' guides; a guide moved by hand into another group; a designer's note; a retitled group; an emptied group, which a filtered and a stopped run keep and a full run removes; an inverse family with no default; effect styles below the groups; and a header set with no Size=Large. Sections 10, 11, 13, 23, 24, 30 and 33 asserted the old page-level rows. Their intent now holds for the groups: column alignment, widening by exact deltas, the grid closing over a deleted guide, the push-down, and no page-level overlap. 21 mutations each fail a named check (PR body).

**Not verified offline.** The shim models a GRID's HUG tracks and auto layout, but not the host's x/y for grid children. Two things are live-checks: that a guide reparented into a grid cell keeps hugging, and that `setGridChildPosition` plus a lower `gridColumnCount` closes a gap the way the shim does. The owner tries this in their test file first.
