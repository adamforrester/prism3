## (2026-11-12) — Update file's run goes on past an update that wrote every set, some to check (#3711, Q-UF3 A)

**The defect.** The owner's Update file run on 2026-11-12 wrote all 47 sets, and the strip read "Stopped at the update". Some sets were not verified (a field differs from the plan, a part not written as planned, a member not finished). `applyVerdict` (`apps/plugin/src/update-apply.ts`) returns `ok: false` for any of those, and `stepDone` ends a run on any step that is not ok, so the steps after the update never ran.

**The fix, the #3308 precedent (#3323).** `applyVerdict` now returns `completed`: the run went through every set it was given, none stopped (`o.stopped`), none refused or left not updated, and no stop asked for. The plugin posts it on `component-update-result` (`messages.ts`), the panel reads it (`write-adapter.ts`, `true` only), and `main.ts` passes it as the update step's `warn`, so the run goes on and the strip ends "File updated" as a warning. A set that stopped or was refused, or a stop the person asked for, still ends the run. The headline of such a run is DRAFT: "⚠ Updated 47 sets · 2 to check" (the sets written, those to check among them); each set to check keeps its own lines naming what differs, as before. A refused set now heads the verdict ("✗ n sets not updated") over sets to check beside it, since it is the one that stops the run; before, "⚠ n sets not verified" hid it.

**What this does not do.** The wording of breaking changes (Q-UF1) and the callout before the run (Q-UF2) are their own PRs. The per-set lines still name three items, then "…".

**Tests and mutations, each failing by name.** `uf3/warn`, `uf3/one`, `uf3/refused stops`, `uf3/stopped stops`, `uf3/halted stops`, `uf3/clean` (`apps/plugin/test-update-apply.ts`, outcomes and headlines typed); `run/update warn goes on` (`test-update-file.ts`); `verdict/update warn` (`test-status-strip.ts`); the write-adapter's `completed` arms; and a chrome arm in section 3170 that posts the host's verdict to the built panel. Mutations: `completed` true for a refused set → `uf3/refused stops`; `main.ts` passing `false` for the update's `warn` → the chrome arm ("Stopped at Tag").
