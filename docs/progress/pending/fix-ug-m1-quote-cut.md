## (2026-11-11) — Usage panels keep a quoted example whole (UG-M1, part of #3552)

The usage panel cuts each line to its first sentence or two (`firstSentences`, `apps/plugin/src/doc-panel.ts`). The cut split at a period, a space and a capital, and it did that inside quotation marks too. So a Content › Errors example of two sentences lost its second half and its closing quote. Three panels showed it: Progress (`"Upload failed. The connection dropped.`), Card number field and Code input. This was class N1 of the 2026-11-11 usage-guide scan.

**The fix:** each sentence inside a quote still counts toward the cut, but when the last sentence kept leaves a `"` open, the sentences after it are kept until the quote closes. So the cut never falls inside an open quote, and a line whose quote already closed inside the cut is unchanged. Only straight quotes are counted, because the defs' prose uses only those. The three lines now end with their quotes closed. Progress's line also keeps its trailing `Not a bare "Error".`, since that sentence follows the closing quote with no period before the space. No other planned line moves across the 37 leads (checked by diffing every string in every lead's planned blocks against `main`). A first version joined a quote's sentences into one before counting, which also lengthened Textarea's and Switch row's lines by a sentence; review caught it, and this version keeps them as they were. The plan hash moves on those three panels, so Update file offers them once, as expected. The docs site and `.ai.json` don't cut, so they were never affected.

**The gate:** a new `quote/…` arm in `apps/plugin/test-doc-panel.ts`. Its three expected lines are typed by hand from each def's `errorPattern`, and a sweep checks that no string in any lead's planned blocks carries an odd count of `"`. Two more hand-typed lines, Textarea's and Switch row's, pin that a quote closed inside the cut extends nothing. Mutations: the extension dropped from `firstSentences` → `quote/progress`, `quote/card-number-field`, `quote/code-input` and `quote/every lead` fail by name; the cut extended past any quote, open or closed → `quote/textarea-count` and `quote/switch-row-count` fail by name.
