## (2026-11-11) — Usage panels keep a quoted example whole (UG-M1, part of #3552)

The usage panel cuts each line to its first sentence or two (`firstSentences`, `apps/plugin/src/doc-panel.ts`). The cut split at a period, a space and a capital, and it did that inside quotation marks too. So a Content › Errors example of two sentences lost its second half and its closing quote. Three panels showed it: Progress (`"Upload failed. The connection dropped.`), Card number field and Code input. This was class N1 of the 2026-11-11 usage-guide scan.

**The fix:** a piece that starts while the previous one has an odd count of `"` is joined to it, so the cut never falls inside an open quote. Only straight quotes are counted, because the defs' prose uses only those. The three lines now end with their quotes closed. Progress's line also keeps its trailing `Not a bare "Error".`, since that sentence follows the closing quote with no period before the space. No other planned line moves across the 37 leads (checked by diffing every lead's plan before and after). The plan hash moves on those three panels, so Update file offers them once, as expected. The docs site and `.ai.json` don't cut, so they were never affected.

**The gate:** a new `quote/…` arm in `apps/plugin/test-doc-panel.ts`. Its three expected lines are typed by hand from each def's `errorPattern`, and a sweep checks that no string in any lead's planned blocks carries an odd count of `"`. Mutation: the guard dropped from `firstSentences` → `quote/progress`, `quote/card-number-field`, `quote/code-input` and `quote/every lead` fail by name.
