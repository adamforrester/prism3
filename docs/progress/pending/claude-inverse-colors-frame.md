## (2026-10-19) — Style guides: Inverse colors is its own group below Semantic colors, never clipped, never overlapping (#2810, #2818)

The owner ran the style-guide command on a real file after #2818. The semantic-tokens page showed three faults. The eight inverse guides sat in a second row inside the owner's own Semantic colors frame. That frame was a horizontal auto layout fixed at 15,160 wide that clips, so the 15,676-wide grid lost its right column (Field / Inverse field). The frame also grew from about 4,700 to 9,175 tall and ran over the owner's Borders and Fonts frames just below it. The owner decided that inverse colors get a parent frame of their own, directly below the defaults, each inverse guide under its default's column. Record: `docs/45-style-guide-generator.md`, "Decided (2026-10-19)".

- **Engine table.** `style-guide-groups.ts` gains Inverse colors (`under: 'semantic-colors'`), and Semantic colors loses `inverseRow`. `styleGuideGroupOf` reads a new `inverse` fact. That fact is structural, an `inverse` path segment, not a family name. Patch note: no emission moves.
- **Plugin.**
  - **The split.** An earlier build's second-row inverse guides move out into Inverse colors, and the grid closes to one row. A one-row or loose hand-made Semantic colors gets a one-row grid of its defaults, once, so the inverse guides have columns to sit under.
  - **Alignment, every run.** Inverse colors goes 320 below that frame, its grid's left edge on the defaults' grid's. The two grids share their gap and each shared column's FIXED width, the wider guide's. Columns are re-derived from the counterparts each run, so they follow a reorder or a close.
  - **Never clipped.** A FIXED frame that holds guides grows to fit, stays FIXED, and never shrinks.
  - **Never overlapping.** A frame the run changed pushes what it runs over, below it, down with everything beneath, keeping order and gaps. A group placed under another counts "below" from that other's bottom edge. A frame beside it, clear to its right before the run, moves right by a width growth instead, keeping its gap, and a group placed under another is never pushed: it follows its anchor, so a rerun moves nothing (review of `4be045f4`).
- **Why the overlap rule is generic.** #2818's push-down moved only frames Prism3 had placed, which is exactly why the owner's hand-made Borders and Fonts were run over. The new rule moves any top-level frame, but only one below a frame that changed this run, so a page nobody touched is never re-laid.
- **Trap for the re-verifier: the shim's auto-layout x.** The test shim now lays out an auto layout's in-flow children's x: left padding, then the widths and spacing before it, start-aligned. The column-alignment checks read every left edge off that model and the grid's track model, never off the plugin's arithmetic (the plugin reads the host's `x` chain). Before this, an auto-layout child's x read whatever was last written, so the alignment checks would have been circular.
- **Decided.** The title is "Inverse colors" (owner decision Q423 A).
- **Held.** What a frame beside a grown frame does is posted as an owner question on the PR; its recommendation, moving it right by the growth with its gap kept, is what is built. Removing the retired legacy Inverse table still waits on the owner's confirm (#2818), and a run does not move it.
