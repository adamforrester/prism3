## (2026-10-25) — Glass: a background-blur effect style bound to a blur token (#2869, Q464 A)

Owner decision Q464 A: a "glass" treatment for text set over the bottom of a photograph, a light veil fill plus a background blur (the source comp: `#f7f7f7` at 69%, 32px). The issue left the naming and the fill/style split to the owner, so this is built as a draft on Q2869.1–5 A (posted on #2869): one token `blur.glass` = 32px, not a ramp and not a lever; the fill a color role `color.glass.surface`; one Effect Style `glass`, blur only.

- **The alpha lives in the value, not on the paint.** The 10/21 evidence on #2869 is that Figma forces a variable-bound color paint to opacity 1 on every instance, so "a surface at 69%" cannot be a bound paint plus an opacity. `color.glass.surface` aliases a `white-alpha` / `black-alpha` step, the way `scrim.default` does: white 70% on the light family, black 70% on the dark, 90% in high contrast. It varies by mode on purpose, which is what separates it from `veil`: glass is a surface that follows the page polarity, so `text.primary` reads on it in every mode.
- **An Effect Style cannot carry a fill**, so the glass in Figma is the `glass` style plus a frame fill bound to `color/glass/surface`. The style's description says so. No paint style is emitted (Q2869.2 A).
- **The binding is by name in the emission, by id in the file.** `shadow-styles.json` carries the glass blur's `boundVariables.radius` as a by-name alias (`<root>/blur/glass`), the same convention as every other emitted binding. Figma cannot read that, so both writers (`write-styles.ts` and the paste path in `materialise-to-figma.ts`) strip it and bind through `setBoundVariableForEffect`. A file without the variable reports a miss and keeps the literal 32px. `blur` is a new FLOAT collection (scope `EFFECT_FLOAT`), written by the FLOAT plan before the styles step.
- **The glass rides in the one Effect Style file** (`shadow-styles.json`), because Figma has one Effect Style list. Tests that assumed "every effect style is a shadow" now name glass as the one exception rather than filtering by prefix.
- **Gates, each mutated red by name** (wip commit first, then the mutation): `test.ts` "glass <brand>: the effect's radius BINDS <root>/blur/glass, not a literal" (the emitter writing a literal radius); "color.glass.surface resolves in every mode … to a translucent primitive" (a dangling alias, and an alias to opaque black); "<root>/blur/glass is a 32 FLOAT …" (the committed Figma value drifting to 31). `check-consumability.mjs` "[#2869] the glass blur reaches CSS as a length" (`blur.glass` retyped to a bare number). `test-write-styles.ts` "glass: its radius is bound to blur/glass by variable id" (the executor skipping `setBoundVariableForEffect`).
- **A trap for whoever re-verifies:** mutating `modes.ts` to a nonexistent alpha step does not turn the `test.ts` glass gate red. `regen.ts` throws on the dangling alias, so the committed artifacts the gate reads never change; `every-example-compiles` and `regen --check` catch that case instead. Mutate the committed artifact to test the gate itself. Also, `tools/exporter-comparison/gate.ts` does not compare a FLOAT variable's value, so a drifted `blur/glass` value passes it; the `test.ts` arm is the one that holds it.
- **Inverse:** `color.glass.surface` has no inverse counterpart, and is registered in `INVERSE_GAPS` as UNDECIDED: a glass band inside an inverse band has not been asked about.
