## (2026-11-12) — emitted order no longer depends on the machine's locale (#3698 finding 2)

**STATUS: PR open, not merged.** ENGINE {{ENGINE_VERSION}} (patch, `packages/engine/changes/claude-3698-locale-order.md`), CONTRACT stands. Files: `packages/engine/locale-free-order.ts` (**NEW**), `packages/engine/lint-locale-order.ts` (**NEW** gate), nine engine sources moved onto the comparator (`emit-icons.ts`, `emit-marks.ts`, `emit-agent-reference.ts`, `component-defs-export.ts`, `rename-map.ts`, `release-notes.ts`, `anatomy-readback.ts`, `lint-paint.ts`, `test.ts`), and the gate's place in `verify.ts`, `ci.yml`, `CONTRIBUTING.md` §3, the PR template and `CLAUDE.md`.

**What was wrong.** A bare `localeCompare` sorts by the host's locale. Under `LC_ALL=cs_CZ.UTF-8`, where `ch` is one letter after `h`, `regen --check` reported drift on 8 artifacts with no code change (reproduced here before the fix). CI runs one locale, so it could not see it.

**The comparator folds case on purpose.** Pure code-unit order (what `emit-analysis-reports.ts` already uses) puts uppercase first, so `FPO-default-icon` would have moved ahead of `arrow-down` and become Icon's default member in Figma. That is a design change, not this fix's. `localeFreeCompare` folds ASCII case with `toLowerCase` (which reads no locale, unlike `toLocaleLowerCase`) and breaks ties by code unit. That reproduces the committed English order exactly: `regen.ts` moved no artifact, and `LC_ALL=cs_CZ.UTF-8 regen.ts --check` now passes at 229. If the owner wants pure code-unit order, it is a one-line change with the Icon default moving as above.

**Trap: `rename-map.ts` restates the comparator.** `planVariableRenames` ships as source in the CLI paste payload (#1024, `plannerSources`), where an imported name compiles to `import_x.name` and does not exist. Importing `localeFreeCompare` there made every paste payload throw (`localeFreeCompare is not defined`), caught by the plugin's `test-rename-parity.ts`. So that one function carries a local copy, with a comment to keep the two identical.

**The gate.** `lint-locale-order.ts` scans every tracked source file under `packages/engine/` (194) for a locale-dependent comparison, an ICU collator or a locale-aware case fold, and fails `LOCALE ORDER` by file and line. Tests and lints are in scope: one rule is simpler to hold than a list of exemptions. `PROBE` runs the comparator on a literal list against a typed order, and checks a Czech collation orders it differently, so the probe could catch the defect. `REPRESENTED` holds the scan to nine named emitters and a floor of 150 files. Mutations, each from a `wip:` commit: `localeCompare` put back in `emit-icons.ts` → `LOCALE ORDER: packages/engine/emit-icons.ts:95`; the comparator made pure code-unit → `PROBE`.

**Not changed.** The plugin, Studio and `tools/` still use `localeCompare` for their own screens and reports (`apps/plugin/src/style-guide.ts`, `doc-panel.ts`, `list-fonts.ts`, `tools/exporter-comparison/*`, others). Filed as #3701. Pinning exact Node and `tsx` versions in CI (the issue's other half of this finding) is an owner-facing change and is not made here.
