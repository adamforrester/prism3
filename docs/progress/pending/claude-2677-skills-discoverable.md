## (2026-10-15) — The four engine skills load in every Claude Code session here (#2677, Q320.2)

**What changed.** `.claude/skills/` now holds one symlink per engine skill (`prism3-theme`, `prism3-consume`, `prism3-rebind`, `prism3-build-component`), each pointing at `skills/<name>`. `skills/` stays the single source and the only thing `lint-skills.ts` reads for claims. `lint-skills.ts` gains check 6, DISCOVERY: every `skills/<name>` must have a `.claude/skills/<name>` that is a symlink resolving to it, and any `.claude/skills/` link that dangles or resolves into `skills/` under another name fails. An entry that resolves elsewhere (a repo-local skill with its own home) passes. `.claude/settings.json` is untouched.

**Why a symlink, and how that was established.** Claude Code finds project skills only at `.claude/skills/<name>/SKILL.md`; the repo-root `skills/` is invisible to it. Its skills docs say a skill entry may be a symlink to a directory elsewhere and that it reads `SKILL.md` from the target. Measured rather than trusted: a scratch repo with `.claude/skills/zz-probe-skill -> ../../skills/zz-probe-skill`, and a fresh `claude -p` session (Claude Code 2.1.300) listed `zz-probe-skill` among its skills. The same check in this worktree listed all four. Unknown frontmatter keys (`documents:`, `omits:`, which `lint-skills` reads) are ignored by Claude Code, per the same docs.

**Approach discarded.** A generated copy under `.claude/skills/` plus a drift gate. It would load identically, but it is two sources kept equal by a gate, and the gate would have to be added to regen's artifact count. A link has nothing to drift. The gate refuses a copy by name ("copy, not a link") so the discarded shape cannot come back quietly.

**Ceiling, stated.** The gate checks the links, not the host. If a future Claude Code stopped following linked skill directories, this stays green and the skills silently stop loading. On a Windows checkout without `core.symlinks`, git writes each link as a text file; the gate fails there, which is correct. Uploading these skills to claude.ai or the Skills API would reject the extra frontmatter keys; nothing does that today.
