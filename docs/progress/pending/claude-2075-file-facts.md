## (2026-11-12) — Plugin: the file facts report, a deterministic scan of a Figma file (#2075 part 1, Q189)

**What changed.** `packages/engine/file-facts.ts` scans one Figma document into a JSON evidence report, `prism3-file-facts/1.0`, with an authored schema at `packages/engine/schema/file-facts.schema.json`. It covers what the owner's Q189 direction lists for part 1: variables (collections, modes, type, per-mode values, alias chains resolved to their end, scopes, descriptions), paint, text, effect and grid styles with their values and the layers using each, the fills, strokes and text colors layers use sorted by role, the type values (families, style names, weights, sizes, line heights), corner radii and auto-layout spacing, the components placed (local and library, with the pages they are on), and the library collections, styles and components the file draws on. Every value is reported with its binding: a variable, a style, or raw. It has no judgement in it: no seed, no confidence, nothing proposed.

**Where it runs.** The scan is a pure function over `FactsSource`, the slice of the plugin API it reads. `apps/plugin/src/file-facts-figma.ts` builds that source from the open file (the global `figma` passes with no cast; `tsconfig.main.json` now compiles the adapter, so a drift between it and the plugin typings is a type error). `sourceFromSnapshot` builds it from plain data, and `packages/engine/file-facts-cli.ts` runs the scan over a snapshot file. The CLI is in `emit-agent-reference.ts`'s `CLI_EXCLUDED`, not its `CLI` list: the snapshot format is a working format for part 2, not yet something to offer agents. Nothing calls the adapter yet: no UI, no start-screen entry and no agent-link command, since where the report surfaces is the owner's call.

**Decisions made inside the arc, each stated in the scanner's header.** A use is one layer, deduplicated per row. Instances' contents are walked and split out as `inInstances`. Hidden layers are skipped and counted. A paint on a layer with a style is the style's even when the style's own paint is bound to a variable. An alias into another collection resolves in that collection's default mode. A square corner is left out unless a variable sets it. A space-between gap is `auto`. The role rule (`name-and-type/1`, carried in every report) is icon (vector shape, or the word icon in a layer's, ancestor's or main component's name), then text, then border (any stroke), then button-like (the word button, btn or cta on the layer or its parent), then background. The report carries no file name, file key or timestamp, so a file scans to the same bytes twice.

**The test.** `apps/plugin/test-file-facts.ts`, in the plugin's `test` script, builds three files with `FileShim` and `NodeShim`: variables, modes and aliases (a two-step chain, a cross-collection alias in a non-default mode, a loop, a missing target, a library variable); styles only (all four kinds, a library style, an unused one); raw values only (a mixed text layer read by its runs, mixed corners, a wrapped space-between layout, a local component set). Every count and binding is written by hand. Each report is validated against the schema, scanned twice for byte equality, and checked for an empty write log. Mutations, each failing by name: alias resolution dropped (`vars/button background light resolves through two aliases` and four more); the cross-collection default mode ignored (`vars/button background dark crosses into primitives' default mode`); style precedence reversed (`vars/a fill style whose paint is bound to a variable is the style's`); the icon word never matching (`raw/a layer named as an icon is an icon`); hidden layers walked (`vars/coverage`); per-layer dedupe dropped (`vars/spacing: one layer, four equal paddings, one use` and eight more).

**Ceiling.** Not run against a live file in this PR: the shims model the calls the scan makes, and the first live scans are part 2's test set. The plugin API does not name the library a remote item came from, only its key, so `libraries` lists keys and names, not library names. Effects and grids applied without a style, and gradient stops bound to variables, are not counted as usage.
