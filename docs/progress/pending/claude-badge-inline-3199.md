## (2026-10-31) — Badge gains an inline status style: a dot and plain text on the text line (#3199)

Badge has a new authoring axis, `style: contained | inline` (owner decisions Q-ST1 A and Q1–Q8 A on #3199). An inline badge is an 8px status dot and the label in body text, with no fill, padding, radius or edge. It is as tall as the line it sits in: 24px at medium and 21px at small. The label is `text.primary` in every tone. The dot is the tone's icon role (neutral `icon.secondary`), bound to `space.100`. `excludeCoordinates` keeps `inline` off the count and dot and off bold and surface, so the set grows from 40 to 50 members. The approved §4 guidance copy ships without its DRAFT markers.

**The diagnosis that shaped the paint.** Inline members sit at `emphasis=subtle`, the one emphasis coordinate left to them. Under the old single grammar `{tone}.{type}.{emphasis}.{slot}`, an inline root would therefore resolve the subtle label's tint and edge. A leading inline template would not fix it either: `paintOf` falls through to the next template for any slot the first leaves unbound, so the root's `fill` and `border` would still reach the subtle keys. So `{style}` joined the one grammar (`{tone}.{type}.{style}.{emphasis}.{slot}`), every contained key gained `contained`, and the inline keys bind only a label and an `indicator`. The dot paints through `indicator` (the radio dot's slot) so it never shares the root's `fill`. The padding, corner, gap and type keys gained the style segment the same way.

**The first line.** The root is now top-aligned, and the dot sits in `dotCell`, one line box tall (`type.body.*.line-box`, fixed), which centers it. This is the checkbox row's #1201 construction, so a wrapping label keeps the dot on its first line. A contained badge holds one child in a box that hugs it, so the alignment change does not move it. `badge.surface` left #1009's centered-row exemptions, since it no longer centers.

**The rename needs no ledger entry.** An update adds a new axis to every existing member at the plan's first value, renaming each in place with its id kept (`update-plan.ts`). Nothing leaves the projection, so `lint-component-renames` asks for no entry, and the ledger has no "add" kind to write. `test-update-apply.ts` holds it on the shim: the 40 old members are renamed in place with their ids and keys, a hand edit survives, and the 10 inline members are built.

**Tests, each mutated to fail by name.** `test.ts` gates the inline label at 4.5:1 and the dot at 3:1 against `background.primary`, `background.secondary`, `foreground.primary` and `foreground.raised` in 5 brands × 4 modes (lowest 14.05:1 and 3.16:1). It also holds the markup contract (the dot aria-hidden with no role or name; the label unhidden, never `role="status"`), the inline projection against the issue's literal geometry, and the six footprint cohorts. A new `test:chrome` section, `3199`, lays each projected inline member out in the browser from its own plan and the committed emission, for the default brand and the reference brand. It checks the box is 24 / 21px on one line, and that at 210px a wrapping label keeps the dot's center on the first line.

**Trap for whoever re-verifies:** the `test:chrome` section's label is longer than the docs' "Out of stock at this location". In the runner's fallback face that phrase is 192px, which fits beside the dot at 210px, so it would not wrap there, though it does in the brands' faces. The section's premise arm proves the wrap before it measures.

**Held for the owner:** the `size` prop's description still reads "medium = 12px text, about 30px tall. small = 11px text, about 19px tall", which is true of the contained style only. Rewording it is copy, so it is not changed here. The `type=dot` size finding (Q8 A) is #3226.
