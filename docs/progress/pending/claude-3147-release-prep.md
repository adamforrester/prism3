## (2026-11-01) — Release prep for the org-private "Prism3 Studio": a strict release build, the approved privacy note, a release record (#3147)

**What landed, by decision.** The owner's release decisions on #3147 (Q3147.15 to Q3147.21, all A), with nothing published:
- **Q3147.16, a strict release build.** `releaseCheck` in `apps/plugin/git-stamp.mjs` refuses a release when the stamp's commit is `-dirty` or `git-unavailable`, when the checkout is behind `origin/main`, or when it cannot tell (no fetch, no count). `build.mjs --release` runs it before anything is written, so a refused release leaves no bundle to import by mistake. The dev build keeps #3239's warning.
- **Q3147.17, the privacy note.** `PRIVACY_NETWORK` is the approved Q3147.7 wording, character for character. The manifest `reasoning` is untouched.
- **Q3147.18, the release record.** `tools/release/prepare.ts --figma-version <N>` checks the checkout and both builds (each bundle's stamp must name this commit). It writes the two zips and a draft release note under the git-ignored `tools/release/out/`, and prints the `git tag`, `git push` and `gh release create --draft` commands. It runs none of them.
- **Q3147.15 and .19 to .21** are documented in `apps/plugin/README.md`'s new release section: keep the id, publish on demand at most once a day after verify, publish Offline too, and publish without `ws://localhost` if Figma refuses it, recording that on #3147.

**Why strict only outside CI.** `verify.ts` sets `CI=1` for every gate and GitHub Actions sets `CI`. In both, the release build is a gate that is never published, and a branch that falls behind `main` while a 40-minute run goes would turn it red for nothing: `main` moved twice during this lane's own verify. So under `CI` the same reasons print as a warning and the build goes on. The owner's hand-run `build:release`, the one the publish steps use, has no `CI` and is always strict. `release/ci-warns` tests that boundary.

**The note needed a layout fix.** The Inspect menu sizes to `max-content`, so the approved 260-character note on one line made the menu 1534 px wide at a 1280 px viewport (measured in Chromium against the real `chrome.css`; the old note gave 529 px). `.p3-menu-privacy` now takes `width: 0; min-width: 100%`, so it wraps within the width the menu's items give it (325 px in the same measure) and never sets that width, whatever its wording. This is a visual change, flagged for the owner.

**Gates.** `test-git-stamp.ts` section 5 drives `releaseCheck` with stubbed answers: `release/clean`, `release/refuses-dirty`, `release/refuses-no-git`, `release/refuses-behind`, `release/refuses-unknown`, `release/every-reason`, `release/ci-warns`. `release/build-refuses` then runs the real `build.mjs --release` with a stand-in `git` (a shell script answering from literals) first on `PATH` and `CI` unset. It must exit 1 with the refusal and leave `release/main.js` untouched. `lint-network-reach.ts` now holds each build's bundle to its own note, against the approved text typed in the gate.

**Mutations, each failing by name.** `releaseCheck` warning only when strict → `release/refuses-dirty`, `-no-git`, `-behind`, `-unknown` and `release/build-refuses`. `PRIVACY_NETWORK` back to the fonts-only line → `release/ui.html shows the approved privacy note (Q3147.7 A)`.
