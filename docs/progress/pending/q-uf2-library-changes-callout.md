## (2026-11-13) — Update file names the changes it passes on to files that use the library before the run (#3711, Q-UF2 A)

**The defect.** The owner had not noticed, before the run, that the update would pass two changes on to files that use the library. The checklist showed one line under the set (`breaks`), among the other rows, and the Update button read the same as always, so the click acknowledged nothing.

**The fix.** The host's checked set (`checkedSetOf`, `apps/plugin/src/update-plan.ts`) now carries `changes`: each change named (`consumerLines`, the check's section's own lines for the set, capped at 8 then a count of the rest) and how many in all. The panel reads it (`write-adapter.ts`: a count above 0 and every line a string, or nothing). `libraryChangesOf` (`state/update-file.ts`) sums them over the sets the update step runs (`updateDefsOf`), so a set unticked or blocked adds nothing. When there are any, Update file draws a callout as the body's last item, directly above the button: "Files that use this library", "n changes in this update reach them at the next library publish:", then each change. The button reads "Update, including n library changes", so the click is the acknowledgement. All DRAFT. A file that is not set up keeps "Set up and update": it holds no published set.

**Stacked on Q-UF1 (#3748).** The callout's lines are Q-UF1's wording, so this branch builds on it; its diff shows both until #3748 merges.
