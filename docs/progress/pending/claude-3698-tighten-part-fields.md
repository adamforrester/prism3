## (2026-11-15) — the documented-kind part fields are refused off their kinds (#3698 Q-PU1 A, #3779)

**STATUS: PR open, not merged.** ENGINE {{ENGINE_VERSION}} (minor, `packages/engine/changes/claude-3698-tighten-part-fields.md`: new run-time refusals for def authors), CONTRACT stands. Files: `packages/engine/component-schema.ts` (the per-kind key lists, the validator's `KIND_ONLY` table, the #3779 refusal, the field docs), `packages/engine/lint-part-union.ts` (26 new illegal probes), `packages/engine/test.ts` (the refusal tests), `skills/prism3-build-component/SKILL.md`.

**What changed.** #3780 left eight fields in `PartBaseKey`, admitted on every kind, because the validator refused none of them by kind. The owner chose to tighten the ones a doc comment ties to some kinds (Q-PU1 A). Four of the five fields asked for now hold on both layers. `radius` and `children` are box-only. `replaces` and `overlaysWhenAbsent` are overlay-only. `when` is for an overlay or an absolute. `role`, `optional` and `note` stay open, and so does `type`; the next paragraph says why. On the type side, each field moved from `PartBaseKey` into the key lists of the kinds that take it. On the run-time side, one table (`KIND_ONLY`) refuses each field on every other kind, naming the part, its kind and the field. `children` was already refused on absolute, nest and vector, each with its own message, so the table asks only text, slot and overlay. Also #3779: a root's `builtSize.grow` must name a `box` or a `nest`, because `builtSizeAt` writes `grow: true` onto the part it names, and `grow` is a box and nest field.

**`type` is held, not tightened.** The brief said to stop on any field a projection reads on another kind, and `type` is one. `figmaAnatomyPlan` reads it on every kind, at `anatomy-figma.ts:2066`, with no kind guard. On a non-text part that puts a `textStyle` on the FRAME or instance plan node. `planTextStyles` then asks for that style, `component-specs.ts` lists a typography row for the part, and both executors try to apply it to a node that holds no text. The paste payload calls `node.setTextStyleIdAsync` without a guard, so it would throw there. No shipped def sets `type` off a text part, so tightening it would change no output. The owner decides on the PR.

**How the `children` set was derived.** The projector builds plan children for any kind (`anatomy-figma.ts`, the `childNames` map in `node()`), and both executors append children under any node. So the set is the kinds whose node can hold children. A `box` becomes a FRAME or a CONTENT_SLOT frame, which takes appends. A `text` becomes a TEXT node, which has no children: the paste payload's `node.appendChild` would throw, and the plugin's `appendChild?.()` silently leaves the child loose. A `slot` or `overlay` becomes an INSTANCE_SWAP, built as an instance of its target, which Figma refuses an append into. Only on a missing target is it a placeholder frame, and that path is already a reported miss. The other surfaces (docs, `.ai.json`, specs, the def export, Code Connect) all read the plan, so they add no reader of their own. That leaves `box`, and it matches shipped usage: children appear on 152 box parts and nowhere else.

**Proof.** `regen --check` is in sync (230 artifacts), and the three uncommitted exports are byte-identical on main and the head. `lint-part-union` probes the five fields on every kind that refuses them (50/50 illegal probes refused by name, up from 24). Each field was then re-admitted at the type (added to one wrong kind's key list) and at the validator (its `KIND_ONLY` row deleted). Every mutation failed by name, as did disabling the #3779 refusal. The commands and output are on the PR.

**Trap.** The probe values in `test.ts` don't need to be valid. `children: ['probeChild']` also raises "not a declared part", and `radius` on a glyph also raises a missing token key. The test reads for the error that names the part, its kind and the field, so an unrelated error on the same part can't pass it.
