## (2026-11-11) — lint-skills reads the per-version release notes as dated history, so a fold can carry a renamed skill's old name

**The conflict.** Two landed PRs met for the first time in the 0.238.0 fold. #2650 made the fold write release notes under `docs/public/releases/`, carrying each folded change note verbatim under "In detail", and `lint-release-notes.ts` forbids editing them by hand. #3412 (PR #3430) added `lint-skills.ts` check 9, which fails any line naming the retired skill `prism3-consume` outside the dated history: the log, the changelog, their pending entries and `docs/superpowers/`. A change note written before the rename (the link-over-media note) names the old skill, so `0.238.0.md` and `.json` failed check 9, and the notes could not be edited to pass it.

**The fix.** `docs/public/releases/` joins check 9's `HISTORY` list. The release notes are the same change-note prose as `CHANGELOG.md`, which was already exempt, published per version. Every other `docs/public/` page is still read. Two self-check arms pin that boundary: a release-notes page with the old name gives no finding, and `docs/public/llms.txt` with the old name gives one.

**Mutations, each failing by name:** removing the new `HISTORY` entry fails with `a release-notes page gave 1 finding(s), expected 0`, and widening it to `docs/public/` fails with `another public page gave 0 finding(s), expected 1`. No engine behavior moved, so there is no change note.
