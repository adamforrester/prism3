## (2026-10-23) — CI caches Chromium's system packages, so a slow mirror no longer fails the browser install (#2951)

The browser came from the cache since #2323, but `--with-deps` still downloaded about 26 MB of system packages (mostly CJK and Thai fonts) from Ubuntu's mirror on every run. On 2026-10-22 the mirror was slow, not stalled: `fonts-wqy-zenhei` took about 3 minutes, so no apt timeout from #2348 fired, and all three 240 s attempts ran out. The logs also show each attempt kept the packages the one before had finished downloading ("Need to get 14.8 MB/25.9 MB", then 11.8 MB). The archive directory already worked as a cache within a job. It just did not survive the job.

So `install-chromium.sh` points apt's archive directory at `~/.cache/prism3-apt`, which the runner user owns, and each of the four browser jobs caches the `.deb` files there with `actions/cache`. The key is the runner image (`ImageOS` + `ImageVersion`) plus the Playwright version, which together decide which packages `--with-deps` needs. `restore-keys` lets a new image start from the previous image's packages and save its own. On a hit, apt reads the index from the mirror and installs from disk. The script logs how many `.deb` files it found, so a run's log shows whether the cache hit.

Unchanged on purpose: the 240 s bound, the three attempts, the 15-minute step limit and the named failure. A cache miss runs the install exactly as before, so it is never a skip (#2323's rule). apt downloads as root here (`APT::Sandbox::User "root"`), because `_apt` cannot reach a directory under the runner's home. That is acceptable on a disposable runner.

**Gap.** A cold cache on a slow mirror can still fail: a new Playwright version with no earlier entry, or a cache that has been evicted. Once any job succeeds, every later run restores its packages. `test-install-chromium.sh` gains `config/archives` and `config/no archive`. Its four `stall/…` cases fail in a container whose PID 1 does not reap orphans, on `main` too: the stopped stand-in stays a zombie that still answers `kill -0`. GitHub's runners do reap orphans.
