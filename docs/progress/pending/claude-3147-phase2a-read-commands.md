## (2026-11-01) — Agent link: four read-only node commands, so the master needs one plugin (#3147 Phase 2a)

**What landed.** `inspect`, `component-keys`, `audit-frames` and `snapshot`, with the args and results drafted in the Phase 2 proposal on #3147 and approved as drafted (Q3147.10 A, Q3147.14 A). The Mac mini's queue showed that in the master an agent only reads: component keys, instance properties, variable bindings. These four answer those reads, so the master can run Prism3 alone. They live in `apps/plugin/src/agent-reads.ts`, are routed in `agent-dispatch.ts` and validated in `parseCommand`, and need nothing transport-specific: the mailbox and the bridge both carry them. `commands.json` is regenerated, and the ecosystem map, the agent-link guide, the plugin README, the bridge README and the mailbox runbook list them.

**Write nothing, proven by a log rather than by reading the code.** `file-shim.ts` gains `NodeShim`: a page tree behind Proxies that log every assignment, `defineProperty`, `delete`, and every call to a method outside a short read list. Each command runs over both transports against it (`test-agent-link.ts` through the real `main.ts` and the mailbox, `test-agent-bridge.ts` through the real server, socket and relay), and the `no-write/<cmd>` arm requires the log to stay empty, no root plugin data to move outside the mailbox's own keys, and no `ACTIONS` handler to run. The one exception is stated: the bridge suite skips `prism3agent/link`, the link record the agent link rewrites after every command whatever it is. The FileShim did not model nodes, so the node model is a new class beside it rather than a second variables model.

**Expectations are literals.** `agent-read-fixture.ts` holds the fixture file and each command's `result.data`, typed by hand, shared by both suites so the transports are held to one answer. The PNG's base64 is Node's encoder, not the plugin's hand-written one. Arms beyond the envelope: `inspect/unreadable` (a layer that throws on read is listed and its sibling still read), `inspect/cap`, `keys/fixture` (a name list and `missing`), `audit/each-count/<count>` (one planted defect per frame counts exactly one), `audit/clean`, `audit/legacy-lists`, `snapshot/scale`, and six `refuse/<case>` arms.

**Calls made inside the draft, for the owner to correct.** The draft named `inspect`'s `fields` values without saying what each adds. Here, absent means all five, and each adds one key: `props` → `componentProperties`, `bindings` → `boundVariables`, `styles` → `textStyle`, `layout` → `layout`, `text` → `characters`. Each entry also carries `parentId`, so a flat depth-first list can be put back into a tree. `component-keys`' `sets: true` lists each set's `members`. `audit-frames` does not walk inside instances (their layers are the component's), and with no `nameRule` it counts frames still carrying a Figma default name. A snapshot of a node that is not in the file fails `bad-args`, through a `ReadRefusal` the dispatcher maps to that code instead of `handler-threw`.

**Not in this PR.** The write-command guard (protected-node defaults, Q3147.11; version first, Q3147.12) is Phase 2b's first step in the proposal's order, so it waits for 2b. `run-code` stays dev-only (Q3147.13 A).

**Mutations, each failing by name.** `readOne` assigning `n.name = n.name` → `no-write/inspect` on both transports. `locked` dropped from `readOne`'s entry → `envelope/inspect` on both transports.
