## (2026-10-19) — Update on a published set lists what breaks library consumers; slot items stay unprefixed (#2831, Q394)

Items 1 and 2 of #2831. Item 3, the library publish description, waits for #2828's version naming.

- **The publish status is read, and it decides everything.** The Update check reads `getPublishStatusAsync()` on each set (`UNPUBLISHED | CURRENT | CHANGED`). A single-component def reads as its most published component. A set that is not published gets no `publish` field and no breaking list, so its preview and its hash are byte-for-byte what they were. That is the "nothing changes for unpublished sets" arm. A published set carries `publish` inside its hashed body, so publishing a set between the check and the confirm refuses the confirm.
- **What counts as breaking (`breakingOf`, pure, over what the dry run already lists):** a component property removed or retyped, a dropped member, a layer replaced rather than updated in place, and a set rename to a `_` or `.` name. A set the check blocks lists nothing, because the update changes nothing there. A replacement of the member itself is also left out, because the update refuses that member.
- **Where it shows.** A "Breaks library consumers" section in the check's lines, a clause on the check's headline (`· N changes break library consumers`), and the same section and clause in the confirm's verdict. The confirm takes the list from the check it applied. Each set's list is capped at `DIFFERENCE_LINES`, as its differences are, with the rest counted. The data payload carries every entry. All the wording is DRAFT and is posted to the owner on the PR.
- **A drop is not a delete.** The update keeps a dropped member and marks it deprecated (Q2), so a consumer instance keeps working. The line says what the consumer gets: an instance pointing at a deprecated member. Whether that counts as breaking is the owner's call. It is built as the issue asks, and the question is on the PR.
- **The rename arm reads `setRename`, which #2769 sets.** Nothing on main renames a set, so the field is declared here in #2769's exact shape and wording, and `breakingOf` reads it. When #2769 lands, its rename feeds the arm with no further change, because `breaking` is computed after every set's preview is complete. The test drives the arm by setting `setRename` on a real dry run read through the shim.
- **The shim models publishing.** `component-shim.ts` gives every COMPONENT and COMPONENT_SET a non-enumerable `getPublishStatusAsync` that answers `UNPUBLISHED` until a test calls `publish(node, status)`. That is the host's answer for a file never published, so every existing suite reads unpublished and is unchanged. The brief said "file shim", but `file-shim.ts` models variables and styles only. Nodes live in `component-shim.ts`.
- **Q394 on main, without `lint-naming`.** #2763 has not landed. `slotPreferredOf` already refuses a `_` id in a slot's `preferred` list at projection (`#2646 projection: a building block`). The gap is the sweep's own failure mode: a slot item renamed to `_…` with its slot's `preferred` dropped or renamed with it. `test.ts` now reads every native slot in the registry (`preferred`, `preferredWhenBuilt`, and what its default items nest) and refuses a `_` or `.` id by name. It asserts the three items the sweep renames are among those read. When `lint-naming` lands, this arm can move there.
- **Mutations, each failing by name.** In `test-update-apply.ts`: the publish test always true → `published/unpublished no-op`; each `breakingOf` arm dropped → `published/drop`, `/replace`, `/property removed`, `/retype`, `/private rename`; the status not read → `published/status`; the status left out of the hash → `published/hash`; the apply's section dropped → `published/confirm`. In `test.ts`: the prefix test dropped → `Q394 slot items: a prefixed item is refused`; the nests arm dropped → `Q394 slot items: a prefixed item the slot's default items nest is refused`.
