## (2026-11-02) — Agent link: a read-only `activity` command, so an agent can read what Activity shows (#3309)

**What landed.** `activity { since?, limit? }` returns the Activity drawer's runs this session, newest first: `seq`, `op`, `by` (panel or agent) and `cmd`, `at`, `verdict { type, ok }`, `headline`, `summary`, `lines`, `problems: [{ set, reasons }]`, and `built { commit, build }`. It answers over the mailbox and the bridge, posts no verdict and writes nothing. `commands.json` is regenerated; the ecosystem map (a `read-activity` feature), the agent-link guide, the plugin README, the bridge README and the mailbox runbook list it.

**Where the runs come from.** The drawer lives in the panel; an agent command runs in the main thread. Everything the drawer shows passes through the main thread, so it keeps the copy (`apps/plugin/src/activity-log.ts`, memory only, 50 runs): each verdict as `uiSink` posts it (the panel's) or as the dispatcher's `forward` does (an agent's, named by the command running), and the two results only the panel computes, a multi-set build's `runVerdict` and Update file's strip verdict, which the panel now posts as `activity-note` (`HostCommit.noteActivity`; inert on the web). The update's note carries each step's verdict as a line, so "Stopped at To add" comes with the step that stopped it.

**Per-set problems.** `buildComponents` attaches them to its run after it posts the verdict: one entry per set not clean, with the reasons by the rule its `ok` reads (misses that are not `ALREADY PRESENT` or `STALE` members, the stale note, and each furniture outcome with a missing template), capped at 20 reasons plus a count. A dependency built first with misses is listed by its count.

**Tests.** `test-agent-link.ts` and `test-agent-bridge.ts` gain the `activity` arm in their read loops (`mailbox|bridge/activity`, `envelope/activity`, `no-write/activity`) against literals in `agent-read-fixture.ts` (two panel notes posted as the panel posts them; `at` checked as ISO 8601, the rest compared whole), plus `refuse/activity/limit` and `refuse/activity/since`. `test-build-completed.ts` reads the panel's own Badge build over the bridge: `activity/run`, `activity/problems` (the missing-template line, literal, as Badge's one reason) and `activity/no-write`.

**Mutations, each failing by name.** `cmd` dropped from the log's run → `envelope/activity` on both transports. `annotate` never called from `buildComponents` → `activity/problems`.
