## (2026-10-28) — Glass fills: a typed name, the shipped glass's row, and a picker that keeps its pick (#3106, Q827 A)

The owner's review of #3088's Glass section in the plugin (#3106) found four layout bugs and settled how a glass fill is named (Q827 A). Studio only: the engine, its validation and the emission are unchanged.

- **Q827 A, the name.** Add glass fill no longer names the fill (`card`, then `card-2`). It opens a Name field that starts empty, with the hint "e.g. card, header, overlay" (DRAFT), and previews the token, `color.glass.<name>`, as it is typed. `glassNameRefusal` (`state/glass-input.ts`) refuses an empty name, a name that isn't a lowercase slug (the engine's own `GLASS_ROLE_NAME`), `surface`, and a name the brand already has, each in its own line (every line a DRAFT). The check runs as the designer types and is drawn in place, so typing never redraws the page. Enter or Add adds the fill, and Escape or Cancel closes the field and writes nothing. Stored names keep working: the reference brand's `card` loads and renders unchanged.
- **The row.** An added fill is drawn as the Glass surface row: its swatch, then "Glass card" over `glass.card` through the shared `tokenLabel`, in the same type and on the same left edge. The remove button is a small square icon button on that line, as a gradient's is. Color and opacity sit on a line under the name. The old row put five children in `.p3-fillrow`'s three-column grid. The opacity field wrapped into the swatch column, which was the "empty swatch", and × stretched across the name column. The name was a `p3-hex-input`, which is uppercase. The row now has its own grid, so a snug pane keeps the remove button beside the name.
- **Diagnosis: the picker reading "Page color".** A plain pick reads back correctly on both hosts and after a reload, so the cause was timing. The name field committed a task after its `change` (`onCommitted`, #2487). A click on the color picker blurred the field, and the rename redrew the row while the menu was open. The pick then landed on the replaced `<select>`, whose handler still named the old fill, so `setGlassSource` found nothing and wrote nothing. The picker read the stored "Page color" though Card color had been chosen. Reproduced in the browser before the fix. The row has no rename field now, so this cannot recur. Renaming a fill is remove and add again; an in-row rename is left to the owner.
- **Gates.** `test-glass-input.ts` (new, in the studio `test` script) holds 17 typed names to literal verdicts and lines, checks that the engine's `brandTheme` agrees with every slug and `surface` verdict, covers Add's writes (nothing for a refused or empty name, no auto-name, order kept), and reads the reference brand's `card` from its design.md. `test:chrome` section 18 (shard 1, no new section) adds an arm for each of the five points. The picker arm includes a pick made on a select that the opacity commit has just replaced, and a figma-host restore of a file whose input holds `glassRoles.card`.
- **Mutations** (each on a `wip:` commit, each failing its arm by name): remove moved to the controls line → (1); the opacity field beside the swatch, and the controls line under the swatch → (2); the name in capitals → (3); a pick on a replaced select dropped, and the picker showing the wrong option → (4); no duplicate, `surface`, slug or empty check → the unit cases by name; auto-naming back, no token preview, and the duplicate refusal not drawn → (5).
- **Trap.** `test:chrome` reads the built bundles, so rebuild the studio and the plugin before a re-run. A mutation that moves `pf` above its `const` dies in the temporal dead zone and reads as a different failure.
