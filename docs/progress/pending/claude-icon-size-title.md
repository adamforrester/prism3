## (2026-10-15) — Style guides: the icon-size table is titled "Icon size" (#2728, owner decision Q341 A)

**What moved.** `planVariableTables` in `apps/plugin/src/style-guide.ts` titles a dimension table whose rows are all icon sizes (`varKind` → `iconSize`) "Icon size". Before this, a semantic dimension table took its collection's name, so the `icon` collection's table read "Icon", the same title as the icon color family's table on `↳ Semantic tokens`. The tables filter matches by title, so a filter for "Icon" drew both.

**Why the kind and not the collection name.** The rows' kind is what the table holds. A rule keyed on a collection named `icon` would miss a file that names it otherwise. A rule that renamed any dimension title that matched a color title would have to invent a noun for each case, and that is a naming call for the owner (filed as #2729). The rule also covers a primitive icon-size table, which was titled from its last shared segment ("Size") and would have collided with the size table's title.

**The key does not move.** It is still `dimension|<collection id>|<prefix>`. A rerun finds the earlier table by key and retitles it through the existing path: the frame name, the header title and the title record change only while they read what the generator last wrote. The table is not superseded, so #2704's delete path never sees it. §35e of `test-style-guide.ts` plants a table as an earlier build left it ("Icon" in all three places) and checks that the rerun keeps the same frame, retitles it, and deletes nothing.

**Collision audit.** Every brand emits the same Figma collections (one adds a layout mode). On `↳ Semantic tokens` the color tables are titled by family: Background, Foreground, Text, Icon, Interactive, Disabled, Border, Scrim, Veil, Field, Inverse. A semantic dimension table is titled by its collection: `space`, `radius`, `size`, `icon` and `control` give Space, Radius, Size, Icon and Control. The other tables there are titled by type (Border width, Font weight roles, Text styles). "Icon" was the only repeat. §35e plans phase 2's file, the icon collection and the color collections together and checks that every Semantic tokens title is unique. The mechanism stays general: a foreign file with a dimension collection named like a color family (`border`, `text`) would still repeat a title. Fixing that needs a noun for each case, so it is filed as #2729 rather than fixed here.
