# Concept v4: build spec

This is the brief for the v4 mockup: Concept C revised with the owner's decisions (`decisions-2026-09-30.md`) and the fixes from `phase1-audit.md`.

- **The deliverable:** `concept-v4.html` (self-contained) and its note `concept-v4.md`.
- **What it is:** a design direction for owner review, **not** product code.
- **Where this spec is silent:** keep Concept C's choices.

## 1. Ground rules

- **Offline:**
  - no `<link>` to any host, no web fonts, no network;
  - chrome uses the system stack (`system-ui, -apple-system, "Segoe UI", sans-serif`);
  - brand specimen faces are named by family with a system fallback, and a face that isn't installed shows an explicit **"Not installed: showing fallback"** marker (the real product's state, brief §8.3).
- **Real data, not invented:**
  - **Levers:** the 49 from `packages/engine/schema/lever-manifest.json` (keys, labels, options, option labels, ranges, steps, named stops, `advanced`), embedded at build time.
  - **Components:** the 26 defs from `packages/engine/components/index.ts`, with their real variant counts and what they nest.
  - **Example brands:** `prism3` (the default), `aurora` and `harbor`, from `packages/engine/schema/example-brands.json`.
  - **Resolved values:** roles, ramps, contrast, type sizes, size heights (28/36/44/56/68) and the decisions log (`theme.notes`), from running the engine.
  - **Versions:** engine and contract, read from `packages/engine/version.ts` at build time.
- **Engine: the preferred route.**
  - Bundle the real engine (`@prism3/engine`, pure TypeScript) into the mockup with esbuild, so levers actually re-resolve the system live.
  - Use `npx -y esbuild@0.24.0`, which does not touch `node_modules`. **Never** run `npm install` in a shared tree.
- **Engine: the fallback.**
  - Precompute a data snapshot per brand × mode with a committed script in this folder (`build-v4.mjs` or `.ts`) and embed it.
  - Lever edits then change only the preview elements they obviously drive, and the note must say so.
- **Reproducible:** `concept-v4.html` is generated by a committed build script in this folder from a hand-written source (for example `concept-v4.src.html` plus a data step). Say the command in the note.
- **Light chrome only** (brief §8.3).
- **Coverage self-check against the manifest, not the mockup's own list.** The build script fails if any manifest key has zero or more than one home. It prints the per-domain count.

## 2. Harness bar (prototype-only, as in Concept C)

- **Host:** Studio / Plugin.
- **Frame:** Fill / 1280×900 / 380×420.
- **State shortcuts:** first run; an Apply running; a Build with errors; an agent working; a refused edit.

These let the owner see every state without clicking through.

## 3. Layout (wide)

- **Top bar**, left to right:
  - **brand select ▾** (opens the brand menu: switch brand, start a new one, rename);
  - **verdict** (see §6);
  - spacer;
  - **Export**;
  - **Figma ▾** (plugin only; see §7);
  - **Apply Theme** (plugin only, primary, solid).
- **Levers panel** (left, default 2/5, draggable 28–62%, remembered):
  - domain tabs **Brand · Color · Type · Shape · Depth & motion · Layout · Components**, which scroll horizontally with a visible cue when they overflow;
  - a search box;
  - each domain page runs Foundations → Decisions → Results;
  - advanced settings sit behind one "Show N advanced" disclosure at the end of each domain (Q4), except Layout, which shows everything.
- **Preview pane** (center/right). Its header holds:
  - the **view select**: Style guide, Palettes, Roles, Type, Size & shape, Elevation, Motion, Layout, Components, Tokens, **Contrast**, **Decisions log**;
  - the **mode control** (§5);
  - **Compare**;
  - the **Keep this view** pin.
- **Activity drawer** (§8): docked at the bottom of the preview pane. Collapsed, it is a 32px bar, or hidden when there has never been an operation. It opens on any operation.

## 4. Levers panel

Controls follow the table in `phase1-audit.md` §1.3 **exactly** (control type, home, labels, steps, stops). The key rules:

- **Chips (#1675):**
  - a native radio group (`fieldset`/`legend`) styled as pills;
  - selected is a soft fill **and** an ink border **and** a check glyph, never color alone;
  - focus is a distinct 2px offset ring in the chrome accent, **visibly different from selected**;
  - chips wrap when narrow.
- **Chip or select:** chips for 2–4 short options, or wherever a slider's step leaves ≤4 values (`disabledMin` → 3 / 3.5 / 4 / 4.5:1). Selects for 5+ options, palette lists, and anything whose default is **"Auto: ‹resolved value›"**.
- **Auto always names its value.** That includes the status colors ("Auto: synthesized red, 27°").
- **Sliders:**
  - use the manifest step;
  - named stops are marked on the track;
  - the readout shows the value and the stop name;
  - preview while dragging, commit on release.
- **Descriptions** move behind an **"i"**:
  - a real `<button>` at least 24×24, named "About ‹lever label›";
  - opens a click or tap toggletip containing the manifest description;
  - closes on Esc and on outside click;
  - does not trap focus;
  - never the only place a number lives.
- **Inline state lines stay visible** for the five "+i" rows in audit §1.3:
  - the link-palette underline warning;
  - the density heights-only sentence (inside the Per mode disclosure);
  - the reason 16px is refused under compact;
  - the 8px size-floor warning;
  - the Full disabled caveat.
- **Italics (Q6):** per category, 3 chips: *Upright* / *Upright + italic* / *Italic only*. This replaces separate italics and italicDefault controls.
- **`typography.responsive` (Q5):** in Type › Scale, as a toggle plus min and max viewport fields, with a "Depends on Layout: breakpoints" link.
- **`root` (Q9):** in Brand › Advanced. Editing it shows an inline warning, "Renames every token path: `prism.color…` becomes `‹new›.color…`. Consumers referencing the old names stop resolving.", and needs an explicit "Rename namespace" confirm.
- **Button settings:** Components › Button has all four button levers, including `buttonLabelWeight`.
- **Density:** Shape › Density links from Components ("Density sets component heights and spacing").
- **Destructive lever changes preview what they drop, then confirm with the outcome named:**
  - gradients off ("Remove 2 custom gradients");
  - turning a mode off ("Turn off dark: drops 3 overrides");
  - removing a brand color ("Remove azure: 14 references return to Auto").
- **Refused edits:** a banner names the rule, the refused field is marked, and the preview keeps showing the last good theme.

## 5. Modes: model B (Q1)

- **The mode control lives in the preview header:**
  - a segmented control listing the brand's on modes in fixed order;
  - derived modes hatched;
  - each segment carries a tiny contrast dot (fail count);
  - at <760px preview width it becomes a select.
- **It changes only what the preview shows. It edits nothing.**
- **Compare:** splits the preview into two columns (current mode plus a second-mode select). At narrow sizes it is disabled, with the reason given.
- **Levers always edit the base value.** Per-mode levers show a **"Per mode"** disclosure under the control:
  - **Scope:** `radiusScale`, `density`, `motionPersonality.tempo`, `typography.families`, `typography.weightRoles`, `shadow.softness`, `shadow.tint`, and `surfaces`.
  - **Surfaces:** light and dark rows only; say why ("Surfaces are set for light and dark only.").
  - **Collapsed:** "Per mode · follows base", or "Per mode · 1 override".
  - **Expanded:** one row per on mode other than light.
    - **Customizable modes** (dark, custom): the same control type, compact, defaulting to "Auto: follows light (‹value›)", with a reset link when overridden.
    - **Derived modes** (hc-light, hc-dark, wireframe): read-only, "Follows dark. No settings of its own." plus that mode's contrast verdict.
  - **Density's disclosure** carries the decided sentence verbatim: "Spacing follows the brand's density, not the mode's: a mode's density changes control heights only."
  - **`typography.typeScale`** carries "All modes, never per mode" in its "i".
- **Color › Roles** is a **role × mode matrix**:
  - rows are roles grouped by family;
  - columns are modes;
  - derived columns are hatched and read-only;
  - the preview's current mode column is highlighted.
  - **Each cell** shows the palette step, the ratio and its state (Auto / override / derived / anchored).
  - **Clicking a customizable cell** opens the step picker, with contrast marks shown **before** choosing.
  - **Below about 700px panel width** the matrix becomes a one-mode list with a mode select.
- **Interactive columns:** the per-column anchor step (`modeAnchors`) appears in the same Per mode pattern.
- **Modes on/off and custom modes** (name + base) live in Brand › Modes. "Light is always generated: it's the base mode." hc-dark follows dark.

## 6. Verdict and Health (Q8, Q10)

- **The top-bar verdict** is a button, "All 384 pairs at or above floor" or "3 of 384 below floor, 2 modes". It uses real counts from the engine.
- **Clicking it opens Health**, a popover with:
  - the contrast summary, linking to the **Contrast** view;
  - a **Warnings** list: the disabled caveat, link distinctness, weight roles crossing, mobile merges, unavailable fonts, a stale font-cut pin, heading scale vs pinned sizes, and **type styles this brand doesn't emit (#1802)**;
  - **Build identity**: the engine version and the plugin build stamp, compared, with a "Plugin build is older than engine ‹v›" state.
- **Contrast view** (preview pane): a pairs × modes table with ratios, floors, "large text 3:1" / "non-text 3:1" tags and a filter to failures. Clicking a failing cell jumps to the lever or role that drives it.
- **Decisions log view:** the engine's `theme.notes`, grouped by domain, each linking to the lever it explains.
- **Type view** also lists the #1802 unresolved styles, in the scale table's context.

## 7. Figma menu and the plugin actions

- **The Figma ▾ menu** holds: Build set…, Set up file, Style guide…, Prune stale…, Read-back.
- **Apply Theme** stays a separate primary button.
- **While any write runs:** every write action is disabled with the reason ("Writes run one at a time.").
- **Every action reports into the Activity drawer**, and none navigates away from the current domain.
- **Build set…** opens its picker in the drawer:
  - the real 26 defs, with variant count, nesting, and each set's last result from the file;
  - dependencies are listed and built first, each on its own line;
  - the page-switch notice: "Build set switches Figma to the set's page."
- **Style guide…** opens its options in the drawer (Q11), marked **"Pending #1784/#1788"**:
  - tables filter, collections and types;
  - value format;
  - header dark / light;
  - alias chips on / off, descriptions on / off;
  - color specimen;
  - dimension specimen: filled bar / bracket, one per run;
  - font specimen;
  - paragraph spacing and text decoration columns;
  - Name column, where edits are kept across reruns;
  - REM column, always added to px. **No Pixels toggle.**
  - It runs one at a time, and says it yields to Figma so the file stays usable.
- **Set up file:** the result lists the pages created, the `_Section-header` headers placed, and the `_style-guide-*` cell components built.
- **Read-back:** reports theme present or absent, whether the contract holds, and the declared vs planned mode comparison (#1704). Its outcomes are the three settled states (#721): restored exactly / Prism3 variables but no recoverable input / not a Prism3 file.
- **Prune stale:** preview (the four categories with names), then a confirm dialog titled with the outcome, "Delete 16 items". It recomputes from a fresh read.

## 8. Activity drawer (§7.1, Q2)

- **One row per operation:** Apply Theme, Build set, Set up file, Style guide, Prune stale, Read-back, plus agent commands.
  - Each row shows the last result as a verdict and the time.
  - Each expands to the detail.
  - **A failure opens automatically.**
- **Progress while it runs:**
  - the phase: Build shows *Building members x of N*, *Wiring references x of N*, *Retrying property links x of N*;
  - a bar;
  - dependencies as their own lines above;
  - Apply, Set up, Style guide ("Drawing table N of M") and Prune each show their own phases.
- **Final status, readable:** built, **skipped as already present**, stale and missing, each as a count with the detail one step away.
- **Errors grouped by cause, each with its fix**, covering all ten causes in brief §7.1:

  | Cause | Fix shown |
  |---|---|
  | Variables missing | **Apply Theme first** (button) |
  | Property links didn't take | **Build again** (button) |
  | Layer not found / link not kept | Report only; say a rebuild does not fix it |
  | Stale members | **Delete stale members and rebuild…**. This previews first, because it deletes. Or **Build into a fresh page** |
  | Pre-flight conflict | Name each item; "Rename or remove it in Figma, then apply again" |
  | Fonts unavailable | Name the faces; **Choose another face** (jumps to Type › Faces) |
  | Orphaned / stranded after Apply | **Prune stale…** (opens its preview) |
  | Declared mode missing | **Apply again** |
  | Plugin build older than engine | "Rebuild the plugin" (text; nothing to click) |
  | Figma window in the background | "Keep the Figma window in front: background builds run 20–300× slower." |

- **History:** each operation keeps its previous results, and a set's last build report is readable even in a new session.
- **Agent-started work** shows exactly like yours, with an **Agent** tag.
  - Agent commands **queue behind an in-flight panel write** and show as "Queued".
  - An agent's prune preview is a passive notice, never the confirm dialog.
- **The Agent link switch lives in the drawer header:**
  - "Off at every launch. Only you can turn it on.";
  - the transport ("file mailbox", "desktop bridge");
  - the last command.
- **Safe actions:** any fix that deletes previews first. Nothing irreversible runs from one click.

## 9. Preview views (fixes from audit §1.4)

- **Style guide:**
  - specimens in the brand's tokens: backgrounds, foregrounds, text, borders, icons, disabled, interactive;
  - a **surface switch**: page / second tier / inverse;
  - neutral sample copy, with no idioms;
  - clicking a specimen names its role and offers "Edit role".
- **Palettes:** every ramp with step keys **and visible hex**, the anchor marked, and alpha ramps and opacity steps on a checkerboard.
- **Roles:** a read-only view of the §5 matrix.
- **Type:**
  - the face library with availability ("In this Figma" / "On this device" / "Not installed");
  - the size, line-height and tracking ladders;
  - the weights each face ships;
  - the ramp across modes;
  - real `clamp()` values;
  - mobile merges;
  - #1802.
- **Size & shape:**
  - the radius ramp with the components that use each step (real defs);
  - the four control-shape silhouettes;
  - **button layout** at sm/md/lg (minimum width, both icons, trailing only);
  - the **size ladder with heights only** (xs–xl 28/36/44/56/68, moving with density), with the sentence "Padding is per component; see Components.";
  - the `space.*` scale including the sub-8px steps;
  - border widths and icon sizes.
- **Elevation, Motion, Layout:** as Concept C. Under reduced motion, the motion specimen shows static curves and a "Play" that states "Reduced motion is on: playing once on request."
- **Components:** the real 26, with variant count, nesting, per-component spacing (padding and gap from `space.*` per size), and the last build result (plugin).
- **Tokens:** columns per mode **where values differ**, not the first four. The contract version comes from `version.ts`.
- **Preview follows the setting (Q3):**
  - on **change or commit** of a lever, the preview switches to that lever's view and highlights what it drives;
  - debounced at 250ms;
  - **no switching on focus**;
  - **Keep this view** (pinned) suppresses the switching;
  - view changes are announced in a polite live region ("Showing Elevation").

## 10. Narrow mode (380×420, Q7)

- **One pane.** A single 36px top row holds: the brand select (truncating), the verdict dot, a **Settings | Preview** toggle, and **⋯** (Export, Apply Theme, the Figma actions, Health).
- **Domain tabs become a select.** The view select and mode select sit in the Preview pane's first row; neither is sticky.
- **An activity strip** (24px, under the top row) appears while an operation runs. Tapping it opens the drawer as a full-pane sheet.
- **Dialogs** use the full pane, with a sticky action row.
- **Target:** at least 3 levers visible at 380×420 in Brand. **Measure it and report it in the note.**

## 11. Start (Q14)

- **Studio first run:** a start screen.
  - From a color (hex + picker).
  - Blank.
  - An example: **prism3** (default), aurora, harbor.
  - Import a brand brief (paste or upload `design.md`; the error names the line and the fix).
- **Plugin:**
  - **An empty file** gets the same start screen, plus "From this Figma file" when a saved brand exists.
  - **A file with a theme** opens with the read-back result in the drawer, in one of the three #721 states.
- **The replace guard** appears only when there are unsaved edits. Its button names the loss: "Discard 3 edits".

## 12. Accessibility (brief §8.5; audit §1.7)

- Chrome text at 4.5:1 or better. **Control boundaries at 3:1 or better**, measured.
- Focus is visible and distinct from selected.
- Full keyboard operation:
  - arrows within chip groups;
  - Home/End on the divider.
- Hit targets are at least 24px, including text links.
- Dialogs use `showModal()` and **return focus to their trigger** after any re-render.
- Real tabs (`tablist`/`tab`/`tabpanel` with arrow keys) wherever tabs appear, or chip groups instead. Never mixed ARIA.
- No `title`-only information.
- Reduced motion is respected.
- **The note reports the measured numbers:** the lowest text ratio, the lowest boundary ratio, and the smallest target.

## 13. Voice (brief §8.4; `docs/voice-standard.md`)

- **UI lines** are 90 characters or fewer, with the system as subject. No domain intros longer than one line.
- **Banned:** "simply", "just" (meaning easy), "easy", exclamation marks, apologies and idioms. US English.
- **Labels:** "verdict", "Decisions log", "Build set", "Read-back", "Keep the Figma window in front".
- **Empty states** say what appears and what produces it: "Results of Apply, Build and Prune appear here after they run."
- **Success** says what changed, with counts. **Errors** say what failed and the next action.
- **Destructive buttons** name the outcome.
- **Specimen copy** is neutral and brand-recessive, for example a product-card layout with plain placeholder copy.
