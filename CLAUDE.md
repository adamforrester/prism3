# CLAUDE.md

Guidance for Claude Code (claude.ai/code) in this repository. It holds rules; the incidents behind them live where each rule points.

## What this repo is

An npm-workspace monorepo for the **Prism3 design-token engine** and its surfaces. Knowing which layer you're in decides almost everything:

| Layer | What it is |
|---|---|
| `packages/engine/` | The **engine** — dependency-free TypeScript, run via `tsx` (**no build**). Generates the token layer from a small brand input. Consumed by name as `@prism3/engine`, never by relative path. Start here for engine work. |
| `packages/tokens/` | The **consumability gate** (`@prism3/tokens`) — a stock Style Dictionary over the emitted DTCG, proving the output is consumable without custom code. |
| `apps/studio/`, `apps/plugin/` | The two **surfaces** that bundle the engine (`@prism3/studio`, `@prism3/plugin`). These build. |
| `apps/tokenpress/` | **TokenPress** (`@prism3/tokenpress`) — the public Figma Community plugin that exports Figma variables/styles *out* to DTCG. Ported in whole (copy first, adapt second), so it does **not** follow this repo's patterns inside `src/`: its own emitter and alias resolution, no `@prism3/engine` import. Treat it as a guest — read `apps/tokenpress/README.md` and its `agents.md` before editing, and don't "align" it with the engine: the duplication is measured, not accidental. |
| `docs/` | The **design record** — the numbered design docs plus `superpowers/` working notes. |
| `skills/` | The **shipped skills** (`prism3-theme`, `prism3-consume`, `prism3-rebind` for agents working *with* Prism3; `prism3-build-component` for agents working *on* the engine), gated by `lint-skills.ts`. Per-brand *payload* skills will be emitted by the engine (#668, not yet built) and will not live here. |
| `reference/` | The **legacy hand-built token JSON** — Prism2 + New Balance. Read-only in practice: it is the engine's regression target, not a place to author. |
| `tools/` | **Measurement harnesses**, not wired into `ci.yml`: a tool answers a question and exits 0, a gate asserts an answer and fails, so the two stay in separate files. Depth: `tools/CLAUDE.md`. |

Also read `README.md` (the signpost) and **`CONTRIBUTING.md`** — §3 is the canonical gate list, and `packages/engine/lint-doc-gates.ts` enforces that it matches CI. No Cursor/Copilot rules exist.

## Prism3 — the generation engine (start here for engine work)

The engine generates the token layer instead of hand-authoring it: it reproduces New Balance from a small brand input, then generalizes to new brands. **No build, no `npm install`** — run it via `tsx`. For any engine task, read first:
- `docs/00-progress.md` — status, decisions log, next steps. **Read `docs/progress/pending/` first:** entries merged since the last fold wait there (#1807).
- `docs/07-e2e-journey.md` — the designer↔developer↔agent pipeline + portable-core architecture.
- `packages/engine/README.md` — how the engine works and how to run it.

For the surfaces, start at `apps/studio/README.md` and `apps/plugin/README.md`; plugin work also reads `docs/18-plugin-and-host-architecture.md` and `docs/22-plugin-plan.md`.

Workflow: one PR per feature branch off `main` → squash-merge → delete branch → sync `main`.

**When more than one agent may be working, use a git worktree, not the shared checkout:** `git worktree add /tmp/p3-<lane> -b <branch> origin/main`, then `npm ci` — never a bare `npm install`, never a hand-rolled symlink loop. **Never point a package manager at a worktree whose `node_modules` is links** (not `--prefix`, not `--no-save`, not for one dependency): it writes through into the shared checkout. `.claude/hooks/session-start-npm-ci.sh` populates a fresh worktree; its header and `.claude/commands/review-pr.md` hold the incidents and the repair. A one-off `npx playwright install chromium` is fine.

**Checking out a branch in a tree someone else is editing destroys their uncommitted work** (recovery: `.claude/commands/review-pr.md`). **`git checkout <ref> -- <path>` is a destructive write spelled like a read, and nothing stashes it, so there is no recovery** — use `git show <ref>:<path>` and `git diff <ref> -- <path>`. **When mutation-testing a gate, commit before every mutation, not just the first** — each restore reaches back to `HEAD` and silently deletes work done in between; a `wip:` commit is enough, `--amend` once green.

`regen --check`'s expected artifact count lives in **two** places that move together: `EXPECTED_ARTIFACTS` in `verify.ts` and the same number in `ci.yml`. This file deliberately does not restate it (#1110; why: `.claude/hooks/session-start-claude-md-freshness.sh`). If `regen --check` disagrees with `verify.ts`, check for an untracked file under `packages/engine/out/` before assuming drift.

**A squash-merge rewrites the SHA, so judge "is my work in" by content, never SHA.** Once a branch is up for review, land a correction as a follow-up PR, not a push to it. Before pushing to a branch untouched for an hour, compare trees (`git diff origin/main <branch>`) rather than trusting `--force-with-lease`; if the work is in, reset onto `origin/main`. **`* [new branch]` on a push to a branch you did not just create means you recreated a merged, deleted branch** (a `PostToolUse` hook replies with the diff). Incidents for this and the previous two paragraphs: `docs/progress/archive/2026-07-08.md`.

**Carry the progress entry in the feature PR itself**, as `docs/progress/pending/<branch-with-slashes-as-dashes>.md` — never an edit to `docs/00-progress.md`. **Every PR carries one, except a fold;** `lint-progress-order.ts` enforces it. Format: `docs/progress/pending/README.md`; corrections and the fold exemption: `CONTRIBUTING.md` §2.

## Working in `reference/`

- Each brand holds the **same tokens twice**: `raw-figma/*.json` (Figma export: RGB float colors, `alias` + `VariableID:*`) and `tokens/*.json` (DTCG: brace aliases like `"{pds.color.neutral-cool.850}"`). **Change a value in both**, keeping the `$extensions.figma.variableId` linkage intact.
- Modes differ per brand — Prism2 by appearance (`light`, `dark`, `wireframe`), New Balance by viewport (`desktop`, `mobile`), each plus `shared/`. Don't force one brand's structure onto the other.
- Preserve the `nbds.pds.` prefix. DTCG slugs are kebab-case, dot-separated, numeric steps as keys (`blueberry.100`); the `050`-style padding exists only in raw-figma's slash paths.
- Nothing to build: validate by JSON parse, every DTCG `{...}` alias resolving, and every raw-figma `alias` matching a `VariableID` in that brand. Quote `reference/New Balance/`.

## Prose rules

- **US English** in all *visible UI text* and *emitted artifact prose* (`out/**`, emitted `schema/*`, generated reports): `color`, `gray`, `-ize`. Enforced by `lint-us-english.ts` and `lint-schema-classification.ts`. **Fix a false positive by adding to `NOT_EN_GB`, never by narrowing a scan.** Code comments and identifiers are exempt unless they ship in a built bundle (#464, #849); the gate's header has the rest.
- **Voice.** Shipped prose follows `docs/voice-standard.md` (change it only by changing its reasoning, `docs/29-tone-of-voice.md`) — read it before writing UI strings, descriptions, `.ai.json` fields, READMEs or marketing copy. Most prose is generated, so apply it in `levers.ts` or `ai-metadata.ts`. The load-bearing attribute is **recessive**: the tool's voice must not compete with the brand on screen. Code comments are exempt.

## Working principles (agent behavior)

Adapted from the Karpathy coding guidelines (github.com/multica-ai/andrej-karpathy-skills): turn imperative requests into declarative goals with verification loops.

Quote paths that contain spaces; use repo-relative paths, because the absolute root differs per checkout.

1. **Think before coding.** State assumptions; surface ambiguities and tradeoffs *before* writing code. When a choice is genuinely the user's to make, ask — don't guess. Decisions get confirmed before they're built.
2. **Simple implementation, rigorous correctness.** Minimum code, no speculative abstractions, stay dependency-free (own the math). BUT hold the *correctness* bar high — contrast contracts, field research and "better than the examples" are the standard, not gold-plating.
3. **Surgical changes.** Edit only what the task needs; one concern per PR; preserve existing patterns. **One concern per PR stops you fixing a defect you weren't asked to fix — not filing it.** A mention in a PR body or progress entry is not filing: open it as its own issue, citing where it was found.
4. **Goal-driven execution with verification.** Define verifiable success up front and loop until green. **Before pushing, run the whole list below — never a subset chosen because the diff "only touched the engine."** CI runs every one on every PR.

   - **Run them with `npm run verify`** (`verify.ts`) rather than by hand — it runs every gate below in a declared, checked order and prints a per-gate PASS/FAIL table (why a runner and not a hand-list — exit-status capture, per-gate buffering, enforced ordering, SKIP-is-not-a-pass: `CONTRIBUTING.md` §3).
   - **Engine** — run `npx tsx packages/engine/regen.ts` first (regenerates every committed artifact), then confirm: `regen.ts --check` · `lint-materialization-renames.ts` · `lint-emission-version.ts` · `lint-component-surface.ts` · `lint-component-renames.ts` · `lint-push-base.ts` · `test.ts` · `mcp-test.ts` · `token-contract.ts --check` · `lint-contract-version.ts` · `emit-agent-reference.ts --check` · `emit-figma-conventions.ts --check` · `lint-skills.ts` · `nb-regression.ts` · `lint-doc-gates.ts` · `lint-layout-claims.ts` · `lint-decisions-index.ts` · `lint-context-nodes.ts` · `lint-ratio-truth.ts` · `lint-description-claims.ts` · `lint-axis-values.ts` · `lint-progress-order.ts` · `typecheck-components.ts` · `lint-payload-manifest.ts` · `lint-overlay-completeness.ts` · `lint-overlay-provenance.ts` · `lint-figma-destination.ts` · `lint-stranded-collections.ts` · `lint-ramp-steps.ts` · `lint-ramp-values.ts` · `lint-paint.ts` · `lint-paint-placement.ts` · `lint-rung-names.ts` · `lint-shape-index.ts` · `lint-schema-classification.ts` · `lint-absolute-inset.ts` · `lint-lineheight-bake.ts` · `lint-cut-binding.ts` · `lint-size-override-coherence.ts` · `lint-standalone-floor.ts` · `lint-glyph-geometry.ts` · `lint-icon-count.ts` · `lint-nesting.ts` · `lint-hit-target.ts` · `lint-lever-sweep.ts` · `lint-figma-descriptions.ts` · `lint-tool-neutral-prose.ts` · `lint-consumer-build.ts` · `lint-advisory-expiry.ts` · `lint-component-docs.ts` · `lint-ecosystem.ts` · `lint-release-notes.ts`, plus every DTCG alias resolving and every mode contrast contract passing.

   - **TokenPress** — `npm run -w @prism3/tokenpress` → `test` · `build`. **No `typecheck`** — a pre-existing `tsconfig.json` mis-wiring, out of scope for the port and tracked as a follow-up; don't add the step until the tsconfig is fixed, or you just pin the count its `tsc` reports. Full narrative: `CONTRIBUTING.md` §3.
   - **Exporter agreement** — `npx tsx tools/exporter-comparison/gate.ts`, run **after** the TokenPress build — it executes TokenPress's real `TokenExporter` in memory over prism3's own Figma emission. Then `npm run -w @prism3/plugin test:readback-parity` (#2351) — the plugin's Apply Theme, written into the file shim, exports through the same exporter to the same DTCG as that emission, by path.
   - **Tokens** — `npm run -w @prism3/tokens check:consumability`.
   - **Freshness detector** — `sh tools/claude-md-freshness/mutations.sh` — the mutation battery for the CLAUDE.md-freshness SessionStart hook (#1110), the one `tools/` battery wired into CI (#1123). It is named for the **detector**, not for this tree: `docs/34` shape 17 is explicit that a stale checkout is internally consistent, so CI — which runs inside the tree — can never check whether *this* checkout is stale; what it checks is that the detector still fires on a stale world, goes silent when its fetch is dropped, and says CANNOT DETERMINE when the oracle is unavailable. Local `file://` git in `$TMPDIR`, no network, no git history, so it runs cleanly under CI's shallow checkout.
   - **Last, after BOTH the web and plugin builds** — `npx tsx packages/engine/lint-us-english.ts` and `npx tsx packages/engine/lint-voice.ts`; their scope includes the built bundles, so running them earlier scans a stale one. Scope details (the `apps/plugin/dist` coverage #937 added, and the matching gap in `lint-voice.ts` filed as #948) live in each gate's own header.

   **Per-gate rationale lives in `CONTRIBUTING.md` §3 and each gate's header.** `lint-doc-gates.ts` fails CI if this list, `CONTRIBUTING.md` §3, or the PR template drifts from `ci.yml`.

   **A gate is only as strong as the independence of the two things it compares.** One derived from its subject cannot fail, and reports that as a pass. **So mutate the subject and confirm *your* gate fails, by name.** DRY between a gate and its subject silently deletes the gate, and a scope must assert each promised surface is **represented**, not count files. Read `docs/34-gate-independence.md` (rule, sub-shapes, register) *before* writing a gate.

5. **Versioning: names are versioned, values are not.** `packages/engine/version.ts` holds two. `ENGINE_VERSION` (*"what code produced this?"*) bumps on any behavior change, but **a PR never edits it or its changelog, `packages/engine/CHANGELOG.md`:** it adds `packages/engine/changes/<branch-with-slashes-as-dashes>.md` declaring the class, and `fold.ts` assigns the number (`CONTRIBUTING.md` §2). `CONTRACT_VERSION` (*"can my app still resolve its names?"*) bumps **only** when the guaranteed token-name surface moves. Its baseline, `packages/engine/schema/token-contract.json`, is **never a `regen.ts` artifact** — only `token-contract.ts --accept` rewrites it, after the version is raised: **a gate allowed to rewrite what it reads has no memory.** Policy: `docs/30-versioning-and-compatibility.md`.

6. **Autonomous arcs and the decision boundary.** Inside an arc scoped with the owner, the agent executes autonomously and owns the technical calls (implementation, structure, gate design, version-bump class, merge mechanics, test strategy).
   - **Design decisions are the owner's, always** — component API or identity, visual/behavioral design, brand-facing naming, voice/tone copy, new component shapes or composition models, and any public-contract change that isn't the mechanical fallout of a fix. Flag, don't pick; a fix that turns out to carry one **stops and flags**. Unsure? Treat it as design.
   - **The safety net is non-negotiable and gates every merge:** independent verification + independent review + green CI + a mutation that fails *by name*. Autonomy is earned by the net, not asserted.
   - **Keep the owner oriented** — plain-language summaries at arc boundaries, every held decision surfaced with enough context to answer without digging.
