## What this repo is

An npm-workspace monorepo for the **Prism3 design-token engine** and its surfaces. Knowing which layer you're in decides almost everything:

| Layer | What it is |
|---|---|
| `packages/engine/` | The **engine** — dependency-free TypeScript, run via `tsx` (**no build**). Generates the token layer from a small brand input. Consumed by name as `@prism3/engine`, never by relative path. Start here for engine work. |
| `packages/tokens/` | The **consumability gate** (`@prism3/tokens`) — a stock Style Dictionary over the emitted DTCG, proving the output is consumable without custom code. |
| `apps/studio/`, `apps/plugin/` | The two **surfaces** that bundle the engine (`@prism3/studio`, `@prism3/plugin`). These build. |
| `apps/tokenpress/` | **TokenPress** (`@prism3/tokenpress`) — the Figma plugin that exports Figma variables/styles *out* to DTCG, i.e. the opposite direction from the engine, and the one surface here that ships publicly in the Figma Community. Ported in whole (copy first, adapt second), so it does **not** follow this repo's patterns inside `src/`: its own DTCG emitter, its own alias resolution, no `@prism3/engine` import anywhere. Treat it as a guest — read `apps/tokenpress/README.md` and its own `agents.md` before editing, and do not "align" it with the engine on the assumption the duplication is accidental. It is measured, not accidental. |
| `docs/` | The **design record** — the numbered design docs plus `superpowers/` working notes. |
| `skills/` | The **product skills** — `prism3-theme` (authoring a brand) and `prism3-consume` (building UI from generated tokens), addressed to an agent working *with* Prism3. Shipped prose that makes factual claims about the engine, so `lint-skills.ts` gates them. Per-brand *payload* skills, addressed to an agent in a client's ejected repo, are emitted by the engine (#668) and do not live here. |
| `reference/` | The **legacy hand-built token JSON** — Prism2 + New Balance. Read-only in practice: it is the engine's regression target, not a place to author. |
| `tools/` | **Measurement harnesses** — runnable and committed. `tools/exporter-comparison/` runs prism3's DTCG emitter and TokenPress's over the same brand and classifies every difference (#697's Verify bullet). A tool here answers a question; a gate asserts an answer, so the two live in **separate files**: `compare.ts` reports all five categories and always exits 0, and `gate.ts` — the assertable subset, in CI — fails on the seven arms where a difference means one exporter is *wrong* rather than *different*. Its third file, `axes.ts`, is neither: it is #697's recorded **decision** about which collections' modes are an axis, wired in so mislabeling one fails a gate rather than sitting in prose. Don't promote a category without deciding it is a *defect* rather than a documented disagreement; the ones left out are named in `gate.ts`'s header, with why. `tools/nest-exposed-cost/` measures what a `nest-exposed` nested part would cost the parent that exposes it (#681) — panel rows against Figma's ceilings, and payload bytes through the real chunk packer. It has no gate sibling on purpose: nobody has decided what the ceiling ought to be, so there is no answer to assert. Read its header before quoting a number from it, and know that **#761 read its own byte figure wrong and a reviewer caught it**: worst-chunk fullness is near-budget *by construction* (`pack` fills until the next variant will not fit) and chunk overflow is absorbed by adding chunks, so "4 bytes of headroom" was an artifact, not a cliff. The ceiling that means something is the **indivisible unit** — shell + largest single variant, since no re-packing can split one variant across two calls — which is at 49% of budget on the largest real set. The generalizable trap: an instrument found non-monotonic is disqualified for *every* reading taken from it, not just the one that prompted the check. `tools/forward-claim-check/` finds present-tense claims about *mutable* issue state in tracked prose (`blocked on #N`, `#N is still open`, `parked pending #N` — written schematically here on purpose, see below) and reports each against the state the cited issue is in — a small fraction of the repo's issue citations qualify as reportable sites (see the file's own header for the live count; a hardcoded snapshot here would go stale the same way the claims it detects do). Also **no gate sibling, and for a sharper reason**: **recall is unmeasured and the denominator unknown**. A confirmed false negative (an em-dash construction the `still-open` pattern's grammar didn't cover) turned up by accident in `packages/engine/theme.ts`, and a concurrent PR fixed that exact sentence before this file even merged — which the file's own header treats as evidence *for* the argument, not against it: nothing here was watching for it either. A gate here would report clean over everything it cannot see — `docs/34` shape 9. It exits non-zero **only when the instrument is broken** (zero citations, a corpus below the recorded baseline, a pattern that stopped firing on its own sample, a stale register), never because a claim is stale. Its two exclusions — append-only dated journals, and claims *quoted* rather than asserted — are properties of the **document**, not of the pattern; narrowing the pattern instead would score better and know less, and the header says so at length. Issue states come from a committed `issue-states.json` resolved via the GitHub MCP tools, so verdicts are only as fresh as that file. One hazard learned while writing that row: **quoting a live claim verbatim in a non-journal document is indistinguishable from asserting one** — this row's first draft cited a real closed issue as an example and the tool duly reported `CLAUDE.md` itself as stale. Write examples schematically (`#N`), or expect the documentation of a detector to be caught by it. |

## Prism3 — the generation engine (start here for engine work)

The engine generates the token layer instead of hand-authoring it: it reproduces New Balance from a small brand input, then generalizes to new brands. **No build, no `npm install`** — run it via `tsx`.

For any engine or token-generation task, read these first (they hold the durable state so work survives a context clear):
- `docs/00-progress.md` — status, decisions log, and prioritized next steps.
- `docs/07-e2e-journey.md` — the designer↔developer↔agent pipeline + portable-core architecture.
- `packages/engine/README.md` — how the engine works and how to run it.

The two surfaces that bundle the engine:
- `apps/studio/` (`@prism3/studio`) — the web dashboard/theme studio (esbuild dev server); see `apps/studio/README.md`.
- `apps/plugin/` (`@prism3/plugin`) — the Figma plugin (two-context split + typed postMessage bridge); see `apps/plugin/README.md`. For plugin work read `docs/18-plugin-and-host-architecture.md` (capability grounding) and `docs/22-plugin-plan.md` (the phased build plan, #106–#110).

Workflow: one PR per feature branch off `main` → squash-merge → delete branch → sync `main`.

**When more than one agent may be working, use a git worktree — not the shared checkout.** `git worktree add /tmp/p3-<lane> -b <branch> origin/main`, then give it a `node_modules` (the repo is buildless, but a fresh worktree has none, so `npx tsx` would re-download and the `apps/studio`/`apps/plugin` builds would fail). **Populate it with `npm ci` — never a bare `npm install`, and never a hand-rolled symlink loop.** `npm ci` is the whole setup: measured in a fresh worktree, 5s, and it builds all five `@prism3/*` links *relative* so they resolve inside that worktree. `install` is free to resolve a version the lockfile does not pin, and on 2026-08-11 a stray interrupted-install artifact in the shared tree let an unlocked `@figma/plugin-typings` leak into a review worktree that way. **Do not also symlink afterwards** — composing the two leaves 86 stray links in a tree whose cleanliness is load-bearing, and `never `ln -s` the whole directory` is the older hazard it replaces: workspace links are relative (`@prism3/engine` → `../../packages/engine`), so reached through a whole-directory symlink they resolve against the *main checkout*, and every `@prism3/*` import loads the code from the tree you are not working in, with exit 0 and no warning. Nor may you symlink the directory and overwrite `@prism3/*` afterwards — that writes *through* the link and repoints another session's `node_modules` at your worktree. `.claude/commands/review-pr.md` carries all of these measurements; for a review, the failure mode is a false pass. Anything that checks out a branch in a tree someone else is editing destroys their uncommitted work: `/review-pr` did exactly that twice on 2026-08-05, once auto-stashing the other session's edits and once rebasing its branch onto an unrelated PR's commits. Recovery, if it happens to you: the checkout auto-stashes rather than deletes, so `git stash list` then `git show 'stash@{0}:<path>'` extracts single files **without popping** — popping merges two PRs' work, since the stash may hold both. `regen --check` should report **105** artifacts; `ci.yml` asserts that number. If you see a different count, check `git status` for an untracked file under `packages/engine/out/` before assuming drift.

**A squash-merge rewrites the SHA, so a merged branch is not recognizable as merged from its own history.** Three separate races on 2026-08-12, each diagnosed correctly in isolation and none recognized as the third: a `--force-with-lease` rejected as stale after another session had rebased the branch; a first push that recreated a branch already squash-merged mid-task, instead of updating its open PR; and a correction pushed to a branch under review, orphaned when the merge took a rewritten copy of the earlier commit — the PR body carried the fix and `main` did not. Two rules follow, and both are about *content, never SHA*. **Once a branch is up for review, land a correction as a follow-up PR rather than a push to it** — a review comment arriving on merge-ready work is a race you will sometimes lose, and losing it drops the commit silently. And **before pushing to a branch you have not touched in the last hour, compare trees rather than trusting `--force-with-lease`**: the lease reads your *tracking ref*, which goes stale the moment the remote branch is deleted after merge, so it rejects on bookkeeping while proving nothing about the work. `git log --oneline origin/main..<branch>` plus `git diff origin/main <branch>` answers "is my work already in" in the only way squash-merge leaves available. If the answer is yes, reset the branch onto `origin/main` and start the follow-up there.

**Carry the `docs/00-progress.md` entry in the feature PR itself**, not as a follow-up. Three PRs in a row (#306, #312, #315) merged without one and needed a separate docs PR to catch up, and the entry is worth most for exactly the things a diff cannot show: the diagnosis that made the fix small, the tradeoff that was deliberate, the approach tried and discarded, and any trap waiting for whoever re-verifies this later. Write it as part of the work, while that reasoning is still in hand.

## Two parallel token formats

Each brand contains the **same logical tokens twice**, in two formats. Edits usually need to land in both — they describe the same data for different consumers.

```
<Brand>/tokens/
├── raw-figma/   # Figma plugin export format
└── tokens/      # DTCG (W3C Design Tokens) format
```

### `raw-figma/*.json` — Figma variable export
Flat array under `variables[]`, file-scoped `$collection` + `$mode`. Colors are RGB float objects (`{r, g, b, a}` 0-1). References use `alias` + numeric `VariableID:*`. This is what Figma's Variables plugin reads/writes.

### `tokens/*.json` — DTCG format
Nested object tree (e.g. `nbds.pds.color.blueberry.100`). Each leaf has `$type`, `$value`, `$description`, `$extensions.figma`. Aliases use brace syntax: `"{pds.color.neutral-cool.850}"`. The `$extensions.figma.variableId` round-trips back to the raw-figma IDs.

When editing a value: change it in **both** the raw-figma file and the DTCG file, and keep the `variableId` linkage intact — it's how the two formats stay reconcilable.

## Mode organization differs per brand

- **Prism2** splits by appearance: `light/`, `dark/`, `wireframe/` each carry `brand-theme.json` + `motion.json`; primitives, typography, spacing, etc. live in `shared/`.
- **New Balance** splits by viewport: `desktop/typography.json`, `mobile/typography.json`; everything else (color, motion, focus, radius, layout, shadows, breakpoints, dimensions) lives in `shared/`.

Don't force one brand's structure onto the other.

## Naming conventions

- Prism2 tokens are namespaced `nbds.pds.<category>.<...>` — preserve this prefix.
- Token slugs in DTCG paths use kebab-case for words, dot-separated levels, with numeric scale steps as keys (`blueberry.100`, `blueberry.150`).
- The Figma exports use slash paths (`pds/color/blueberry/050`) — the `0` padding (e.g. `050`) only appears in raw-figma; DTCG drops it.
- **US English** in all *visible UI text* and all *emitted artifact prose* (`out/**`, the emitted `schema/*` files, the generated reports): `color` not `colour`, `gray` not `grey`, `-ize` not `-ise`. **Enforced, not remembered** — `npx tsx packages/engine/lint-us-english.ts` gates every shipped surface and runs in CI *after* the web build (its scope covers the built bundle). Scope is imported from `regen.ts`, so a new emitted artifact is covered automatically; `schema/token-contract.json` is deliberately *not* a regen artifact (see principle 5) and so is named by hand in the gate — anything else kept out of regen needs the same line, **in this gate *and* in `lint-voice.ts`, and that is now asserted rather than remembered** (#807). `lint-schema-classification.ts` fails until every file in `packages/engine/schema/` is classified: regen-covered, hand-named in **both** prose gates, or exempt with a stated reason. The rule above had been performed by memory, and three files — `payload-manifest.json`, `nb-measured.json`, `theme-schema.example.json` — were in neither gate with nothing recording whether anyone had decided. Note what made that invisible: two files in the *same directory*, one covered and one not, are indistinguishable from outside, which is exactly the membership-by-location defect `payload-manifest.json` itself exists to remove one tier down. **A false positive is fixed by adding to `NOT_EN_GB`, never by narrowing a scan.** Code comments and identifiers are exempt, *except in `apps/studio/src`*: which comments esbuild keeps in the bundle is an implementation detail, so an exemption the gate cannot see is not enforceable — write US English in `apps/studio/src` comments too. The four traps this gate encodes, each of which caught a previous pass, are documented in the file's own header; read it before touching either scan.

- **Voice.** All shipped prose follows `docs/voice-standard.md` — the operative rules (four voice attributes, a banned-phrase list, per-channel register, tone by situation, a 5-question pre-ship check). It is short and self-contained by design: read it before writing UI strings, lever/role descriptions, emitted `$description` prose, `.ai.json` fields, READMEs, or marketing copy. The reasoning behind it is `docs/29-tone-of-voice.md`; change the standard only by changing that. Two things to know going in: **most Prism3 prose is generated, not typed**, so applying the standard usually means editing `levers.ts` or `ai-metadata.ts` rather than a string; and the load-bearing attribute is **recessive** — Prism3 builds *other people's* brands, so in every product surface the tool's voice must not compete with the brand on screen (this is why we don't borrow the confidence about personality that first-party systems like Polaris or Material can afford). Code comments are exempt, same carve-out as US-English.

## Working with this repo

- Path quoting: some paths contain spaces (`reference/New Balance/`) — quote them in Bash commands. Use repo-relative paths; the absolute root differs per checkout (worktree, container, CI).
- **`reference/` has nothing to build, lint, or test** — validation there is JSON parse + reference resolution: every `{...}` alias in DTCG files resolves to a real path, and every raw-figma `alias` ID matches a `VariableID` defined in that brand's exports. Everywhere else, the gates in principle 4 apply.

## Working principles (agent behavior)

Adapted from the Karpathy coding guidelines (github.com/multica-ai/andrej-karpathy-skills). The point is to turn imperative requests into declarative goals with verification loops.

1. **Think before coding.** State assumptions explicitly; surface ambiguities and tradeoffs *before* writing code. When a choice is genuinely the user's to make, ask — don't guess. (This project runs as a design dialogue; decisions get confirmed before they're built.)
2. **Simple implementation, rigorous correctness.** Write the minimum code that solves the request — no speculative abstractions or features beyond what was asked; stay dependency-free (own the math, don't pull libraries). BUT this is an accessibility / design-system domain: hold the *correctness* bar high — contrast contracts, field research (the knowledge-base + NB/Prism2 examples), and "better than the examples" are the standard, not gold-plating. Simple code, rigorous contracts — the two are not in tension.
3. **Surgical changes.** Edit only what the task needs; don't refactor adjacent code or fix unrelated pre-existing issues unless asked. One concern per PR. Preserve existing patterns, naming, and conventions. **"One concern per PR" stops you fixing a defect you found but weren't asked to fix — it does not stop you filing it.** Noting it in the PR body or a `docs/00-progress.md` entry is not filing it: prose in a write-up is not discoverable as work, doesn't get a label or a lane, and strands the defect for whoever next reads that entry to rediscover independently. Before moving on, file it as its own issue, citing where it was found.
4. **Goal-driven execution with verification.** Define verifiable success up front and loop until green. **Before pushing, run the whole list below — never a subset chosen because the diff "only touched the engine."** CI runs every one of these on every PR regardless of which files changed, so a documented checklist shorter than CI's is one a diligent contributor can follow exactly and still ship broken. That is not hypothetical: two independent PRs each shipped a "gates all pass" table built faithfully off a list that had gone short, and both broke a gate it omitted (`lint:classes`, since retired in #770 — the *list* going short is the durable lesson, not the particular gate).

   - **Run them with `npm run verify`** (`verify.ts`, #789) rather than by hand. It runs every gate in this list in a declared, checked order and prints a per-gate PASS/FAIL table — the transcription this bullet list otherwise asks you to do twice, once into shell commands and once back into a report. Four properties are the point, each of them a defect that has shipped here: it captures the exit status with **no pipeline between** (`… | tail -2; echo $?` reports *tail's* status, which is how a failing `lint-us-english.ts` was reported as a pass); it **buffers output per gate**, so a clean run is a table and a red one is a table plus only what failed; it **enforces the ordering** below (the prose gates after the web build, the exporter gate after the TokenPress build) and refuses to run if the authored order violates a gate's own declaration; and it **never prints a pass for a gate that did not run** — SKIP is a distinct outcome, a skipped gate makes the run non-green, and a table shorter than the list is itself a failure. Its list is the **fifth** authored statement of what the gates are, compared against `ci.yml` in *both* directions by `lint-doc-gates.ts`, which is what makes `ci.yml` itself checkable: before #789 a gate missing from `ci.yml` left four artifacts in perfect agreement and fired nothing (measured, not assumed — deleting `lint-paint.ts` from `ci.yml` left the old gate exiting 0). It deliberately does **not** run bare `regen.ts`: that would make the next gate compare the fresh output with itself and pass unconditionally. If `out/` is dirty it reports `regen.ts --check` as SKIP with the reason, because with uncommitted artifacts that gate answers a question about your working tree, not about `HEAD`.
   - **Engine** — run `npx tsx packages/engine/regen.ts` first (regenerates every committed artifact), then confirm: `regen.ts --check` · `test.ts` · `mcp-test.ts` · `token-contract.ts --check` · `lint-skills.ts` · `nb-regression.ts` · `lint-doc-gates.ts` · `lint-layout-claims.ts` · `typecheck-components.ts` · `lint-payload-manifest.ts` · `lint-overlay-completeness.ts` · `lint-paint.ts` · `lint-shape-index.ts` · `lint-schema-classification.ts` · `lint-absolute-inset.ts` · `lint-advisory-expiry.ts`, plus every DTCG alias resolving and every mode contrast contract passing. That last one is the only gate here whose oracle is the **clock**: it scans the tracked tree for a stated advisory window and fails once the stated day arrives, naming every site that describes it, because the same dated promise is written in six places and all six go false on the same morning. It is deliberately **gating and not advisory** — a gate that watches for expired advisories and is itself advisory would be its own joke. Its scope is `docs/34` shape 9 in miniature: the run prints the whole census on every invocation, so a count that drops without a deletion in the diff is the tell that the detector has narrowed. `docs/00-progress.md` is exempt **by genre**, the same exemption `lint-layout-claims.ts` grants it — its dated entries describe the repo as it was, so a closed window recorded there is correct prose forever. Its stated limit: a claim phrased with neither `advis…` nor `continue-on-error` is not seen, and that wider class is a `tools/` harness, not this gate.
   - **Web** — `npm run -w @prism3/studio` → `typecheck` (esbuild does not typecheck, so this and `build` are not redundant) · `test` (the provenance model, #722 — and `typecheck` does **not** subsume it: `apps/studio/tsconfig.json` includes `src` only, so the test file is never compiled and this is the only thing that runs it) · `build` · `test:smoke` (#767 — the headless DOM/interaction suite, run **after** `build` because it drives the built `dist/main.js`; a *separate* script from `test` on purpose, so a browser flake can never take #722/#723's pure suites down with it. **Advisory in CI until 2026-08-20, then gating — #775.** It is the only coverage `src/main.ts` has or can have: that file touches `document` at import time, so it cannot be loaded into a Node harness at any granularity, which is precisely why both pure suites cover modules *extracted* from it) · `check:ignore` · `lint:contrast` (STATIC, the token VALUES — the smoke suite measures what *renders*, and neither subsumes the other). There is no `lint:classes` any more: #770 gave the stylesheet scoped class names, so a cross-surface collision is refused by `el`'s type and by the stylesheet's own installer rather than reviewed into an allowlist.

Seven arms, on every brand with a Figma emission (discovered by scanning `out/figma/`, count asserted `>= 3`): a `$type` disagreement on a shared path, the same on a path a pairing **rule** relates (#747), a pairing that compares **no** types at all, an emitted collection whose mode axis nobody **declared** (#697), a path TokenPress emits that prism3 does not, the float32 cleanup **rewriting** a value instead of restoring it (#703's prediction), and #709's opacity 100× at the integration level. Its sibling `compare.ts` is the **measurement** and always exits 0 — most of what it reports is a difference that is *right for its host*, so categories 3–5 stay reporting-only until #697's byte-for-byte question is answered, and the gate imports `analyze` (one measurement path) but deliberately **not** `VERDICTS`, whose authored predicates were three-of-four wrong until #729. The prism3-only arm is a **memory of paths with causes**, never a count, and fails in *both* directions: a third unreachable path fails, and a path becoming reachable fails as a stale memory — aurora's 2 gradients are the only entry, carved out under #731 rather than forever, because `getLocalPaintStylesAsync()` exists and TokenPress simply never calls it. The three type arms are one claim at three widths, and the second two exist because of a mutation that did **not** fail (#747): the original arm compared only paths appearing verbatim on both sides, so retyping an axis-collapsed path (`grid.<breakpoint>.<prop>` vs `grid.<prop>`) left it green — the same mutation on `FONT_SIZE`, which pairs verbatim, produced 66 failures. Blind set was **71–73 paths per brand**, ~14% of the paired surface, across all four pairing rules; it is now **0 and asserted**, so a rule added later that resolves no counterpart type fails rather than widening the hole silently. Each rule declares a **`counterpart`** — a whole token, or a named *field* of a composite — and the expectation is read from the **canonical tree**, the emitter's own input, never from the rule's claim about itself. Two things it cost to learn are worth more than the arm: the new arm **falsified one of the rules on its first run** (the `font-fluid.*` prose said "a second copy of the composite"; it is the composite's `fontSize` *referent*, carrying neither `fontFamily` nor `fontWeight` — fixed by *tightening* the rule, and a check independent enough to contradict a claim its own file makes is the best evidence it is not a tautology — **but the arm compares `$type`, so it falsifies a `reason` only when the error changes a type**, which font-fluid's did by luck: swapping the `grid.*` rule's `gutter`↔`margin` orphans nothing, keeps both sides `dimension`, and passes fully green while nb's values differ at 3 of 5 breakpoints, so a green `paired types` means *the two sides agree on type*, not *the pairing is right*, and closing that needs values compared across rule-paired pairs); and **a mutation that changes nothing is indistinguishable from a blind spot** — disabling the explicit `FONT_SIZE` check alone stayed green because a *defensive* scope list downstream catches it, so both sites had to move before the behavior did. Closing this needed a **decision**, not effort: a Figma variable can vary a value only by mode, so prism3's non-appearance axes become modes going out and paths coming back, and carrying a type across that collapse requires knowing which collections' modes *are* an axis. Nothing in a Figma file records it (inference by "do the variables vary" does not separate them — nb's `layout` varies 3 of 10 against `color`'s 159 of 163, a difference of degree that a fourth brand moves), so **#697's call is: be told for the round-trip, flatten for a foreign import**, declared in `tools/exporter-comparison/axes.ts`. `$extensions.prism3.figma` is a *third* thing rather than an alternative — already on 43–47% of leaves, it records where a leaf **went**, not what a collection's modes **mean**, and a consumer needs the second to know if modes are alternatives or coordinates. The declaration is load-bearing, verified by mutation: relabeling `layout` `breakpoint`→`none` produces 57 failures because `grid.*` stops pairing at all, an undeclared collection fails as **unclassified** (never defaulted — 13 of 16 entries are `none`, so a default would be right 13 times *by accident*), and a declared-but-unemitted one fails as **stale**.
   - **Tokens** — `npm run -w @prism3/tokens check:consumability`: a stock Style Dictionary over the emitted DTCG — a *characterization* gate over **every** emitted brand, discovered from `out/` and asserted by name (#635). It pins each brand's mode collapse (permanent by DTCG design, #609) and splits unserializable values in two (#642): the **emitter side is a RULE asserted at 0** — every `$type` in the conforming projection is a DTCG type, checked against the spec list rather than by counting `[object Object]`, so it fails the day a non-standard type ships — while the **consumer side is a MEMORY pinned at 2**, aurora's gradients, which are correct DTCG that a stock Style Dictionary has no handler for. It also asserts the emitted `base` + `<mode>.overlay` projection reads back through a stock config, and refuses custom preprocessors/transforms (see `packages/tokens/README.md`).
   - **Last, after the web build** — `npx tsx packages/engine/lint-us-english.ts` and its sibling `npx tsx packages/engine/lint-voice.ts` (voice-standard.md §2's banned-phrase list — #617); their scope includes the built `apps/studio/dist/*.js` bundle, so running them earlier scans a stale one.

   `CONTRIBUTING.md` §3 is the canonical list with per-gate rationale, and `lint-doc-gates.ts` fails CI if it, this list, or the PR template drifts from `ci.yml`. Its sibling `lint-layout-claims.ts` gates the layer table above and the layout tables in `README.md` and `docs/09` §3 — a path a doc claims must resolve, and a directory that exists must be described. **Adding a workspace under `apps/` or `packages/` therefore requires editing those three tables in the same PR**, which is the gate working: #669 shipped a `README.md` with no `skills/` row at all. And `typecheck-components.ts` typechecks the component defs against `component-schema.ts` (#657) — `tsc --noEmit` over `packages/engine/tsconfig.json`, which is a **check, not a build**: the engine stays buildless and the gate asserts both halves of that (`noEmit` in tsc's own resolved config, and nothing emitted beside the defs). It also asserts every tracked def is **represented in what tsc actually read**, because a passing typecheck proves nothing about which files it opened — before this, exactly one def of five was checked, and only because `apps/plugin/src/main.ts` happened to import it. Since #742 it also carries the **registry arm**, both directions: every tracked def file must contribute an export to `components/index.ts`'s `componentDefs`, and every member of that set must come from a tracked def file. **git's index stays the ORACLE; the registry is only ever the SUBJECT** — a gate that read the registry to decide what to expect could only confirm the list agrees with itself. The `include` glob was deliberately *not* narrowed to reach the defs through the registry, tempting as that is: it would make one bookkeeping slip *also* stop typechecking the def. And `lint-payload-manifest.ts` asserts every emitted artifact is classified **payload** (it travels to a client on eject) or **ours** (#674) — `out/` previously mixed the brand's token trees with a regression report and a preview page, with nothing but human knowledge distinguishing them, which is how the first eject would have decided membership by accident. **`schema/payload-manifest.json` is AUTHORED and deliberately not a regen artifact**, for the same reason `token-contract.json` is not: regenerated from a scan of `out/`, it would classify each new artifact itself and report that as a pass. So **adding an emitted artifact fails this gate until a human classifies it** — that friction is the feature. Know its limit: it checks a class is *declared*, not that the class is *right* (moving the canonical tree to `ours` passes, verified by mutation), which is what the `why` on every rule is for. And `lint-overlay-completeness.ts` asserts each mode's overlay carries **exactly** the leaves that vary in that mode (#708), in both directions — a varying leaf missing, and a non-varying leaf present. Why this needed its own gate is the instructive part: `$extensions.prism3.modes` was written in **two shapes for one concept** (color wrapped its value, shadow was the bare array), the projector's guard read one of them, and 28 mode-varying shadows were dropped from every overlay in all four brands — a conforming consumer reading `base + dark.overlay` rendered **light shadows in dark mode**. Every existing gate passed it legitimately: the base+overlay cascade means every token is always present in every mode, because base supplies it, so a dropped override resolves to a real value — just the wrong one. Nothing anywhere held an independent answer to *which* tokens ought to differ per mode. This does, and its independence is the whole design: EXPECTED is derived from the projector's **input** (the canonical `modes` extension) by the gate's own traversal, ACTUAL is read from its **output** (the emitted overlays). Deriving EXPECTED by re-running `buildOverlay`, or by reading the overlays, would reproduce the bug on both sides and report it as a pass — so **the duplicated walk is the gate, not redundancy to DRY away.** It covers every composite type **by rule**, never a list naming `shadow`: `typography`, `border`, `transition` and `gradient` hit the identical trap the day one gains a mode entry. And `lint-paint.ts` gates the **component tier's colour bindings** (#758), in two arms, because #758's own stated acceptance — *"Button's 648-member paint is byte-identical: `regen --check` reports 104"* — **cannot fail**: `figmaAnatomySet` is called by no emitter and no component payload is committed under `out/`, so component paint is outside regen's universe entirely. Repointing `destructive.outline.icon` at `color.interactive.neutral.text.rest`, a token that *resolves*, left `regen --check` at 104 **and `test.ts` at 2192 passed / 0 failed** while a destructive button's icon painted neutral ink. Arm 1 is a **rule at zero**: a paint key led by an axis value must point at a token ref carrying that value (90/90 across the corpus), with EXPECTED read from the key and ACTUAL from the ref — two authored halves, and deliberately *not* `paintOf`'s own lookup, which would agree with itself in the mutated case too; its four exceptions are named per key with a reason and checked in **both** directions, so a stale exemption fails. Arm 2 is a **characterization** pinned to an authored baseline, because a uniform loss (dropping the state-qualified lookup: 1926 → 1782 assignments) crosses no intent boundary and leaves arm 1 legitimately green. **It is taken over the full declared grid, never over `figmaAnatomySet`** — `icon.figmaProperties.variantAxes` is `['size']` while its paint axis is `tone`, so a set-based census pins `icon: 0`, a number no mutation can move, recorded in a file that reads as coverage. **`schema/paint-census.json` is AUTHORED and not a regen artifact**, same reason as the two above. The grammar's *order* is gated separately, in `component-schema.ts` rather than here, and that placement is the finding: reversing `focus-ring`'s two templates strands the authored `stroke.inverse` binding (#656's invisible ring, reintroduced), and no census can see it because `focus-ring` declares no `size` axis and cannot be projected at all — so the check runs per **binding** against the def, where all seven are covered rather than three. And `lint-absolute-inset.ts` asserts an absolutely-positioned part carrying an `inset` leaves a **visible gap** between itself and its parent (#801, the first instance of #802) — the **gap, not the coordinate**, and that distinction is worth more than the check. Button's focus ring shipped flush against the component, and **all three causes #801 proposed were wrong.** Measured against the real executor over the real 648-member set: the `focus/ring/offset` lookup *resolves* (0 misses), its miss path is both reachable and *counted* (108 misses with the variable removed), and `focus.ring.offset` is **2** in every brand — so the third proposal, *"nothing read the NUMBER"*, was itself measured and false. The actual cause was found by comparing a built file against the **Prism2** reference, which sites the identical ring at `-4` where ours sat at `-2`: `strokeAlign` is `INSIDE` at both executors — correct for a border, since an outside stroke grows the auto-layout footprint — so the ring's own 2px stroke is drawn *back inward* across the whole 2px gap. The visible separation is `offset − strokeWidth`, which at the shipped 2/2 is **zero**, out of a component that is otherwise perfect: right positioning, constraints and paints, 0 misses. **Nothing anywhere knew the ring carried a stroke.** That is #802's whole class: every other gate here checks a thing *exists*, a ref *resolves*, a count *matches*, or nothing *threw*. **And two gates reported a pass on it, for two different reasons — which is the part to read.** `test-write-components.ts` first asserted the ring's geometry under the label *"2px larger on EVERY side"* while skipping itself whenever the ring was flush (`if (ring.x >= 0) continue`, the negative origin doubling as the inset-vs-centered discriminator) and deriving EXPECTED from the node under test (`off = -ring.x`, so `width === parent + off*2` asserts `0 === 0`): `docs/34` shape 1 twice, in four lines. Then **the repaired version, and the first version of this gate, were both fully independent and measured the wrong quantity** — the repair expected exactly `-2`, this gate asserted `off > 0` on the same coordinate, and `-2` *is* the flush geometry. Both were falsifiable, both had firing negative controls, and `test.ts`'s **parity gate was green**, so two independently-written executors were pinned to each other and confirmed to agree on one wrong formula. Agreement between implementations is evidence about *drift* and none at all about whether the formula is right; `docs/34` **shape 16** is that, and its remedy is different from shape 1's — state the quantity a human would check, in the units they would check it in. So: EXPECTED walks the **def** (part → `inset` + `strokeInset` keys → `tokens` → refs → variable names, restating the naming convention rather than calling `varOf`, which would make both halves one derivation) and asks the **nested** def whether it draws a stroke inward, so a host cannot answer that question about itself; ACTUAL is the plan's `absoluteInset` / `absoluteStrokeInset` and the FLOATs they resolve to in each brand's **committed** export. `C` computes `gap = offset − stroke` and then **re-derives the gap back out of the sited coordinate**, so a compensation applied in the wrong direction fails even though `offset > 0` still holds (verified by mutation). It deliberately does **not** re-derive the executors' arithmetic — `test.ts` compares that against its own stub's two inputs, including an unequal-halves case (gap 5, stroke 1 → −6) that a doubling could not produce. Both directions, so it cannot pass over an empty set: every declared inset part must be **represented** in a projected plan, and a part gated by `when:` must carry its inset at that state and **no other**. And a second, separate floor — `MUST_CLEAR_STROKE`, deliberately *not* derived from `MUST_COVER` — asserts the compensation path was **exercised**, because the whole check degrades silently to `gap = offset` (#801's arithmetic exactly) the moment the plan stops carrying the second name, and every other assertion passes through that. A legitimately-zero gap — `focus.ring.offset-field` is 0 by design, per Primer — must be admitted in `ZERO_OK` with a reason, **authored** for the same argument as `payload-manifest.json`. Its limit is stated in its own header: no browser and no Figma file, so a host that accepts a write and discards it is caught by the executors' read-backs, not here. One consequence for anyone fixing a gate: **#801 is in `docs/34`'s register twice for one visible defect**, because a gate repaired against the shape you found inherits the original's idea of what was worth measuring. **`regen.ts --check` is the only gate that reads the *committed* artifacts** — every other one runs the engine live and compares it against itself, so a stale committed artifact passes all of them.

   **And a gate is only as strong as the independence of the two things it compares.** A gate whose expected value is derived from the thing it checks cannot fail — and it reports that as a pass, not as silence. **So the check is not "does the suite go red" — it is: mutate the subject and confirm *your* gate is among the failures, by name.** Two consequences worth holding: DRY between a gate and its subject is a *silent deletion of the gate*, not a cleanup (the second derivation **is** the gate — say so in a comment, or someone will tidy it away); and a gate with a scope must assert each promised surface is **represented**, never merely count files. This is the most-repeated defect class in the repo's history and not one instance was ever caught by a gate — every one was found by hand. Read `docs/34-gate-independence.md` (the rule, the sub-shapes, and the register) *before* writing a gate, not after.

5. **Versioning: names are versioned, values are not.** Two independent versions live in `packages/engine/version.ts`. `ENGINE_VERSION` answers *"what code produced this?"* — stamped into every emitted tree's `$extensions.generator.version` and reported as the MCP `serverInfo.version`; it bumps on any behavior change including a pure value change. `CONTRACT_VERSION` answers *"can my app still resolve the names it references?"* — it bumps **only** when the guaranteed token-name surface moves. The split is the point: a consumer hard-codes `prism.color.text.primary` and does not care that the brand's hue moved four degrees, but a rename makes that reference resolve to nothing with no error anywhere. `packages/engine/schema/token-contract.json` is the committed baseline, keyed *below* the configurable root because the root is itself a lever. Removing or retyping a path is MAJOR; adding is MINOR; `brandDependent` paths never force a bump. **Never add this baseline to `regen.ts`** — regen rewrites every generated artifact, so a regenerated baseline would silently rewrite itself to agree with a deletion and both gates would go green. It is rewritten only by an explicit `npx tsx packages/engine/token-contract.ts --accept`, which refuses unless `CONTRACT_VERSION` has already been raised by the increment the diff requires: **a gate allowed to rewrite what it reads has no memory.** Full policy, corpus rationale and what is deliberately *not* covered: `docs/30-versioning-and-compatibility.md`.
