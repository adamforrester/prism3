## 4. Key context (decisions, gotchas, non-obvious knowledge)

- **The SD preset is an in-plugin chip group** (DTCG-spec / Style Dictionary / Off-spec) in `src/ui.html`, NOT a separate branch or the `examples/style-dictionary/` starters. Chips stamp *option values* (a fingerprint), they don't change behavior. Relevant functions: `applySDCompatPreset`, `applyDTCGDefaults`, `presetFingerprint`, `isSpecConformant`, `detectActivePreset`. (Earlier in the session I initially mis-stated this from a stale memory — the chip is real and shipped in 1.7.0.)
- **The exporter shaping layer is pure of `figma.*` runtime calls** — verified. Zero calls in `converters/*`, `type-detection.ts`, `cache-manager.ts`, `validator.ts`; the only `figma` token in `exporter.ts` is a JSON key literal (`$extensions.figma.codeSyntax`). Only `scanner.ts` touches Figma at runtime (4 async API calls). This is the key fact behind the Prism3 shared-core feasibility.
- **Hot path for variable values is `convertVariableValue` / `mapVariableTypeToDTCG` in `src/plugin/exporter.ts`** — NOT the `DimensionConverter` strategy class. There are actually FOUR near-duplicate `formatDimension` implementations (TokenExporter, DimensionConverter, TypographyConverter, ShadowConverter) — relevant if anyone consolidates formatters.
- **`DTCGValidator` in `src/utils/dtcg-validator.ts` is test-only** — never invoked in the production export path. No runtime `$type` allowlist anywhere.
- **Line-height ratio mode legitimately emits `number`, not `dimension`** — if a user reports a line-height alias "typing wrong," check the Line Height Output dropdown (default `ratio`) before assuming a bug.
- **Multi-mode layout:** `hasMultiMode = collections.some(c => c.modes.length > 1)` → `tokens/shared/<file>` + `tokens/<mode>/<file>`; single-mode-only stays flat. No default-mode privileging (`defaultModeId` is pass-through metadata only). Logic in `exporter.ts` `getVariableFileName` (~:1166) + `sanitizeFileName`.
- **Plugin can only be verified by manual reload in Figma desktop** (import manifest, reload). No automated Figma integration test — build + unit tests are the automated ceiling.
- **Release process (manual):** bump `package.json`, stamp `docs/CHANGELOG.md` date, `npm run build`, commit `chore(release): vX.Y.Z`, `git tag -a vX.Y.Z`, push main + tag, `gh release create`. `lint-staged` clears the stage on commit — re-`git add` if a commit reports "no staged files."
