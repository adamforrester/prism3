# SD per-mode merge verification harness

Reproduces the pre-2.2.0 Style Dictionary merge crash and confirms the
directory-per-mode layout fixes it. Used during the v2.2.0
[`docs/known-issues/SD-PER-MODE-MERGE.md`](../../docs/known-issues/SD-PER-MODE-MERGE.md)
work — kept in-tree as a regression check.

## Setup

```bash
# From repo root, after a fresh clone:
ln -s ../sd/node_modules tests/sd-per-mode/node_modules
ln -s ../../test-examples/tokens/tokens tests/sd-per-mode/tokens
cd tests/sd
npm install   # installs style-dictionary 3.x for both harnesses
```

Both symlinks are gitignored. Recreate them on each clone.

## What it tests

- `sd.naive-glob.json` — sources `tokens/**/*.json`, merging every mode
  into one build. This is the pre-2.2.0 shape.
- `sd.dark.json` / `sd.light.json` / `sd.wireframe.json` — source
  `tokens/shared/**/*.json` plus `tokens/<mode>/**/*.json`. One build
  per mode, which is what 2.2.0+ exports are laid out for.

### Two different collision classes

SD emits two unrelated warnings and they measure different things. Keep
them apart when reading the output:

| | naive glob | per mode |
|---|---|---|
| **Value collisions** — `Collision detected at: <path>!` (two sources define the same DTCG path) | 3212 | 18 |
| ↳ of those, real token paths (excluding `$extensions`) | **1712** | **0** |
| **Name collisions** — `Output name … was generated by …` (two paths transform to one CSS variable) | 8 | 8 |

The number that matters is the middle row. The naive glob produces **1712
real token collisions** — the same figure this harness was built to
demonstrate — because every multi-mode token appears once per mode at the
same path with a different `$value`, and SD's deep-merge takes last write.
Per-mode builds produce **zero**.

All 18 per-mode "collisions" are `$extensions` metadata: each file carries
a file-level `$extensions.generator` block, so merging any two files
collides on that path. It's benign noise, identical for every mode, and
not what the layout was meant to fix.

The 8 name collisions are **identical in both configs**, which is the
point — they're not a merge artifact at all. They come from
`transformGroup: "css"` collapsing distinct DTCG paths onto one CSS
variable name, so the export layout can't affect them. Don't read a
change in this row as a merge regression.

### On the historical stack crash

`docs/known-issues/SD-PER-MODE-MERGE.md` records the naive glob crashing
with `RangeError: Maximum call stack size exceeded`. **It no longer
does** — both configs exit 0 against the current export. The crash needed
a specific alias-cycle shape that the export has since stopped producing;
the 1712 silent value collisions are the durable symptom, and they're the
thing worth asserting on. Treat the crash as historical context, not an
expected outcome.

## Run

```bash
cd tests/sd-per-mode
npm run build:all     # per-mode: exits 0, zero real token collisions
npm run build:naive   # naive glob: exits 0, but warns 1712 real collisions
```

Both exit 0. Read the warnings, not the exit code — the failure this
harness demonstrates is silent.

## Notes

- The `tokens/` symlink points at a real Token Press export checked in
  under `test-examples/tokens/tokens/`. If you regenerate that export,
  the harness picks up the new shape automatically.
- This harness uses SD 3.x because that's what the original bug was
  reported against. The fix is shape-level (directory layout), so it
  applies to all SD versions.
- These configs deliberately **omit** `outputReferences`, unlike the SD 4/5
  starter in
  [`examples/style-dictionary/`](../../examples/style-dictionary/README.md#where-to-put-it).
  What's under test here is the source-glob merge. Collisions are detected
  during merge/resolution, strictly before any formatting runs, so
  `outputReferences` cannot affect the counts above — verified identical
  either way. Enabling it would only reorder the output (SD's reference-safe
  sort kicks in), which is churn in a file you diff by hand. It would also
  crash: this is an SD 3 harness, and SD 3 throws
  `TypeError: value.replace is not a function` on aliased composites when
  `outputReferences` is on.
- Figures above were measured with the stock CLI (`npm run build:*`), which
  registers **no DTCG parser** — SD 3 sees `$value` / `$type` as literal path
  segments. That's deliberate: it's the pre-2.2.0 reproduction. Adding the
  parser shim from `examples/style-dictionary/sd-v3-with-parser/` changes the
  counts, so don't compare across the two setups.
