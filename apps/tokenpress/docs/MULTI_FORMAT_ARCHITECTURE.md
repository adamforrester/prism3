# Multi-Format Export Architecture

## Overview

Token Press now includes an extensible architecture for exporting design tokens to multiple platform-specific formats beyond the core DTCG JSON format. This architecture prepares the foundation for supporting CSS, SCSS, Flutter, iOS, Android, and other target platforms.

## Architecture Components

### 1. Format Exporter Interface (`FormatExporter`)

The base interface that all format exporters must implement:

```typescript
interface FormatExporter {
  export(tokens: DTCGFile, options: FormatOptions): Promise<PlatformExport[]>;
  getSupportedExtensions(): string[];
  getDisplayName(): string;
  validateTokens(tokens: DTCGFile): { isValid: boolean; errors: string[] };
}
```

### 2. Token Transformer Interface (`TokenTransformer`)

Handles the conversion of DTCG token values to platform-specific formats:

```typescript
interface TokenTransformer {
  transformColor(token: DTCGToken, path: string): string;
  transformDimension(token: DTCGToken, path: string): string;
  transformTypography(token: DTCGToken, path: string): string;
  transformShadow(token: DTCGToken, path: string): string;
  transformGeneric(token: DTCGToken, path: string, type: string): string;
}
```

### 3. Exporter Registry (`ExporterRegistry`)

Central registry for managing format exporters:

```typescript
interface ExporterRegistry {
  register(format: ExportFormat, exporter: FormatExporter): void;
  get(format: ExportFormat): FormatExporter | undefined;
  getSupportedFormats(): ExportFormat[];
  isSupported(format: ExportFormat): boolean;
}
```

### 4. Base Format Exporter (`BaseFormatExporter`)

Abstract base class providing common functionality:

- Token validation
- Token tree walking
- Name sanitization with multiple case styles
- Platform export result creation

## Current Implementation

### CSS Format Exporter

The architecture includes a complete CSS format exporter as a reference implementation:

- **CSS Custom Properties**: Converts DTCG tokens to CSS custom properties in `:root`
- **Color Support**: Handles sRGB colors with optional alpha
- **Dimension Support**: Converts dimension tokens with units
- **Reference Support**: Handles token references with `var()` syntax
- **Shadow Support**: Converts shadow tokens to CSS box-shadow values

Example output:
```css
/**
 * Design Tokens - CSS Custom Properties
 * Generated by Token Press
 */

:root {
  --colors-primary: rgb(0, 123, 255);
  --spacing-small: 8px;
  --colors-primary-transparent: rgba(0, 123, 255, 0.5);
}
```

### Multi-Format Token Exporter (`MultiFormatTokenExporter`)

Extends the base `TokenExporter` to support multiple output formats:

```typescript
const exporter = new MultiFormatTokenExporter({
  // Standard DTCG options...
  additionalFormats: [
    {
      format: 'css',
      config: {
        css: {
          prefix: 'ds-',
          useCustomProperties: true,
          generateUtilities: false
        }
      }
    }
  ],
  includeDTCG: true // Include DTCG JSON files
});
```

## Adding New Format Exporters

1. **Create Token Transformer**: Implement `TokenTransformer` for your platform
2. **Create Format Exporter**: Extend `BaseFormatExporter` or implement `FormatExporter`
3. **Register Format**: Add to registry in `MultiFormatTokenExporter.initializeFormatExporters()`
4. **Add Tests**: Create unit tests following the pattern in `multi-format-export.test.ts`

Example:
```typescript
export class FlutterFormatExporter extends BaseFormatExporter {
  constructor() {
    super(new FlutterTokenTransformer());
  }

  async export(tokens: DTCGFile, options: FormatOptions): Promise<PlatformExport[]> {
    // Implementation here
  }

  getSupportedExtensions(): string[] {
    return ['dart'];
  }

  getDisplayName(): string {
    return 'Flutter Theme';
  }
}
```

## Integration

The multi-format architecture is designed to integrate seamlessly with the existing Figma plugin:

1. **UI Updates**: Add format selection checkboxes in the export panel
2. **Options Extension**: Extend `ExportOptions` with format-specific configurations
3. **Progress Reporting**: Multi-format exports report progress for each format
4. **Error Handling**: Individual format failures don't block other formats

## Performance Considerations

- **Lazy Loading**: Format exporters are only instantiated when needed
- **Parallel Processing**: Multiple formats can be generated concurrently
- **Memory Management**: Batch processing prevents memory issues with large token sets
- **Caching**: Token transformation results can be cached for repeated use

## Future Enhancements
